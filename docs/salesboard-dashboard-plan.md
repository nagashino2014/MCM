## 2. 이번 요청 범위(1단계) — 목록 검색성·열 정리

### 2-1. 목록 왼쪽 태그 필터 패널
- 영업건 리스트 카드 왼쪽에 세로 태그 패널(폭 약 150px)을 둔다. 상단 필터 줄(제목·사업장 검색, 담당, 연도)은 그대로 둔다.
- **지역권** 태그: 공공입찰 화면과 같은 7권 — 수도권 / 강원권 / 충청권 / 경북권 / 경남권 / 전라권 / 제주권 (+ 시도 없는 건은 "미상"). 판정은 `facilities.region_sido` → 시도 약칭(`lib/catalog/regions.ts`의 `shortSido` 재사용) → 7권 매핑. 매핑 상수와 함수는 클라이언트에서 import 가능한 `lib/sales/regions.ts`에 둔다(`lib/bid/bid-queries.ts`는 DB 모듈을 import하므로 클라이언트에서 쓸 수 없음).
- **업종분류** 태그: `sales_projects.service_category` 4종 — 통합허가 / 화관법 / ESG·탄소중립 / 기타(미지정은 "미분류").
- 동작: 태그 다중 선택, 같은 그룹 안은 OR, 그룹 사이는 AND. 선택된 태그는 채움색, 그룹 머리에 선택 수 표시, 상단 "초기화"가 태그도 함께 비운다. 각 태그에 현재 조건의 건수를 작게 표시한다.
- 데이터: `PROJECT_SELECT`에 `f.region_sido`를 추가해 `SalesProject.regionSido`로 내려주고, 지역권은 클라이언트에서 파생한다. 필터는 현행과 같이 클라이언트 측(전건 fetch 후 필터)으로 유지한다.
- 많아질 때 대비: 목록에 공용 `useClientPaging`(`components/ui/PaginationControls.tsx`) 쪽 나눔을 적용한다(행 밀도는 10-21 규칙과 동일). 영업건이 수천 건 규모가 되면 `/api/sales/projects`에 `regionGroup`·`serviceCategory` 서버 필터를 추가하는 것을 후속으로 둔다.

### 2-2. 검색란 너비
- "제목·사업장 검색" 입력을 180px → 300px로 넓힌다(좁은 화면에서는 줄 바꿈).

### 2-3. 예상 수주금액 삭제
- 목록 열 "예상 수주금액" 삭제, 영업건 추가 모달의 "예상 수주금액(원)" 입력 삭제(POST에 보내지 않음).
- DB 컬럼 `sales_projects.expected_amount`, API 필드, 타입은 **유지**(마이그레이션 없음, 기존 데이터 보존). 영업 상세 화면에는 이 값 표시가 없어 영향 없음.
- 2차 W6 "수주 성과"의 금액 축은 예상 수주금액이 아니라 스케쥴에 기록된 **투찰가(`sales_activities` bids)** 를 쓴다.

### 2-4. 매뉴얼 동기화(같은 커밋)
- `sales.board` 기사: summary 1행(예상 수주금액 삭제), "영업건 만들기" 3단계 문구, "영업건 목록 읽기"에 지역권·업종분류 태그 필터 설명 추가, `reviewedAt` 갱신. `changelog.ts`에 한 줄. `npm run test:manual` 통과.

## 3. 2단계 — 상단 KPI 띠(2026-10-26 구현)
- 위치: 페이지 헤더 아래, 탭 패널·목록 위에 1줄 5칸(칸 높이 약 74px, `xl` 미만은 3열·2열로 wrap).
- 지표(모두 현재 목록 응답과 탭 패널 응답에서 파생, 새 API 없음). 목록 필터(검색·담당·연도·태그)와 무관하게 보이는 영업건 전체 기준, 날짜는 KST:
  1. 진행 중 영업건 — status가 closed가 아니고 단계가 수주·실주가 아닌 건. 보조 줄 = 단계별 내역(보류는 있을 때만)
  2. 이번 달 신규 — opened_at(없으면 created_at) 당월. 보조 줄 = 지난달 건수
  3. 투찰 예정(14일) — 탭 패널 upcoming-bids와 같은 모집단. 보조 줄 = 가장 가까운 D-day
  4. 올해 수주 / 실주 — 결과 스케쥴 날짜(`SalesProject.outcomeAt`, 서버 attachStepTypes에서 채움)가 올해인 수주·실주. 결과 스케쥴 없는 옛 건은 closed_at → opened_at로 판정
  5. 올해 수주율 — 수주 ÷ (수주+실주), 결과 없으면 —
- 칸 클릭 = 목록 필터(하나만, 다시 누르면 해제, 검색란 옆에 이름 칩 표시). 수주/실주 칸은 두 값을 각각 누른다. 투찰 예정 칸은 필터 대신 왼쪽 투찰 임박 탭을 연다.
- 숫자는 텍스트 색, 아이콘만 칸별 색. 상태색(수주 녹색·실주 빨강)은 라벨과 함께. 선택된 칸은 경계만 primary.

## 4. 3단계 — 하단 인포그래픽 존(2026-10-26 구현)
탭 패널·목록 아래, 영업 제설정 카드 위. "영업 현황" 머리(+`CdHelp topic="sales.insights"`) 아래 4카드(`xl` 4열 · `md` 2열 · 그 밖 1열)와 W8 한 줄 카드. 코드는 `components/sales/SalesInsights.tsx`.

| 위젯 | 내용 | 데이터 | 누르면 |
|---|---|---|---|
| W4 파이프라인 퍼널 | 전체 → 컨택 이상 → 제안 이상 → 입찰 이상 → 수주, 도달 건수와 앞 단계 대비 전환율 | `SalesProject.reachedStage`(시작된 스케쥴 중 최고 단계, 수주면 won) | 목록에 그 단계 이상 도달 건만(칩 "제안 이상 도달") |
| W5 용역 분류 분포 | 4대 분류+미분류 건수·비율, 아래 줄 세분류 | `service_category`/`service_subcategory` | 왼쪽 업종분류 태그 토글 |
| W6 수주 성과 | 최근 3년 연도별 수주·실주 건수, 수주율 게이지, 낙찰·투찰 금액(금액 기록 n/m건) | `outcomeAt` 연도 + `SalesProject.finalBidAmount`(가장 늦은 투찰 스케쥴의 마지막 회차) | — |
| W7 담당자 현황 | 영업 담당자별 진행 중·14일 일정·미보고 경과·올해 수주, 미지정 줄 | 목록·upcoming-activities·pending-reports | 담당 필터 토글 |
| W8 인텔·AI 요약 | 최근 7일 수집·채택·등급별 신호, 최근 브리핑 질문 | 기존 `/api/sales/intel/stats`, `/api/sales/rag/briefings?limit=1` | `/sales/intel`, `/sales/rag` 이동 |

- **계획 변경**: 집계 API `/api/sales/stats`는 만들지 않았다. W6에 필요한 투찰가만 목록 응답(attachStepTypes)에 `finalBidAmount`로 붙여, 모든 카드가 목록과 같은 가시성 scope를 자동으로 따른다.
- 기준은 KPI 띠와 같이 보이는 영업건 전체이며 목록 필터와 무관하다.
- 차트: 단일 계열 막대(primary 한 색, 14px, 끝 4px 둥글게, 값은 끝에 텍스트 색), 범례 없음. 호버·키보드 포커스 툴팁(값 먼저)은 보조이고 값은 모두 화면 글자에 있다.
- **W6 색**: 수주 녹색·실주 빨강 두 색은 dataviz 검증기에서 적록 색각 ΔE 6.2~6.7(최저 기준 구간), 다크 모드 명도 범위 이탈로 실패했다. 그래서 수주율을 한 색 게이지(채움 primary, 트랙 같은 색 16%)로 그리고 건수는 글자로 쓴다.

## 5. 결정 사항(2026-10-26 사용자 확정)
1. 지역권 체계: **공공입찰 7권** 확정.
2. 태그 **다중 선택** 확정(그룹 안 OR, 그룹 사이 AND).
3. KPI 띠 **채택** — 3절의 5개 지표 그대로(구현 완료).
4. 하단 위젯 **W4~W7 전부 + W8 요약 카드**(구현 완료).
5. 예상 수주금액: **UI만 제거**, 컬럼·API 유지.
6. 진행 순서: **1단계 구현·로컬 확인 → 2단계 KPI → 3단계 하단 위젯**.
