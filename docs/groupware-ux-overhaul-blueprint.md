# 그룹웨어 UI/UX 전면 개편 블루프린트 (PermitIQ → 통합 그룹웨어)

> 목표: 기능 실증 위주로 속성 구축된 화면들을 **다우오피스·아마란스10급 그룹웨어 UI/UX**로 전면 개편한다.
> 범위: **그룹웨어 전체 동시 개편**(전역 셸 + 정보구조 + 공통 디자인 시스템 + 전 모듈). 메일 화면은 **전통 3-pane**.
> 원칙: cdash 디자인 토큰(라이트/다크)·기존 기능·데이터 모델은 **보존**하고 표현·정보구조·상호작용만 개편(비회귀).
>
> 작성일 2026-07-25. 관련: [`.cursor/rules/ui-modernize.mdc`](../.cursor/rules/ui-modernize.mdc)(cdash 권위 규칙), [company-email-blueprint.md](company-email-blueprint.md), [home-dashboard-blueprint.md 등].
> ⚠ 이 문서는 **착수 전 합의용 계획서**다. 승인 후 Phase 순으로 구현한다.

| **정보구조(IA)** | IEPS 사업운영 중심(사업장·계약·영업·데이터), 협업(메일·전자결재)이 "업무 보고" 그룹에 얹힘 | 그룹웨어 정체성과 **주객 불일치** — 협업 도구가 후순위 |

## 2. 목표 정보구조(IA) — "어떤 메뉴·기능을 어디에" ★ 핵심

그룹웨어 = **협업 스위트(메일·결재·일정·게시)** 를 전면에, **사업 운영(원 PermitIQ 도메인)** 을 병렬로. 단일 좌측 사이드바를 **주 네비**로 승격하고 탑바의 중복 가로 nav는 폐지(→ 검색·알림·작성·계정만).

### 2.1 좌측 사이드바 — 5개 섹션 재편

```
[로고 PermitIQ]                     ← 브랜드
[통합검색 바로가기 / ⌘K]            ← 검색 진입(탑바와 연동)

▚ 홈
   • 대시보드                        (/home — 오늘의 할일: 미결재·안읽은메일·일정·공지)

▚ 협업                              ← ★ 신설·전면 배치
   • 메일           [안읽음 뱃지]    (/mail — 3-pane)
   • 전자결재       [미결재 뱃지]    (/approval …)
   • 일정/캘린더    (신규 검토·§7)   (/calendar)
   • 공지·게시판    (신규/공문 연계) (/board)
   • 주소록·조직도  (신규·§7)        (/directory)

▚ 업무
   • 업무추진계획                    (/work-plan …)
   • 사업참여 수행인력               (/staffing …)
   • 근태·휴가                       (/hr — 전자결재서 승격, §2.3)

▚ 사업 운영                         ← 원 PermitIQ 도메인(보존)
   • 사업장                          (/facilities)
   • 계약                            (/contracts …)
   • 영업/마케팅                     (/sales …)
   • 데이터                          (/data …)

──────────── 하단 고정 ────────────
▚ 관리 (admin/editor)
   • 사용자·조직 관리
   • 회사 프로필
   • 메일 관리(별칭·배포리스트)       (메일 P4 연계)
   • 결재 양식·정책
   • 휴지통
[내 계정 카드: 아바타·이름·상태]     ← "자동 수집" 위젯 제거
```

> 원칙: **협업 3종(메일·결재·일정)** 을 최상단 배치하고 미결재/안읽음 **카운트 뱃지**를 붙여 그룹웨어 첫인상을 만든다. 사업운영은 그대로 보존(팀 업무 연속성).

### 2.2 상단 글로벌 바 — 재정의(중복 가로 nav 폐지)

```
[사이드바 토글] ── [통합검색 ⌘K] ────────── [+새로 작성▾] [알림🔔n] [내계정▾]
```
- **통합검색**: 메일·결재문서·연락처·사업장·계약 교차 검색(모듈 라우팅). 초기엔 스코프별 탭.
- **빠른 작성 +**: 새 메일 · 새 기안 · (일정·공지) 드롭다운.
- **알림센터**: `AlertBell`을 흡수·통합 — 결재 도래/승인·반려, 메일 수신, 멘션, 공지. 미확인 카운트.
- **내 계정**: 프로필·상태(재석/부재)·내 서명·환경설정·로그아웃.

### 2.3 재배치 결정(확정 필요)
- **근태·휴가**를 전자결재 하위 → **업무·근태/휴가(HR)** 로 승격(전자결재는 "결재 흐름"에 집중, HR 대장/촉진은 별도 모듈). 전자결재 하위엔 결재 관련만(홈·기안·문서함·양식별조회·인사이트·양식·정책·알림설정).
- **양식 관리·사전검토 정책·결재 알림 설정**은 "관리"로 이동(운영자 기능).

## 3. 전역 셸 재설계 (Phase G1)

### 3.0 해상도 원칙 — **FHD-first, 울트라와이드는 확장** ★ (2026-07-25 추가)
개발 환경(오디세이 G9, 7680×2160) 기준으로 구축돼 실사용 환경(직원 대부분 FHD 1920×1080)에서 메뉴·배치가 깨지는 문제를 **기준축 전환**으로 해결한다.
- **기준 뷰포트 = 실효 1536×864** (FHD + Windows 배율 125% — 사무용 표준). **1280px(FHD+150%)까지 네비 소실 없이** 동작해야 함.
  - ⚠ 현행 최대 결함: 사이드바가 `hidden xl:flex`(<1280px 숨김) → FHD+150% 배율에서 **네비 통째 소실**. G1 에서 아이콘 레일 축소로 대체(숨기지 않음).
- **울트라와이드 = 전폭 사용(2026-07-27 개정·확정)**: 당초 최대폭+정렬(중앙→좌측)을 시도했으나 초광폭에서 우측 대면적 여백·내부 카드 찌그러짐을 유발해 **본문 고정 max-w 폐지** — 브라우저 가용폭 전체를 쓰고 각 화면 그리드가 자동 배치한다. 개별 위젯/카드는 auto-fit minmax 로 폭에 적응.
- **그리드는 고정 열 수 금지**: 카드 그리드는 `repeat(auto-fit, minmax(…px, 1fr))` 패턴으로 해상도 무관 자동 열 수. 위젯·카드 최소폭을 정해 FHD 에서 2~3열, G9 에서 자연 확장.
- **밀도 조정**: FHD 기준으로 여백·폰트·카드 패딩을 잡고(현행 p-4 gap-4 셸 여백 축소 검토), 초광폭에서 여백이 늘어나는 방향(역방향 금지).
- **★ 축소 금지 원칙(가독성)**: 좁은 실효폭 대응은 **재배치(reflow — 열 수 감소·레일 축소·줄바꿈)** 로만 한다. **폰트·패딩 축소로 밀도를 해결하지 않는다** — 직원의 125%/150% 배율은 "그 크기가 편해서"이므로 존중(배율을 낮추게 유도하는 설계 금지). 타이포 하한: 본문 14px(text-sm)·메타 12px(text-xs) 미만 금지, 10~11px 는 장식 라벨(eyebrow·뱃지 uppercase)에만 허용.
- **검증 게이트**: 모든 G-Phase 산출물은 preview `resize_window` 로 **1920×1080 · 1536×864 · 1280×720** 3종 실측 후 완료 처리(§9). G9 는 최대폭 확장 확인용.

`components/layout/{AppShell,Sidebar,TopBar}` 개편:
- **AppShell**: 반응형 그리드. 사이드바 상태(펼침/축소/오버레이) 관리, 폭에 따라 자동 전환(**≥1536 고정 확장, 1024~1536 아이콘레일**(라벨 툴팁), `<1024` 오버레이 드로어 — xl 숨김 폐지). 모바일 `MobileShell`과 정합.
- **Sidebar**: §2.1 5섹션. 섹션 접힘 기억(localStorage), 활성 경로 하이라이트, 카운트 뱃지 슬롯(메일 안읽음·미결재), 축소(아이콘) 모드.
- **TopBar**: §2.2. 가로 nav 제거, 검색/작성/알림/계정. 스티키.
- **알림센터**: 기존 `AlertBell`+대시보드 알림 소스 통합. 단일 팝오버(탭: 전체/결재/메일/시스템), 읽음 처리, 항목 클릭 → 딥링크.

## 4. 공통 디자인 시스템 확장 (Phase G0 — 최우선 기반)

cdash 토큰(`--cd-*`) 위에 **재사용 컴포넌트 라이브러리**를 `components/cdash/`(또는 `components/ui/`)에 신설. 이후 모든 모듈이 이걸 쓰도록 점진 치환.

| 컴포넌트 | 용도 | 대체 대상(현행 중복 구현) |
|---|---|---|
| `CdButton`/`CdIconButton` | 1차/2차/위험/고스트 버튼 | 각 보드의 인라인 버튼 className |
| `CdTabs` | 폴더/보기 전환 | 결재함·메일 폴더 탭 |
| `CdTable`/`CdDataGrid` | 정렬·페이지·선택·빈상태 | 계약·사업장·결재 목록 |
| `CdModal`/`CdDrawer` | 포털 모달(cdash-vars 스코프 내장) | 각 모달 재구현 |
| `CdToast` | 발송/저장 피드백 | alert()·인라인 notice |
| `CdBadge`/`CdCount` | 상태·카운트 | — |
| `CdAvatar` | 사용자/조직 | 휴가관리 아바타 |
| `CdEmptyState` | 빈 목록 | "메일 없음" 등 |
| `CdDropdown`/`CdMenu`·`CdTooltip` | 메뉴·힌트 | 유저메뉴·서브메뉴 |
| `CdSplitPane` | 3-pane 리사이즈 | 메일 |
| `CdField`(input/select/textarea/checkbox) | 폼 일관화 | 전 폼 |
| `CdPageHeader`(기존 확장) | 브레드크럼·탭·툴바 슬롯 | 기존 |

> 규칙: 신규 컴포넌트도 `.cursor/rules/ui-modernize.mdc` 준수(윤곽선 기본·선택시 tint·`cd-fields-white` 스코프·포털은 `cdash-vars`). 색은 hex 하드코딩 금지, `--cd-*`만.

## 5. 메일 3-pane (Phase G2, 플래그십) — 전통 그룹웨어 레이아웃

현행 `MailComposeBoard`(2-view 목록/상세)를 **3-pane**로 재구성:

```
┌──────────┬───────────────────────┬───────────────────────┐
│ 폴더 트리 │  메시지 목록(스레드)   │  본문 뷰어             │
│          │                       │                       │
│ 받은편지함│ ☐ [●] 제목 …  발신 날짜│ 제목                   │
│  보낸함  │ ☐    제목 …  발신 날짜 │ 발신/수신/일시·첨부칩  │
│  임시함  │ ☐ ★  제목 …          │ ───────────────────── │
│  보관함  │  ⟳ 무한스크롤/페이지  │ 본문(수신HTML=sandbox) │
│  스팸함  │                       │ [답장][전답][전달][삭제]│
│  휴지통  │                       │                       │
│ + 사용자 │                       │                       │
│  라벨    │                       │                       │
│ [내 주소]│                       │                       │
└──────────┴───────────────────────┴───────────────────────┘
```

- **좌 폴더 pane**: 시스템 폴더(096 seed) + 사용자 라벨, 폴더별 안읽음 카운트, 내 주소·서명 진입.
- **중앙 목록**: 스레드 묶기(References 기반), 체크박스 **일괄 작업**(읽음·이동·삭제·별표), 검색(제목/발신/본문), 정렬, 무한스크롤 or 페이지, 안읽음 강조.
- **우 뷰어**: 스레드 펼침(대화형), **답장/전체답장/전달**(원문 인용·헤더 세팅 → 발송 P1 연결), 첨부 다운로드/미리보기, 인쇄. 작성은 우측 오버레이 or 전체.
- **작성기 고도화**: 리치 텍스트 에디터(굵기·목록·링크·인라인이미지), 서명 자동삽입, 자동저장 드래프트(`mail_drafts`), 수신자 자동완성(주소록·최근).
- 반응형: 좁은 폭에서 3→2→1 pane 축소(목록↔상세 토글).
- 재사용: `CdSplitPane`·`CdTable`·`CdTabs`·`CdToast`.

> 백엔드는 대부분 P1/P2 자산 재사용. **신규 필요**: 답장/전달용 스레드 조회 API, 폴더 이동·플래그 변경 API, 라벨 CRUD, 드래프트 저장 API, 검색 쿼리. (P3 백엔드로 별도 정리)

## 6. 모듈별 UX 표준화 (Phase G3~)

공통 컴포넌트 적용 + 화면 패턴 통일. 우선순위 = 사용빈도·현 완성도 갭.
- **전자결재**: 결재함 3-pane(문서목록↔미리보기), 기안 작성기 폼 컴포넌트화, 결재선/조직도 선택 공통화.
- **홈 대시보드**: 위젯 그리드 표준(카드·KPI·차트), 협업 3종 요약(미결재·안읽은메일·오늘일정) 상단.
- **사업장·계약·영업·데이터**: `CdTable`/`CdDataGrid`로 목록 통일, 상세 패널 드로어화, 필터·검색 일관.
- **근태·휴가(HR)**: 대장·촉진·근태 화면 아바타/차트/캘린더 공통화(기존 자산 활용).
- **관리**: 사용자·조직·권한 화면 정비, 메일 관리(별칭·배포리스트) 신설(메일 P4).

## 7. 신규 그룹웨어 요소 검토 (범위 확정 필요)

전통 그룹웨어 정체성을 위해 **없으면 허전한** 요소. 이번 범위 포함 여부를 결정한다.

- **채팅/메신저**: 실시간 대화. (범위 매우 큼 — 후순위 권장)

### 8.1 G-L 로그인·인증 개편 (2026-07-27 추가)
현행: 구식 그린 테마 로그인 페이지, 비밀번호 분실 시 "관리자에게 초기화 요청" 안내뿐(셀프서비스 없음), 세션 유지 옵션 없음.
- **로그인 페이지 cdash 재설계**: `--cd-*` 토큰·라이트/다크, 브랜드(PermitIQ Groupware) 정렬. 기존 로그인 로직(next-auth v5·사번+비밀번호·최초 로그인 변경 강제·login_attempts 스로틀)은 무변경.
- **아이디(사번) 찾기**: 이름 + 등록 이메일(employee_profiles.email 또는 회사메일)로 조회 → **일치 시 해당 이메일로 사번 안내 발송**(화면에 직접 노출하지 않음 — 계정 열거 방지). 메일 발송은 P1 SES 인프라 재사용.
- **비밀번호 찾기(셀프 재설정)**: 사번+등록 이메일 입력 → **1회용 재설정 토큰**(신규 테이블 `password_reset_tokens`: 해시 저장·30분 만료·사용 후 폐기) 링크를 이메일 발송 → 재설정 페이지에서 새 비밀번호 설정. 요청·성공 모두 audit_log. 스로틀(login_attempts 패턴) 적용. 존재하지 않는 계정에도 동일 응답(열거 방지).
- **자동 로그인(로그인 유지)**: 로그인 폼에 "로그인 유지" 체크박스 — 체크 시 세션 30일, 미체크 시 당일(next-auth jwt/session maxAge 분기). 공용 PC 고려해 기본 해제.
- 구현 순서: cdash 재설계(가벼움) → 자동 로그인 → 찾기 2종(메일 인프라 의존). G5(관리)와 병행 가능.

> "전체 동시"라도 **G0(디자인 시스템)·G1(셸)** 을 먼저 세워야 나머지가 일관되게 얹힌다. 각 Phase는 독립 배포 가능하도록 쪼갠다(비회귀·롤백 용이).

## 9. 리스크 · 비회귀 원칙

- **cdash 토큰 유지**: 색·폰트·라이트/다크 전면 준수. 신규 컴포넌트도 hex 금지, `--cd-*`만. 포털 모달은 `cdash-vars`.
- **기능·데이터 보존**: 라우트 경로·API·DB 무변경(표현/IA만). 경로 이동 시 리다이렉트 유지.
- **점진 치환**: 공통 컴포넌트로 한 번에 갈아엎지 않고 모듈 단위로 교체(선행 타입에러 다수 존재 — 수정 파일 필터 검증).
- **권한·모바일 정합**: `minRole` 노출 규칙·`MobileShell` 동작 보존.
- **성능**: 대형 보드(FacilityDetailPanel 4천 줄 등) 리팩터는 범위·회귀 주의.
- **해상도 게이트(§3.0)**: 화면 완료 판정 전 preview 로 1920×1080·1536×864·1280×720 실측. "G9 에서 보기 좋음"은 완료 조건이 아니다.
