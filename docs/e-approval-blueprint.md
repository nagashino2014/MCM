# 전자결재 시스템 블루프린트 (v2 — 확정, 2026-07-21)

작성 2026-07-21. 방침 변경: 기존 "전자결재 보류(별도 앱 분리)" 결정을 철회하고 MCM 앱에
전자결재를 정식 탑재한다. 현재 사용 중인 **다우오피스 전자결재의 구조를 차용**하되, 핵심
불만 사항을 개선한다. 근거 자료: 다우오피스 실사용 스크린샷 4종(홈/양식 선택/결재선/양식
편집기) + 공개 가이드. **§8 논점은 전부 확정됨(같은 날) — §8 확정 결정 참조.**
공문 본문 블록 에디터 프로토타입도 채택 확정(공문 블루프린트 §4-2 방식 A).

## 1. 다우오피스 전자결재 구조 분석 (실측)

### 1-1. 홈 / 결재함
- 결재하기: **결재 대기**(내 차례) / **결재 수신** / **참조·열람 대기** / **결재 예정**(내 차례가
  오기 전 문서) 카운트. 대기 문서는 카드형(긴급 태그·기안자·기안일·결재양식)으로 상단 노출.
- 기안 진행 문서 / 완료 문서 목록(기안일·결재양식·긴급·제목).

### 1-2. 문서함 구조
- **개인 문서함**: 기안 / 임시 저장 / 결재(내가 결재한) / 참조·열람 / 수신 / 발송 / 공문.
- **부서 문서함**(부서별): 기안 완료함 / 부서 참조함 / 부서 수신함 / 공문 발송함.
- **전자결재 문서관리**(관리자): 양식별 문서 조회 / 전사 공문 발송함 / 운영자 작업기록.
- 양식마다 완료 문서가 저장될 전사/부서 문서함을 지정 — 완료 시 자동 분류.

### 1-3. 양식 관리 / 선택
- 양식은 **폴더 트리**로 관리(예: 인사 폴더 — 재택근무신청·단축근무신청·퇴직원·인사 발령·
  결근사유서·교육결과보고·교육수강신청·휴직원·휴가신청·초과/휴일근무신청·승진품의서…,
  업무기안 등). 양식별 속성: 제목·전사문서함·보존연한·기안부서·부서문서함(+문서번호 규칙,
  모바일 기안 허용). '자주 쓰는 양식' 즐겨찾기.

### 1-4. 결재선
- 좌측 **조직도**(이름·직위·직책·직급·부서·전화·아이디 검색) / **나의 결재선**(개인 프리셋
  저장·재사용) 탭 → 우측 단계 구성: `신청(기안)` → `승인` 단계들, 단계 타입 select(**합의**/
  승인 등), 합의방식 **순차합의/병렬합의** 선택, 상태(예정 등) 표시.
- 별도 탭: **참조자 / 열람자**. 자동 결재선(양식별 사전 지정) 기능 존재.
- 결재선 최대 10단계 × 단계당 10명.

### 1-5. 양식 편집기 (웹)
- 필드 팔레트 — 기본 항목: 제목 / 본문 내용 / 결재선 / 텍스트 / 멀티텍스트 / 편집기 /
  숫자 / 통화 / 단일선택 / 드롭박스 / 체크박스 / 날짜 / 시간 / 기간 / 사용자선택 / 부서선택.
  +자동 항목(기안자·직위·기안부서 등 자동 바인딩) / 고급 항목.
- 레이아웃은 리치텍스트 편집기 + HTML 표 기반 자유 배치.
- 실양식 예(국내출장신청): 출장기간(기간)·출장분류(드롭)·출장지(텍스트)·교통편(체크 복수)·
  배차 신청(차량 드롭+이용시간 라디오)·출발 시각(시/분)·계약 구분(체크)·계약명(텍스트)·
  동행자·출장목적(멀티텍스트)·출장자 정보(자동 항목).

### 1-6. 확인된 문제점 (개선 대상 ★)
1. **양식 편집기가 조잡**: HTML 표 자유 배치라 레이아웃 정렬이 잘 안 됨.
2. **★필드 데이터가 DB화되지 않음**: 텍스트·숫자·금액·날짜·목록 등 필드에 입력된 값이
   문서(HTML) 안에만 존재 — "누가 언제 어느 업체에 출장 가서 누구를 만났는지"를 분류·정렬·
   요약·발췌할 수 없음. 문서는 쌓이는데 데이터는 없는 구조.

## 2. MCM 전자결재 설계 원칙

1. **양식 = 필드 스키마다**: 양식의 모든 입력 요소는 `field_key`+타입을 가진 필드 정의이며,
   제출 문서는 `field_key → 값`의 **구조화 데이터로 저장**된다. 렌더된 문서는 그 투영일 뿐.
   → 양식별 문서 조회가 곧 데이터 테이블(필터·정렬·집계·엑셀 내보내기)이 되고, 추후 AI
   요약·발췌의 입력이 된다. **다우 문제 2의 정면 해결이자 본 시스템의 존재 이유.**
2. **레이아웃은 행×열 그리드**: 자유 표 대신 12컬럼 그리드 행 단위 배치(필드가 행 안에서
   콜스팬 차지). 정렬이 항상 맞고, 모바일(/m)에서는 1열로 자연 강하. → 다우 문제 1 해결.
3. **다우의 검증된 UX 는 차용**: 문서함 구조·결재 대기/예정 구분·합의(순차/병렬)/승인 단계·
   참조/열람·개인 결재선·자주 쓰는 양식·긴급 표시 — 사용자 학습 비용 최소화.
4. **기존 MCM 자산 위에**: 조직도(OrganizationTree)·employee_profiles/departments/positions·
   RBAC(requirePermission)·audit·cdash UI·알림 인프라(SES/솔라피) 재사용.

## 3. 필드 타입 카탈로그 (v1)

| 타입 | 저장 | 비고 |
|---|---|---|
| text / multitext | text | 한 줄/여러 줄 |
| number / currency | numeric | 통화는 콤마·원 단위 표시, 집계 가능 |
| select(단일) / radio | text(옵션 key) | 옵션 정의는 양식에 |
| checkbox(복수) | text[] | 교통편 같은 복수 선택 |
| date / time / period | date/text | period = 시작~종료(기간 일수 파생) |
| user_select / dept_select | employee_id / dept_id | 조직 연동, 이름이 아닌 **id 저장** |
| table(반복 행 그룹) | jsonb 행 배열 | 지출 내역 등 — 행 안에 하위 필드 정의 |
| auto(기안자/직위/부서/기안일) | 스냅샷 저장 | 제출 시점 값 고정 |
| contract_select / facility_select ★MCM 특수 | contract_id / facility_id | 계약·사업장 연동(출장 계약구분·계약명을 실데이터로) |
| editor(자유 서식 본문) | html/text | 업무기안 등 자유 본문용 — **남용 금지**(구조화 우선) |

## 4. 데이터 모델 초안 (관례: text 타임스탬프·integer boolean·멱등)

- `approval_form_folders(folder_id, name, sort)` — 양식 폴더 트리.
- `approval_forms(form_id PK, folder_id, name, description, fields jsonb[필드 정의 배열:
  {key,label,type,options,required,colSpan,row,tableColumns…}], doc_no_rule(채번 규칙 key),
  retention_years, org_folder/dept_folder(완료 문서함 지정), auto_line jsonb(자동 결재선),
  mobile_allowed, use_yn, version)` — 양식 수정 시 **version 증가+스냅샷**(기존 문서는 제출
  당시 fields 스냅샷으로 렌더).
- `approval_docs(doc_id PK, doc_no, form_id, form_version, title, urgent, status(draft/
  in_progress/approved/rejected/canceled), drafter_user_id, drafter_employee_id, dept_id,
  field_values jsonb, submitted_at, completed_at, created_at, updated_at)` +
  `field_values` GIN 인덱스. (정렬·집계 성능이 필요해지면 EAV 보조 테이블
  `approval_doc_values(doc_id, field_key, value_text, value_number, value_date)` 추가 —
  v1 은 jsonb 로 시작. §8 논점)
- `approval_steps(step_id, doc_id, step_order, step_type(agree/approve), mode(seq/parallel),
  assignee_user_id, status(waiting/pending/approved/rejected/skipped), acted_at, comment,
  delegated_from)` — 합의 병렬은 같은 step_order 복수 행.
- `approval_watchers(doc_id, user_id, kind(ref/view), read_at)` — 참조/열람.
- `approval_line_presets(preset_id, owner_user_id, name, line jsonb)` — 나의 결재선.
- `doc_no_sequences(rule_key, year, last_seq)` — 양식별 채번. **공문 `{연도}-대외-{NNNNN}` 도
  이 채번기의 규칙 하나로 통합**(공문 블루프린트 §4-1 흡수).
- 첨부: 기존 계약문서 저장 패턴(putContractDocument) 재사용 — `approval_doc_attachments`.
- `approval_delegates(user_id, delegate_user_id, enabled)` — 대결자 사전 지정(§8-4).
  대결 활성 판정은 결재 차례 도래 시점에 결재자의 **승인된 휴가 기간** 여부로 자동.
- `annual_leave_ledger(employee_id, year, granted_days, used_days, entries jsonb 또는 행
  분리(부여/사용/조정, 승인 doc_id 연결))` — 연차 대장(§8-5). 휴가신청 승인 시 자동 차감,
  반차 등 단위는 양식 필드 정의에 따름. 초기 잔여는 사용자 자료 임포트.

## 5. 화면 구성 (cdash)

1. **전자결재 홈**: 결재 대기(내 차례)/예정/참조·열람 카운트 + 대기 카드(긴급 우선) +
   기안 진행/완료 목록. (다우 홈 구도 차용)
2. **기안 작성**: 양식 선택 모달(폴더 트리+자주 쓰는 양식+검색) → 양식 렌더러(그리드 행
   레이아웃, 자동 항목 프리필, 계약/사업장 선택 필드는 기존 picker 재사용) → 결재선 편집
   (조직도+나의 결재선, 단계 타입/합의방식, 참조·열람) → 임시저장/상신.
3. **결재함**: 대기 문서 열람(양식 렌더+필드 값) → 승인/반려(의견) — 병렬 합의는 전원 처리
   시 다음 단계로. 참조/열람자는 읽음 기록.
4. **문서함**: 개인(기안/임시/결재한/참조·열람/발송) · 부서(기안 완료) · 전사(양식별 지정
   문서함) — 물리 폴더가 아닌 **저장 뷰(쿼리)** 로 구현. 보존연한은 표시+만료 보고서(자동
   삭제는 §8 논점).
5. **양식 빌더**(관리자): 필드 팔레트 → 행 추가·필드 배치(콜스팬 조절)·속성 편집(라벨/필수/
   옵션/표 하위 열) → 미리보기 → 채번 규칙·문서함·보존연한·자동 결재선 설정. 폴더 관리.
6. **★양식별 문서 조회**(데이터 테이블): 양식 선택 → 필드가 컬럼으로 펼쳐진 표(모든 문서),
   필터·정렬·기간·기안자·**엑셀 내보내기**. 예: 출장보고서 → 출장자|기간|출장지|면담자|
   목적 컬럼 즉시 조회. (다우에서 불가능했던 것)

## 6. 공문 발송 시스템과의 관계

- 공문 블루프린트(§4-4)의 "경량 승인"은 **본 전자결재로 대체**한다. 공문 기안 = 전자결재의
  한 양식군(공문 유형 7종), 결재 완료 시 공문 채번·HWPX 생성·발송함 기록으로 이어지는
  **도메인 확장**. 공문 전용 개발분은 채번 규칙·본문 블록 에디터·HWPX 생성·발송 기록이며
  결재·문서함·알림은 전자결재 코어를 그대로 쓴다.
- 구축 선후(권고): **전자결재 코어(§7 E-P1~E-P2)를 먼저 얇게 구축 → 공문을 첫 적용
  도메인으로 탑재** → 이후 인사·지출 양식 이관. (공문을 경량 승인으로 먼저 냈다가 재작업
  하는 것보다 낫다. §8 논점)

## 7-1. 우선 양식 5종 필드 정의 (E-P0 실측, 2026-07-21 스샷 수령)

공통: 문서 헤더(기안자·소속·기안일·문서번호)와 결재선 표시는 **렌더러 공통부**(자동) —
양식 fields 에는 본문 필드만 정의한다. "처음엔 유사하게 구현하되 완전 동일할 필요 없음,
세부는 사용자가 웹 빌더에서 직접 수정 + 진행 중 항목·기능 추가 요구 가능"(사용자 방침).

1. **국내 출장 신청**(biz_trip_request): 출장기간(period) / 출장분류(select: 일반(당일 복귀)
   등) / 출장지(text) / 교통편(checkbox 복수: 법인차량·KTX·고속버스·대중교통·택시·렌터카·
   항공기·자차) / 배차: 이용차량(select)+이용시간(radio 종일/오전/오후) / 출장 출발
   시각(time) / 계약 구분(checkbox: 통합환경허가·장외&화관법·HAPs·Etc.) / 계약명(text) /
   동행자(text) / 출장목적(multitext) / 하단 사규 안내(static).
2. **출장보고서**(biz_trip_report — 원본은 본부별 양식 분리, MCM 은 공통 1벌로 시작):
   출장일자(period) / 용역분류(checkbox: 통합·화관법·HAPs·기타) / **일정 표(table 반복행:
   일자(date)·시각(text)·방문지(text)·동행자(text))** — 원본의 일정1~4 고정 슬롯을 반복
   행으로 개선 / 방문목적(text) / 접견인(text) / 출장내용 상세(multitext).
3. **초과/휴일근무 신청**(overtime_request): 담당 프로젝트·용역명(text, 필수) / 업체명(text,
   필수) / 용역분류(select) / 일시(period+시간 text) / 주52시간제: 기사용시간·신청시간·
   잔여시간(number) / 사유(multitext, 필수).
4. **지출 결의서·법인카드**(expense_report): **내역 표(table 반복행: 사용일(date)·사용처
   전표상 상호(text)·지출 항목 구분(select)·사용내역(text)·사용금액(currency, 합계 열)·
   비고(text))** + 사용금액 총계 자동 계산(렌더러 sum).
5. **휴가신청서**(leave_request): 휴가 종류(select: 연차·반차(오전)·반차(오후)·경조휴가·
   예비군/민방위·병가 등, 필수) / 휴가 기간(period, 필수) / 사용일수(number — E-P3 에서
   자동 계산·연차 차감 연동) / 휴가 사유(multitext, 필수) / 안내(static: 반차·예비군·경조).
   원본 하단의 "결재선 수동 조정" 안내는 자동 결재선으로 대체(다우 불편 해소).

## 8. 확정 결정 (2026-07-21)

1. **다우 전환**: 병행 운영 기간을 두고 테스트 후, 기존 완료 문서를 **가능한 한
   마이그레이션**한다. 다우 export 형식은 사용자가 추후 확인해 전달 예정(그때 이관 설계).
2. **선후**: **전자결재 코어 먼저 구축 → 공문 탑재**(§6 권고안 채택).
3. **우선 구현 양식 5종**(실사용 빈도순): **출장신청서 → 출장보고서 → 초과근무신청서 →
   지출결의서 → 휴가신청서**. 각 양식의 현 서식 캡처·파일은 E-P0 착수 시 사용자가 제공.
4. **전결/대결**: **전결은 기능만 구현하고 당분간 미사용**. **대결은 결재자가 '휴가'로
   부재할 때만** 사전 지정된 대결자에게 권한 위임(출장은 업무의 연장이므로 대결 비활성).
   → 휴가신청이 본 시스템 안에 있으므로 **승인된 휴가 기간과 연동해 자동 활성화** 가능:
   결재 차례가 온 시점에 결재자가 승인된 휴가 기간 중이면 대결자에게 라우팅(delegated_from
   기록, 문서에 '대결' 표기). 대결자 지정은 사용자별 설정(`approval_delegates`).
5. **연차 관리 포함**: 휴가신청 승인 → 연차 잔여일수 자동 차감까지 구현.
   `annual_leave_ledger`(직원별 연도별 부여/사용/잔여, 승인 문서 연결) 신설. 초기 잔여일수는
   사용자가 별도 관리 중인 자료를 구현 시점에 받아 임포트.
6. **EAV 보조 테이블**: v1 은 **jsonb 단독**으로 시작(33명 규모 문서량이면 충분).
   양식별 조회 성능이 문제 되면 그때 EAV 파생 테이블 추가(jsonb 원본에서 언제든 재생성
   가능하므로 지금 결정에 리스크 없음).
7. **알림**: 결재 대기 알림은 **이메일(SES)+알림톡(솔라피) — MCM 앱이 발송 주체**(범용
   스크래퍼 알림 채널 자격증명 재사용). 향후 MCM 네이티브 앱 개발 시 모바일 푸시/알림톡
   수신 확장 예정.
8. **보존연한**: 표시 + 만료 보고서만. 자동 삭제 없음.
9. **모바일**: /m 에 결재함(대기 목록+승인/반려)을 테스트 목적으로 우선 구현.
