# 모바일 앱 2차 개편 블루프린트 (2026-08-06)

[모바일 기능 갭 분석](mobile-feature-gap-analysis.md)과 사용자 지시를 반영한 상세 구현 계획.
1차(홈 화면 개편, 커밋 792e03d)에 이어지는 작업이다.

## 사용자 확정 방향

1. **차량 예약은 단독 불가** — 반드시 **출장신청 기안**을 통해서만 예약된다(`frm-biz-trip-request` 의 `asset_select` 필드). 따라서 차량 예약을 모바일에 여는 유일한 길은 **제대로 된 전자결재 기안**이다.
2. 현재 모바일 휴가 신청 같은 **임시 폼이 아니라, 데스크탑 양식 렌더러에 준하는 폼**으로 업그레이드한다.
3. 일정은 **데스크탑 `/calendar` 를 그대로 이식하는 수준**으로 개조한다.
4. 사업장은 초기 `/m` 프로토의 **업종 태그·용역/영업 진행 중 태그**를 복원하고 **지역권 선택**을 추가한다. 상세 정보도 자세히 표기한다.
5. 근태·휴가는 **연차 총/사용/잔여 + 주 초과근무를 인포그래픽으로**, 화면에서 바로 **휴가·초과근무 신청** 가능하게 한다.
6. 영업은 **신규 영업건·스케줄 등록**을 열고, **캘린더 + 스케줄 타임라인**을 배치해 스케줄을 눌러 **경과를 바로 입력**한다.

## P0. 공통 기반 — 먼저 만들어야 나머지가 싸진다

세 화면(일정·영업·기안 날짜 입력)이 같은 부품을 요구한다. 따로 만들면 세 번 만들고 세 번 어긋난다.

### P0-0. 홈 UI 템플릿을 전 화면 기본으로 (사용자 확정) ★ 가장 먼저

1차 홈 개편에서 확립한 **핸드오프 2a "소프트 플랫"** 을 앱 전체의 기본 UI 로 삼는다. 지금은 그 스타일이 `app/(tabs)/index.tsx` **안의 로컬 함수**(`Section`·`Kpi`·`CountBadge`·`Quick`)로 갇혀 있어 다른 화면이 쓸 수 없다. **`components/ui/` 로 승격**하는 것이 2차 개편의 실질적 출발점이다.

**승격할 부품**

| 컴포넌트 | 규격(핸드오프 2a) | 쓰이는 곳 |
|---|---|---|
| `<CardSection title badge action>` | 카드 bg `cd-card` · border 1px · radius 16 · padding 16 / 타이틀 14px/700 / 카운트 배지 / 우측 텍스트 링크 12px/600 primary | 거의 모든 화면의 묶음 단위 |
| `<StatTile label value delta tone>` | 라벨 11 muted → 수치 22/800 → 상태 10/700(값 0 이면 연회색 "없음") | 홈 KPI · 근태/휴가 요약 · 계약 요약 |
| `<CountBadge>` | radius 99 · 11px/700 · 톤별 tint | 카드 헤더 · 리스트 행 |
| `<ActionTile icon label tone>` | 54px 스퀘클 radius 19 + 그림자 `0 6px 14px rgba(60,70,150,.12)` | 빠른 실행 · 화면별 액션 그리드 |
| `<ListRow title meta right chevron>` | 제목 13px/600 · 메타 11.5 faint · 구분선 `cd-grid-line` · chevron 14 | 목록형 화면 전부 |
| `<ScreenHeader title subtitle right>` | 제목 21px/700 + 부제 12 faint · 우측 액션(38px 원형 버튼) | 탭 헤더를 끄고 자체 헤더를 그리는 화면 |

**레이아웃 규칙(전 화면 공통)**: 페이지 좌우 여백 **18px** · 섹션 간 **14px** · 카드 내부 패딩 16 · 그리드 gap 8. 색은 항상 cd 토큰(다크 대응), 핸드오프 hex 직접 사용 금지.

**적용 범위**
- **신규 화면(P1~P6)은 처음부터 이 부품으로만** 만든다.
- **기존 화면**(결재·메일·소통·사업장·담당자·근태·설정 등)은 각 P 단계에서 그 화면을 건드릴 때 함께 이관한다. 손대지 않는 화면은 별도 정리 단계에서 일괄 이관한다 — 한 번에 전부 바꾸면 회귀 위험이 크고 검증이 어렵다.
- 홈 화면도 로컬 함수를 지우고 승격된 부품을 쓰도록 바꾼다(중복 정의 방지 — 두 벌이 되면 반드시 갈라진다).

### P0-1. 공용 월 캘린더 컴포넌트 `<MonthCalendar>`
데스크탑 `components/calendar/ScheduleCalendar.tsx`(6주 격자 · 멀티데이 바 레인 배정 · 초과분 "+N")의 RN 판.

- 입력: `events: {id, start, end, label, color, ink}[]`, `year`, `month0`, `onMonthChange`, `onDayPress`, `onEventPress`

- 모바일 폭(390) 기준 레인 3개 + "+N", 셀 높이 가변.
- **날짜 선택 모드**(`mode="picker"`)를 함께 지원 — 이 하나로 아래 P1의 date/period 필드를 해결한다.

> ★ 이 컴포넌트가 **네이티브 date picker 의존을 없앤다**. `@react-native-community/datetimepicker` 를 쓰면 네이티브 모듈이라 EAS 재빌드가 또 필요한데, 자체 캘린더로 처리하면 이번 2차 개편은 **전부 OTA(`eas update`)로 배포 가능**하다. (첨부 파일은 이미 설치된 `expo-document-picker`·`expo-camera` 로 커버되므로 역시 재빌드 불필요.)

### P0-2. 조직도 인원 선택 시트 `<OrgPickerSheet>`
데스크탑 `components/approval/OrgPickerModal.tsx` 대응. 결재선·참조자·`user_select` 필드가 공유한다.
- 부서 트리 + 이름 검색, 다중/단일 선택 모드. 데이터: `/api/organization`·`/api/directory`(기존 `DirectoryPane` 재사용 가능)

### P0-3. 검색 선택 시트 `<EntityPickerSheet>`
`company_select`(사업장) · `contract_select`(계약) · `contact_select`(담당자) · `asset_select`(자산) 공용. 검색어 입력 → 목록 → 선택 → **자동 채움 규칙(`FILL_SOURCES`) 적용**.

## P1. 전자결재 모바일 기안 ★ 최우선

### 목표
데스크탑 `ApprovalFormRenderer`(1,173줄)가 지원하는 **필드 타입 19종**을 모바일에서 제대로 렌더·입력하고, 결재선을 붙여 상신한다. 기존 `leave/request.tsx`(전용 하드코딩 폼)는 **폐기하고 이 렌더러로 대체**한다.

### 화면 구성
```
기안 (스택)
 ├ 1단계: 양식 선택      GET /api/approval/forms          (자주 쓰는 양식 상단 고정)
 ├ 2단계: 내용 작성      GET /api/approval/forms/{formId}  → 필드 렌더
 │         제목 · 긴급 토글 · 필드들 · 첨부
 ├ 3단계: 결재선         GET /api/approval/line-presets    (프리셋 우선, 조직도 추가)
 └ 상신/임시저장         POST /api/approval/docs
```
단계형(위저드)으로 가되, 2단계는 스크롤 한 화면에 전부 표시한다(데스크탑과 같은 순서·라벨).

### 필드 타입 → 모바일 UI 매핑

| 타입 | 모바일 구현 | 비고 |
|---|---|---|
| `text` | 단일행 입력 | |
| `multitext` | **리치 텍스트(HTML)** — 읽기는 `HtmlView`, 쓰기는 평문 입력 → 최소 HTML 변환 | ★ 아래 주 참조 |
| `number` / `currency` | 숫자 키패드, 통화는 천단위 포맷 | |
| `select` / `radio` | 옵션 시트(항목 3개 이하면 인라인 칩) | |
| `checkbox` | 토글 목록 | |
| `date` | **P0-1 캘린더 피커** | 8자리 직접 입력도 병행 |
| `time` | HH:MM 마스크 입력 | 데스크탑도 텍스트 입력 |
| `period` | 시작·종료 2회 선택(캘린더에서 범위 드래그 대신 2탭) | |
| `user_select` / `dept_select` | **P0-2 조직도 시트** | |
| `company_select` | **P0-3** 사업장 검색 + 자동 채움 | 주소·대표자·전화·사업자번호·지역 |

| `asset_select` | **P0-3** 자산 시트 + **기간 내 가용성 표시** ★ | 차량 예약의 실체 |

> ★ **`multitext` 는 평문이 아니라 HTML 이다.** 데스크탑 렌더러가 `MailEditor`(contentEditable)를 재사용해 서식 있는 HTML 을 저장한다(초과/휴일근무 신청의 "사유" 필드가 그렇다). 모바일에서 평문 textarea 로 그대로 저장하면 데스크탑 표시가 깨지고, 반대로 데스크탑에서 쓴 HTML 을 평문 입력에 넣으면 태그가 노출된다.
> → **읽기**는 이미 있는 `components/ui/HtmlView.tsx`(결재 multitext 렌더 용도로 만들어져 있음)를 쓰고, **쓰기**는 평문 입력을 받아 저장 시 줄바꿈을 `<br>`·문단을 `<p>` 로 감싸는 최소 변환을 적용한다. 서식 편집(굵게·목록·표)은 모바일에서 지원하지 않고, 기존 서식이 있는 값을 편집하려 하면 "웹에서 편집" 안내를 띄운다(서식 유실 방지).

### 모바일 상신 허용 정책 (사용자 확정)

모바일에서 **모든 양식을 상신할 수 있게 하지 않는다.** 입력이 무거운 양식은 데스크탑에 맡기고, 모바일은 승인·참조만 한다.

| 구분 | 모바일 | 판정 방법 |
|---|---|---|
| **상신 허용** | 출장신청 · 휴가신청 · 초과/휴일근무 신청을 **양식 선택 상단에 고정**. 그 외 양식도 아래 제외 조건에 걸리지 않으면 상신 가능 | — |
| **상신 제외 ①** — `table` 필드를 쓰는 양식(지출결의 · 출장 보고서 등) | 목록에 흐리게 + "웹에서 작성" 배지, 탭하면 안내 | **양식 정의를 로드해 `type === "table"` 필드 존재 여부로 자동 판정** — 양식 ID 하드코딩 금지(관리자가 빌더에서 바꾼다) |
| **상신 제외 ②** — 공문 · 견적서 | 발송 기능 자체를 모바일에 두지 않는다. 승인·참조만 | 전용 작성 경로(`/approval/letter`·`/approval/quote`)라 양식 목록에서 애초에 빠진다. 목록에 섞여 나오면 명시 제외 |

★ **상신을 막는 대신 읽기는 완벽해야 한다** — 승인만 가능한 양식인데 표 내용이 안 보이면 결재를 할 수 없다. 확인 결과 모바일 `components/approval/FieldValue.tsx` 에 **`table` 읽기 렌더가 이미 구현돼 있다**(행마다 "열: 값" 세로 카드로 재배치 — 좁은 화면에서 표를 축소하지 않고 리플로우). 추가 작업 없음.
(2026-08-06 최초 조사에서 `case` 문만 훑어 "빈칸으로 나온다"고 잘못 적었던 것을 정정한다 — 해당 블록은 `if` 문이라 눈에 걸리지 않았다.)

### 양식별 특수 로직 — 데스크탑에 하드코딩되어 있어 모바일도 복제해야 한다

데스크탑 `ApprovalDraftBoard` 는 범용 렌더러 위에 **양식별 특수 처리**를 얹는다. 모바일 기안이 이걸 빠뜨리면 같은 양식인데 동작이 다른 앱이 된다.

| 양식 | 특수 처리 | 모바일 대응 |
|---|---|---|
| 휴가 신청 `frm-leave-request` | 올해 **잔여 연차** 조회·표시, 신청 일수가 잔여를 넘으면 경고 | 잔여를 헤더에 표시(P4 화면과 같은 값), 초과 시 경고 배지 |
| 초과/휴일근무 신청 `frm-overtime-request` | `GET /api/approval/overtime/week-usage?date=` 로 **주 사용량 조회** → `used_hours`(기사용)·`remain_hours`(잔여)를 **자동 채움**, 힌트 문구 표시 | 동일 API 호출·자동 채움. 사용자가 손대는 값은 `apply_hours`(신청시간)뿐 |
| 초과/휴일근무 신청 (12h 초과 시) | **특별휴가 전환 동의(전자서명) 모달** — 동의 없이는 상신 자체가 서버에서 거부됨(`assessOverLimitOnSubmit` 이 throw) | `OvertimeConsentModal` 대응 시트 필수. 이게 없으면 12h 초과 신청이 모바일에서 **영원히 상신 실패**한다 |

### 차량 예약(핵심 시나리오)
출장신청 양식을 고르면 → 기간(`period`) 입력 → `asset_select` 에서 차량 선택 시 **그 기간에 이미 예약된 차량을 흐리게/배지 표시**. 상신하면 결재 완료 시점에 자산 이용 현황에 반영된다(현행 서버 로직 그대로).
- 필요 조회: `GET /api/assets` + `GET /api/assets/reservations?from&to` (기존 API)
- 가용성 판정은 **클라이언트에서 겹침 계산** — 신규 API 불필요

### 첨부 — **웹·앱 모두 미구현, 후속 과제** (2026-08-06 사용자 확인)
현재 전자결재 문서에는 첨부 기능이 아예 없다(웹 기안 화면에도 UI 가 없고 `approval_docs` 에 첨부 테이블이 없다). 처음엔 "필요 없는 것"으로 판단했으나, 증빙이 필요한 양식이 실제로 존재한다 — **예비군·병가·경조사 휴가의 증빙 서류, 지출결의 영수증** 등. 첨부가 필요 없는 휴가·초과근무를 먼저 테스트하다 드러나지 않았을 뿐이다.

→ **서버(테이블·업로드 API)부터 만들어야 하는 별도 과제**로 분리한다. 모바일에서 붙일 때는 명함 촬영에서 확립한 방식을 쓴다: `expo-document-picker`(파일)·`expo-camera`(촬영) + expo-file-system `File` 업로드(SDK 57 fetch 가 RN FormData 파트를 거부하는 이슈 회피). 촬영 첨부는 모바일이 데스크탑보다 나은 몇 안 되는 지점이라 우선순위가 낮지 않다.

- 추가/변경: P0-2 조직도 시트로 인원 추가, 합의/승인 타입 토글, 순서 이동

### 주의점
- 필드 `key` 는 서버 양식 정의를 그대로 따른다(하드코딩 금지 — 관리자가 빌더에서 바꾼다).
- 조건부 필드·필수 검증 규칙은 데스크탑 렌더러와 **같은 판정**을 써야 반려가 안 난다. 렌더러의 검증 로직을 `lib/approval/` 의 클라이언트 안전 모듈로 뽑아 양쪽이 공유하는 방안을 우선 검토(웹 회귀 위험이 있으면 모바일에 복제하되 근거 주석).
- 임시저장 후 상신 시 **stale docId 로 이중 상신**되는 사고 이력이 있다(공문 발송 개발 때). 저장 응답의 docId 를 상태에 반영하고 재상신 시 그 값을 쓴다.

## P2. 일정 — 데스크탑 `/calendar` 이식

### 현재 문제
모바일 `schedule.tsx` 는 영업 활동 + 휴가만 본다. 회의·출장·교육·차량 일정이 없고 **등록이 안 된다**.

### 이식 대상
데스크탑 `CalendarBoard`(태그 칩 → 월 캘린더 → 카테고리별 목록) 구조를 그대로.

- 데이터: `GET /api/calendar?month&tags` (스케줄명은 서버가 조립) / 설정: `/api/calendar/prefs`
- 태그 5종 **self(본인)·dept(부서)·sales(영업)·refs(선택)·vehicle(차량)** + 색상 상수(`TAG_COLOR`/`TAG_INK`/`TAG_COLOR_STRONG`)를 **데스크탑과 같은 값**으로 옮긴다.
- 구성: 상단 태그 칩(복수 토글, 서버 저장) → **P0-1 월 캘린더**(카테고리 색 바) → 하단 카테고리별 카드 목록
- 캘린더 바 탭 → 하단 해당 카드로 스크롤·강조(데스크탑과 동일 상호작용)
- 본인 카드의 문서 버튼 → 기존 `approval/[docId]` 상세로 이동
- 참조 대상 선택(`CalendarRefsModal`) → 시트로

### 등록
캘린더에서 일정 등록은 **기안으로 연결**한다(출장·교육·휴가는 전부 결재 문서가 원천이므로). 날짜 셀 롱프레스 → "출장 신청 / 교육 신청 / 휴가 신청" 선택 → P1 기안 화면에 날짜 프리필.
> 이 설계는 데스크탑과 동일한 원칙이다 — 일정은 결재 문서의 **투영**이지 독립 엔티티가 아니다. 영업 스케줄만 예외(P5에서 직접 등록).

### 기존 화면 처리
현재 `schedule.tsx` 의 영업 활동·경과 입력은 **P5 영업 화면으로 이관**하고, 이 화면은 그룹웨어 일정 전용이 된다. 더보기·홈 빠른실행의 "일정" 진입점은 그대로 이 화면을 가리킨다.

## P3. 사업장 — 탐색 복원 + 상세 강화

### P3-1. 탐색(초기 `/m` C안 복원 + 지역권)
원본: `frontend/components/mobile/MobileFacilities.tsx`(601줄). API 는 이미 전부 있다.

- **초기 화면**: 검색창 + 최근 본 사업장(로컬 저장) + **관계 카드**(용역 진행 중 N · 영업 진행 중 N) + **업종별 카운트 그리드**

  - 관계 = `engagement=contract,sales`
- **결과 리스트**: N곳 헤더 + 30건 페이징(더보기)
- 저장 키·정렬은 원본과 동일하게

### P3-2. 상세 (신규)
현재 모바일에는 상세가 없다. 요구하신 항목을 담는다.

| 섹션 | 항목 |
|---|---|
| 기본 | 사명 · 사업자등록번호 · 대표자 · 소재지(지도앱 연결) · 대표 전화 |
| 업종·허가 | 업종명/코드 · **통합허가 대상업종 여부** · 대기/수질 종별(airClass·waterClass) · **허가번호 · 허가일** (사용자 확정 — 이 둘만. 재검토 기한 등 상세 허가 정보의 태그화는 추후 과제) |

## P4. 근태·휴가 — 인포그래픽 + 즉시 신청

한 화면(`/leave` 확장 또는 신규 "근태·휴가")에 연차와 초과근무를 함께 놓는다.

### 구성
```
┌ 연차 ────────────────────────────┐
│  도넛 게이지: 잔여 / 총           │
│  총 N일 · 사용 N일 · 잔여 N일     │
│  발생 기준일 · 소멸 예정 안내      │
│  [휴가 신청]  ← P1 기안(휴가 양식) │
└──────────────────────────────────┘
┌ 이번 주 초과근무 ────────────────┐
│  막대/게이지: 사용 Nh / 한도 12h  │
│  요일별 미니 막대(월~일)          │
│  주 52h 경고 배지(초과 시)        │
│  [초과근무 신청]                  │
└──────────────────────────────────┘
┌ 최근 이력 (탭: 휴가 / 근태) ─────┐
```

- 연차: `GET /api/approval/leave?me=1&year=` (기존 모바일이 이미 사용)
- 초과근무: `GET /api/approval/attendance/me`, 주간 사용량 `GET /api/approval/overtime/week-usage`
- 인포그래픽은 **react-native-svg 로 직접 그린다**(1차에서 이미 도입 — 차트 라이브러리 추가 불필요). 홈 위젯의 연차 게이지와 같은 시각 언어를 쓴다.
- **[휴가 신청]** = P1 기안(`frm-leave-request` 프리필)
- **[초과근무 신청]** = P1 기안(**`frm-overtime-request` — 초과/휴일근무 신청** 프리필). 12h 초과면 동의 시트가 뜬다(위 특수 로직 표 참조)
- 두 버튼 모두 P1 기안 렌더러에 의존하므로, **P1 없이는 이 화면이 반쪽**이다(조회만 가능). 순서를 P1 → P4 로 두는 이유다.

## P5. 영업 — 등록 + 캘린더 + 타임라인 + 경과 입력

데스크탑 `SalesBoard`(648줄) · `SalesCalendar`(295줄) · `ScheduleModal`(364줄) · `ProgressReportModal`(135줄) 대응.

### 화면 구성 (신규 "영업" 화면, 더보기·홈 빠른실행 진입)
```
[+ 신규 영업건]  [+ 일정 등록]
┌ 월 캘린더 (P0-1) ─────────────┐   활동 유형별 색 바
└───────────────────────────────┘
┌ 스케줄 타임라인 ───────────────┐

│   14:00 ㈜○○ 방문  [경과 입력] │
│  내일 ─────────────────────    │
│   ...                          │
│  경과 미입력 N건 (상단 고정)    │
└───────────────────────────────┘
```

- 캘린더 데이터: `GET /api/sales/schedule?month=` (모바일이 이미 사용 중)

  > ⚠ 활동 본 PUT 은 전체 교체라 부분 갱신에 쓰면 안 된다(기존 주석에 명시된 함정).
- **신규 영업건 등록**: `POST /api/sales/projects` — 사업장 선택(P0-3) · 제목 · 용역 분류 · 담당자.
  **권한 `sales.edit` 보유자에게만 버튼 노출**(데스크탑과 동일 — 없는 사람에게 눌러서 403 을 보여주지 않는다)
- **일정(활동) 등록**: `POST /api/sales/activities` — 영업건 선택 · 유형 · 일시(P0-1 피커) · 연결 담당자 · 메모
  - 데스크탑 `ScheduleModal` 입력이 무거워 1차에서 제외했던 항목이다. 모바일은 **필수 항목만** 받고 나머지는 나중에 채우는 방식으로 축약한다.

## P6. 공공입찰 알림 리스트 정리 (사용자 요청 2026-08-06)

알림 기능 테스트로 큐에 항목이 대량으로 쌓였는데 지울 방법이 없어 화면이 지저분한 상태다. 정렬·필터도 없다.

### 현재 구조
- 데이터원: `bid_match_notices` 큐를 `GET /api/sales/bids/matches` 가 bid 단위로 접어서(`DISTINCT ON`) 반환
- 정렬: 기본 **최근 매칭순**(`matched_at DESC`), `?filter=deadline` 이면 마감 임박순
- 응답에 이미 있는 것: `categoryName`(용역 분류) · `orgName` · `postedAt`(공고일) · `deadline` · `budget` · `details[]`
- **삭제 API 없음 · 지역 정보 없음**

### 해야 할 일

| # | 요구 | 구현 |
|---|---|---|
| 1 | **선택 삭제 · 일괄 삭제** | `DELETE /api/sales/bids/matches` 신규 — body `{noticeIds: []}` 또는 `{all: true}`(현재 필터 조건 포함). 권한은 조회(`sales.view`)보다 높은 **`sales.edit`** |
| 2 | **최근 공고순 정렬** | `?sort=posted` 추가 → `posted_at DESC`. 기존 `matched_at DESC`(최근 매칭순)·마감 임박순과 함께 **정렬 3종 토글** |
| 3 | **공고일 태그 표기** | `postedAt` 은 이미 응답에 있다 — 카드 태그 줄에 `공고 08/06` 형태로 추가(UI 만) |
| 4 | **용역 구분 필터** | `categoryName` 기준. 서버에 `?categories=` 추가(페이징과 어긋나지 않게 서버 필터로) |
| 5 | **지역권 필터** | `lib/bid/bid-queries.ts` 의 **`REGION_GROUPS`**(수도권·강원권·충청권·경북권·경남권·전라권·제주권) 재사용. 발주기관명 키워드 매칭으로 `?regions=` 필터 + 응답에 `regionGroup` 을 실어 카드 태그로도 표시 |

### 삭제 방식 — **하드 삭제** (사용자 확정)
`bid_match_notices` 에서 행을 실제로 지운다. 이 큐는 알림 전달용이지 감사 기록이 아니므로 소프트 삭제(컬럼 추가)로 복잡도를 올리지 않는다. **웹의 알림 벨·이력에서도 함께 사라진다는 점은 의도된 동작**이다.

안전장치는 둔다:
- 일괄 삭제의 범위는 **"현재 필터에 해당하는 건"** 으로 한정한다(무조건 전체 삭제 금지).
- 실행 전 **건수 확인**("N건을 삭제합니다")을 받는다.
- 되돌릴 수 없으므로 삭제 후 토스트에 건수를 남긴다.

## 참고 — 초과/휴일근무 신청은 이미 완성되어 있다 (2026-08-06 코드 확인)

`frm-overtime-request` 는 양식·서버 로직이 3단계로 갖춰져 있다(`lib/approval/overtime.ts`). 모바일은 **이 파이프라인에 올라타기만 하면 된다** — 서버 변경 불필요.

1. **기안 화면** — 신청 주의 기존 신청(진행+승인) 합 + 근태 실적을 합산해 주 12h 초과를 미리 경고하고, 기사용·잔여 시간을 자동 채운다.
2. **상신 시** — 초과 판정을 `field_values._over_limit` 에 **스냅샷으로 고정**한다(나중에 다른 신청이 승인돼도 판정이 흔들리지 않게). 12h 초과인데 동의 서명이 없으면 상신을 거부한다. 기간을 고쳐 주가 바뀌면 재동의를 요구한다.
3. **근태 인제스트 후** — 그 주에 승인된 신청 합이 한도를 넘고 실제 초과분(`excess_minutes`)이 있으면, **초과근무 대체휴가를 시간 단위로 자동 적재**한다. 부여량은 근로기준법 56·57조대로 가산 반영(주간 1.5배 · 야간 2.0배)하고, `ref_key = 'ot-<weekStart>'` 로 멱등이라 근태를 재업로드해 조건이 사라지면 **자동 적재분만 회수**된다(수기 입력은 건드리지 않는다).

즉 "신청 → 승인 → 근태 대조 → 대체휴가 적재"가 코드상 닫혀 있다. **남은 것은 실측뿐**이다 — 테스트 신청 1건을 승인하고 그 주 근태를 업로드해 `special_leave_ledger` 에 `source='auto_overtime'` 행이 들어오는지 확인하면 된다. 실측 시 볼 것: 승인 신청 합이 12h를 넘는지, 근태 주간 집계에 `excess_minutes` 가 잡히는지(둘 중 하나라도 0이면 적재되지 않는 것이 정상 동작).

## 확정 사항 (2026-08-06 사용자 확정)

1. **모바일 상신 양식 우선순위** — 출장신청 · 휴가신청 · 초과/휴일근무 신청 3종이 사용 빈도 최상. 양식 선택 화면 상단 고정.
2. **`table` 필드를 쓰는 양식은 모바일 상신 불가** — 지출결의 · 출장 보고서 등. 승인·참조만. 표 값 **읽기 렌더는 신규 구현 필요**(현재 빈칸).
3. **공문 · 견적서도 모바일 상신·발송 불가** — 승인·참조만.
4. **사업장 허가 정보는 허가번호 · 허가일만 표기** — 추후 허가 정보 태그화로 상세 확장 여지 있음.
5. **영업건 신규 등록 권한 = `sales.edit` 보유자만** — 모바일도 데스크탑과 동일하게 적용(권한 없으면 등록 버튼 자체를 숨긴다).
6. **공공입찰 알림 리스트**(P6) — 선택·일괄 삭제, 최근 공고순 정렬, 공고일 태그, 용역 구분·지역권 필터.
7. **홈 UI 템플릿을 전 화면 기본으로 적용** — 신규 화면은 처음부터, 기존 화면은 손대는 단계에서 함께 이관.
8. **P6 삭제는 하드 삭제** — 웹 알림 이력에서도 함께 사라지는 것을 감수한다. 일괄 삭제는 현재 필터 범위로 한정 + 건수 확인.

**확인 사항은 모두 해소되었다 — 착수 가능한 상태다.**
