# 데이터 분석(시맨틱 지표) 사용자 가이드

코딩 지식 없이 전자결재 데이터에서 원가·성과 지표를 만드는 방법. (설계 문서는
[semantic-analytics-wizard-blueprint.md](semantic-analytics-wizard-blueprint.md) — 이 문서는 사용자용.)

## 개념 한 장 요약

1. **태그를 붙인다** — 양식 빌더에서 금액·날짜 항목에 "데이터 의미"(출장 경비, 발생일 등)를 지정.
   계약/업체/인원 검색 필드는 자동으로 연결 고리가 된다.
2. **지표를 만든다** — 데이터 분석 화면의 마법사에서 "[출장 경비]를 [합계]로 [계약]별로" 식으로 조립.
3. **결과를 본다** — 차트·표·CSV. 모든 결과에는 산출 근거(대상 문서 수·제외 사유)가 붙는다.

지표는 필드 이름이 아니라 **태그를 참조**하므로, 양식을 바꿔도 같은 태그만 붙이면 지표가 그대로
동작한다. 이것이 "세팅을 하드코딩하지 않는" 핵심이다.

## 화면 안내

| 화면 | 메뉴 | 하는 일 |
|---|---|---|
| 데이터 분석 | 전자결재 > 데이터 분석 | 지표 실행·차트·CSV. 관리자는 "새 지표 만들기" 마법사·자연어 질문 |
| 양식 관리(빌더) | 결재 운영 설정 > 양식 관리 | 필드에 "데이터 의미" 태그 지정(속성 패널 하단) |
| 데이터 의미 사전 | 결재 운영 설정 > 데이터 의미 사전 | 태그 어휘 관리 + **설정 패키지 내보내기/가져오기** |
| 데이터 관계 맵 | 결재 운영 설정 > 데이터 관계 맵 | 양식↔마스터 연결 상태 진단(연결률·미연결 문서·정책 경고) |
| 데이터 지표 | 결재 운영 설정 > 데이터 지표 | 지표 정의 JSON 직접 편집(고급) |

## 마법사로 지표 만들기 (5단계)

1. **템플릿 선택**: 갤러리 카드 중 목적에 맞는 것을 고르거나, 문장으로 설명해 AI 초안 생성.
2. **소스 선택**: 결재 문서(태깅된 값) 또는 시스템 소스(계약 마스터·수행인력·ADT 근태·연차 대장).
3. **계산 정의**: "[값]을 [합계/평균/건수]로 [차원]별 (× 2차 차원) [기간] 단위로" — 드롭다운 조립.
   차원에는 계약·업체·직원 외에 **용역 세분류, 계약금액대**(1천만 미만~3억 이상 자동 구간)가 있다.
4. **연결 확인**: 문서가 계약 등에 얼마나 연결돼 있는지 실측 — 미연결 문서는 집계에서 제외된다.
5. **미리보기·저장**: 실데이터로 계산한 표와 품질 리포트를 확인하고 이름·공개 범위를 정해 저장.

공개 범위: **관리자만**(기본, 인원별 지표 권장) / 전체 공개 / 작성자만.

## 자연어 질문 (권한 필요)

데이터 분석 화면 상단 입력창에 "출장 경비가 제일 많이 든 용역이 어디야?"처럼 물으면
기존 지표를 재사용하거나 임시 지표를 만들어 즉석 계산해 답한다(저장되지 않음).
`reports.nlq` 권한이 있는 사용자에게만 보인다(LLM 비용 발생 — 관리자가 선별 부여).

## 데이터가 정확하려면 (운영 수칙)

- **출장 경비는 출장보고서의 '지출 내역' 표에** 입력한다(지출결의서 금지 — 비출장 지출 전용).
  출장보고서의 계약 검색 필드 덕분에 경비가 용역에 자동 귀속된다.
- 계약 검색에서 **'직접 입력'을 쓰면 집계에서 빠진다** — 가급적 검색으로 선택할 것.
- 연결이 잘 되고 있는지는 데이터 관계 맵에서 수시로 확인(미연결 문서 목록 제공).

## 설정 패키지 (백업·복제)

데이터 의미 사전 화면의 **설정 내보내기** = 양식(폴더 포함)+태그 사전+지표 정의를 JSON 파일 하나로.
**설정 가져오기** = 그 파일을 다른 환경(신규 테넌트)에 적용 — 기존 항목은 덮어쓰고 삭제는 하지 않는다.
새 고객사 온보딩 = 표준 패키지 적용 → 자기 양식에 태그 확인 → 끝.
