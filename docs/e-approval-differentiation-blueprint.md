# 전자결재 차별화 블루프린트 (AX: Approval eXperience)

**분석보고서(`MCM_그룹웨어_차별화기능_분석보고서.md`) 기반 — 전자결재 코어의 현재 상태 점검과 차별화 기능 단계 계획**

작성일: 2026-07-24 · 상태: **v1.1 확정 — §8 논점 7건 사용자 확정(2026-07-24), §9 세부 구현 계획 포함**

## 1. 배경·목적

분석보고서의 핵심 진단: 2025~2026 그룹웨어 시장의 경쟁 축은 "기능 보유"에서 **"그 기능을 AI가 얼마나 대신 처리해 주는가"**로 이동했다. 보고서가 전자결재 축에 직접 해당하는 제언은 다음과 같다.

| 보고서 항목 | 내용 요지 |
|---|---|
| **A-3 전자결재 고도화** (1순위) | ① 상신 전 AI 사전검토(규정·첨부·결재선 오류 + 유사 과거 문서 제시) ② 결재자용 AI 요약(3줄+핵심 수치, 모바일 30초 판단) ③ 지연 관리(부재 시 자동 위임·병목 대시보드·자동 리마인드) |
| **A-1 52시간 컴플라이언스 엔진** (1순위) | 초과 도달 **전** 경고, 신청 시점 잔여 가용시간 표시로 위반 신청 원천 차단, 증빙 관리, 팀 단위 익명 과로 지표 |
| **A-2 지출결의 = 전수 AI 감사 + 사전 통제** (1순위) | 저위험 자동 승인·예외 결재, 사전 품의↔한도 연동, 증빙 자동화 |
| **B-1 자연어 리포팅** (2순위) | "결재 처리 가장 느린 단계가 어디야?" — 시맨틱 레이어가 구조적 우위 |
| **B-3 사규 Q&A 봇** (2순위) | 규정 RAG + 답변에서 바로 실행(휴가 신청 초안 등) |
| **B-5 AI 브리핑 홈** (2순위) | "내가 결재할 문서 2건(각 3줄 요약)" 개인화 홈 |

이 문서는 **전자결재 코어(E 시리즈)와 그 위 근태·연차(LM/LP/ADT) 축**을 대상으로 한다. 지출결의(A-2)는 바로빌 계약 후 별도 트랙(카드 지출결의)에서 다루되, 본 문서의 AI 레이어 설계(§5)를 공유 기반으로 쓴다.

## 2. 현재 구현 상태 점검 (2026-07-24 코드 실측)

### 2-1. 구현 완료 — 이미 확보한 것

| 영역 | 상태 |
|---|---|
| 양식 빌더 | 캔버스형 자유 배치(행 그리드 스냅), 필드 14+종, MCM 특수 필드(업체/계약 검색·조직도 픽커·fillMap 자동 채움), 버전 스냅샷 |
| **필드 완전 DB화** ★ | 양식=필드 스키마, 문서=`field_values` jsonb(GIN) 구조화 저장 → 양식별 데이터 조회(동적 컬럼·필터·CSV) 동작. **다우오피스가 못 하는 것이자 §5 AI 레이어 전체의 전제 — 이미 확보됨** |
| 결재 플로우 | 상신·자동 채번·합의(순차/병렬)/승인·반려(사유 필수→draft 재상신)·의견 |

| 문서함 | 개인(기안/완료/결재)/부서/전사 탭, 보존연한 표시+만료 표기 |

| 근태(ADT) | 출퇴근 엑셀 업로드→**초과근무 자체 산정**(주52h·주 시작 일요일·야간 22-06 2.0배·12h 초과 감지·산정 제외자) + 관리자 UI 3탭 |

## 3. 전략 프레임 — 무엇이 차별화이고 무엇이 기본기인가

보고서의 시장 분석을 MCM 현황에 대입하면:

1. **알림·참조·프리셋·리마인드(G1~G4)는 차별화가 아니라 위생 요건**이다. 다우·하이웍스·두레이 전부 있는 기능이며, 없으면 "AI 얹기" 이전에 도입 자체가 막힌다. 단, 가장 싸고 빠르다.
2. **MCM의 구조적 우위는 이미 만들어져 있다** — 필드 완전 DB화. 다우는 HTML 표 자유배치라 출장보고서의 누가/언제/어디를 데이터로 못 쓴다. MCM은 `field_values`가 구조화돼 있어 AI 사전검토("같은 업체 출장 최근 3건은 평균 45만원인데 이번 건은 120만원")와 자연어 리포팅이 **정확한 근거를 갖고** 동작할 수 있다. 차별화 전략의 본체는 이 우위를 AI 레이어로 현금화하는 것.
3. **33명 자사 사용이 1차 고객**이므로, "결재 반려율", "결재 소요시간", "초과근무 위반 0건" 같은 정량 ROI를 자사 데이터로 먼저 측정·증명한다(보고서 설계 원칙 4).
4. 설계 원칙(보고서 §4)을 전 단계에 적용: **휴먼 인 더 루프**(AI는 초안·권고까지, 확정은 사람) · **모든 AI 판단에 근거+감사 로그**(`audit` 재사용) · **좁은 태스크부터** · **정량 ROI 측정**.

## 4. 단계 계획 (AX-P0 ~ AX-P5)

### AX-P0. 코어 마감 — 알림·참조/열람·결재선 프리셋 (기본기, 소형)

차별화 이전의 표준 기대치 완결. 기존 테이블(084)이 이미 있어 마이그레이션 부담이 거의 없다.

- **알림**: 이벤트 4종 — ①내 차례 도래(결재 요청) ②최종 승인 ③반려 ④대결 발생(위임자에게). 채널 = 이메일 SES 기본 + 알림톡 솔라피(§8 논점 ①). `lib/approval/notify.ts` 신설, `actOnDoc`/`submitDoc`/`activateOrder` 훅. 발송 실패가 결재 트랜잭션을 막지 않도록 커밋 후 비동기.
- **참조/열람**: 기안 화면에 참조자(결재 완료 시 통보)/열람자(진행 중에도 열람) 지정(조직도 픽커 재사용) → `approval_watchers` INSERT. 문서함에 "참조/열람" 탭 추가, `[docId]` 열람 권한에 watcher 포함.
- **나의 결재선 프리셋**: 기안 화면에서 현재 결재선+참조자 묶음을 이름 붙여 저장/불러오기(`approval_line_presets`). 다우 UX 차용.
- 산출: 마이그 불요(기존 테이블) 또는 알림 로그 테이블 1개(발송 이력·중복 방지).

### AX-P1. 지연 관리 — 리마인드·체류시간·병목 대시보드 (A-3③ 완결, 소형)

- **자동 리마인드**: 대기 상태 N시간(기본 24h, 정책 설정) 경과 시 결재자에게 재알림(1회/일 상한). 스케줄 배치(EventBridge→ECS RunTask, adt-ingest 패턴) 또는 접속 시 lazy 체크 — §8 논점 ②.
- **체류시간 데이터**: `approval_steps`에 `acted_at`은 있으나 **`activated_at`(pending 전환 시각)이 없음**(084 실측) → 컬럼 추가 마이그레이션 필요. 기존 pending 행은 `submitted_at`으로 백필.
- **병목 대시보드**(admin): 평균 결재 소요시간·단계별 체류 상위·결재자별 평균 처리시간·반려율 추이. ApexChart 재사용. **여기서 나온 수치가 이후 AI 단계의 ROI 베이스라인이 된다**(예: "AI 사전검토 도입 전 반려율 X%").
- 대결은 기구현이므로 이 단계로 A-3③이 완결됨.

### AX-P2. 결재자 AI 요약 (A-3②, 소형~중형) ★첫 AI 레이어

가장 좁고 확실한 태스크부터(보고서 원칙 3). 실패해도 원문이 있으므로 리스크 최소.

- **생성 시점**: 상신 시 1회 생성·저장(`approval_docs.ai_summary` jsonb) — 결재자 수만큼 중복 호출하지 않음. 재상신 시 재생성.
- **입력**: 양식 필드 정의(라벨) + `field_values` + **같은 양식의 과거 승인 문서 통계**(예: 같은 업체 최근 출장비 평균 — `field_values` 쿼리로 산출해 프롬프트에 주입). 구조화 데이터가 있어 환각 여지가 작다.
- **출력(구조화)**: 3줄 요약 · 핵심 수치(금액/기간/대상) · 전례 대비 비고("이 업체 최근 3건 평균 대비 +N%"). `llm-json.ts` 패턴.
- **표출**: 결재 대기 카드(홈)·모바일 `/m/approval` 카드·상세 모달 상단. "AI 요약" 배지 + 원문 폴백 항상 제공.
- **모델**: Haiku 기본(문서 추출 아키텍처와 동일 정책). 문서당 1회라 비용 미미.
- 감사: `audit` 액션 `approval_ai_summary` + 프롬프트/모델/응답 저장(근거 추적).

### AX-P3. 상신 전 AI 사전검토 (A-3①, 중형) ★반려율 감소 = 최대 ROI

**이원 구조**: 결정적 규칙 엔진(항상 실행, LLM 아님) + LLM 보조 검토(선택 실행). AI가 아니어도 잡을 수 있는 것은 규칙으로 잡는다 — 비용·신뢰 모두 유리.

- **규칙 레이어**(`lib/approval/precheck.ts`, 순수 함수):
  - 결재선: 자기 자신 포함/결재자 계정 미연결/대결 대상 안내.
  - 연차: 잔여 부족(기구현 배지의 차단 승격 여부는 §8 논점 ③), 촉진제 지정일과 충돌.
  - 초과근무: 주 잔여 가용시간 초과(AX-P4와 연동).
  - 금액 필드: 양식별 상한 정책(신설 테이블 `approval_form_policies` — 양식×필드×조건, admin 편집) 위반.
  - 첨부: 양식별 필수 첨부 정책.
- **LLM 레이어**(상신 직전 "AI 검토" — 자동 실행 여부는 §8 논점 ④):
  - 본문·필드 일관성(기간 역전 서술, 금액 불일치), 사규 위반 소지(leave_types·정책 테이블을 컨텍스트로).
  - **유사 과거 문서 제시**: 같은 양식의 승인/반려 문서를 pgvector(intel RAG 인프라 재사용)로 검색해 "참고: 유사 기안 2건(승인 1·반려 1, 반려 사유: …)" 표시. 반려 전례 학습이 반려율을 직접 낮춘다.
- **UX**: 상신 버튼 → 검토 결과 패널(차단 ⛔ / 경고 ⚠ / 참고 ℹ 3등급). 차단 외에는 "무시하고 상신" 가능(휴먼 인 더 루프 — 시스템이 상신을 막는 건 결정적 위반만).
- 측정: 사전검토 도입 전후 반려율(AX-P1 대시보드) — 세일즈 문구화.

### AX-P4. 52시간 컴플라이언스 연동 — 근태↔결재 결합 (A-1 완결, 중형)

ADT 산정(실측)과 초과근무신청서(계획)를 잇는다. **시프티·플렉스 대비 차별점 = 실측 기반 사전 통제**.

- **신청 시점 가용시간 표시**: 초과근무신청서 기안 화면에 해당 주(일요일 시작) 실측 누적 근로시간 + 기승인 초과근무 합 + 잔여 가용(52h−소정40h−기사용) 배지. 잔여 초과 신청은 AX-P3 규칙 레이어에서 경고/차단(§8 논점 ③).
- **사전 경고 배치**: 주중(예: 수·금) 시점에 현재 페이스로 52h 초과가 예상되는 직원+관리자에게 알림(AX-P0 채널 재사용). 12h 연장 한도 도달 임박·특별휴가 대상(12h 초과분) 발생도 함께.
- **신청↔실측 대사**: 관리자 화면(`/approval/attendance` 확장)에 "승인된 초과근무 vs 실측 초과근무" 주별 대사 뷰 — 무단 초과(신청 없이 실측)·미실행(신청했으나 실측 없음) 플래깅.
- **팀 단위 익명 과로 지표**(보고서 A-1 부수효과): 부서별 주당 평균 초과시간·심야근무 빈도 추이 카드(개인 식별 없음 — 윤리 가드).
- **컴플라이언스 증빙 관리**(2026-07-24 노무 리스크 검토로 추가 — §9-5 참조): 현행 "12h 초과분 특별휴가" 관행은 ①52h 초과 자체가 근기법 53조 위반(보상과 무관, 반의사불벌 아님) ②근로자대표 **서면합의(57조 보상휴가제) 없는 휴가 갈음은 수당 미지급(임금체불, 3년 소급)** 리스크 보유. 합법 경로 = 특별연장근로 인가(돌발상황·업무량 폭증, 연 90일) + 보상휴가 서면합의(가산율 1.5/2.0배 환산·미사용분 임금 정산·소급 불가). **회사 방침(확정): 특별휴가 정책 유지 + 서면합의 문서화·사내 제도화 + 노무사 상담 진행 예정.** 시스템은 이를 전제로 산정·증빙을 묶는다.
- 전제: ADT 엑셀 업로드 실증(현재 사용자 확인 대기)이 선행. 급여 금액 연동은 기존 계획대로 3차.

### AX-P5. 자연어 리포팅 v1 — "말로 물어보는 결재·근태" (B-1, 중형~대형)

구조적 우위의 본체. v1 스코프를 **결재·근태·연차**(이미 스키마를 우리가 설계한 도메인)로 좁힌다.

- **시맨틱 레이어**(`lib/ai/semantic-layer.ts`): 지표 사전(반려율·평균 소요시간·소진율·주당 초과시간 등 정의 고정) + 조회 가능 뷰 카탈로그(approval_docs/steps, attendance_week_summary, annual_leave_ledger + 양식별 field_values flatten). **Text-to-SQL 자유 생성이 아니라, LLM은 "지표+차원+필터" 선택만 하고 SQL은 카탈로그가 조립**(정확도·보안 모두 유리).
- **UX**: 질문 입력 → 차트(ApexChart)+표+한 줄 해설. 대시보드 어딘가의 패널로 시작(독립 챗봇 아님).
- **권한**: RBAC 스코프 필수 — v1은 admin(경영진) 한정 시작(§8 논점 ⑤). 개인 급여·개인 식별 과로 지표는 제외.
- 확장(후속): 주간 자동 브리핑("지난주 결재 처리 현황·지출 추이·근태 이상 징후" — 보고서 B-1 후단), 지출결의 트랙 합류 시 경비 도메인 추가.

### 별도 트랙 / 후순위 (본 블루프린트 범위 밖, 접점만 정의)

- **지출결의 전수 AI 감사·예외 결재(A-2)**: 바로빌 계약 후 카드 지출결의 트랙에서. 단 카드 승인건→지출결의서 초안 생성 시 **AX-P3 사전검토·AX-P2 요약을 그대로 태운다**(같은 결재 코어이므로 자동 상속). 이상 탐지(중복·분할·심야) 규칙도 precheck 규칙 레이어의 확장으로 설계.
- **사규 Q&A 봇(B-3)**: pgvector+사규 PDF(경조금 규정 등 이미 확보) RAG. "경조휴가 며칠?"→답변+**휴가신청 기안 초안 생성 버튼**(휴먼 인 더 루프). AX-P3의 LLM 레이어와 사규 컨텍스트를 공유하므로 그 이후가 적기.
- **AI 브리핑 홈(B-5)**: 홈 위젯 확장 — "내가 결재할 문서 N건(각 AI 요약)"은 AX-P2 저장 요약을 그대로 위젯에 노출하면 되므로 비용 0에 가깝다. AX-P2 직후 소형 작업으로 편입 가능.
- **메신저 내 결재 종결(A-4)**: 메신저 자체가 로드맵 후반이므로 보류. 단 알림톡(AX-P0)의 버튼 링크→모바일 결재함이 그 전 단계 대체재.

## 8. 논점 — 전부 확정 (2026-07-24)

1. **알림 채널**: **이메일 + 알림톡 병행**. 이메일만으로는 미확인("몰랐다") 우려. 알림톡은 솔라피(`kakao-solapi.ts`) 재사용, 이벤트×채널 토글은 관리 설정으로. ⚠ 알림톡 템플릿 사전 심사 등록(솔라피 콘솔)·직원 수신번호(`employee_profiles.mobile_phone`) 정비는 사용자 작업.
2. **리마인드**: **스케줄 배치**(EventBridge→ECS RunTask, adt-ingest 패턴).
3. **사전검토 차단 강도**: **기본 경고, 양식 정책(`approval_form_policies`)에서 항목별 차단 승격 선택 가능**.
4. **LLM 사전검토**: **규칙 레이어는 항상 자동, LLM은 "AI 검토" 버튼 수동**(비용 절감). 사용률 보고 자동 전환 여부는 추후.
5. **자연어 리포팅 권한**: **관리자·임원·부서장·일반 직원까지 부여 가능하되, 부여 여부는 관리자가 결정**(RBAC 권한키 신설, 기본 미부여). 직급별 **데이터 액세스 스코프**(볼 수 있는 데이터 범위 차등)는 후속 기능으로 예정 — v1은 권한 보유자에게 동일 범위.
6. **AI 요약 생성 시점**: **상신 시 자동 생성·저장**(재상신 시 재생성).
7. **순서**: **P0 → P1 → P2 → P3 → P4 → P5 확정**.

### 9-5. AX-P4 — 52시간 근태↔결재 연동

**마이그 불요 예상**(attendance_week_summary·approval_docs 기존 활용, 필요 시 경고 로그만 091 notify_log 재사용).

**코드**
- `/api/approval/attendance/week-usage`: 신청 기간이 속한 주(일요일 시작, `lib/adt/overtime.ts` 주차 로직 재사용)의 실측 누적 + 기승인 초과근무신청 합 + 잔여 가용(52−40−기사용) 반환.
- `ApprovalDraftBoard` 초과근무신청서: 기간 입력 시 잔여 가용 배지(연차 배지 패턴). precheck `overtime_limit` 규칙 연계(기본 warn, 정책에서 block 승격 — §8-3).
- 사전 경고: `approval-remind` 배치에 통합(인프라 추가 없음) — 주중 화·목 게이트, 현재 페이스 52h 초과 예상·연장 12h 임박·12h 초과분(특별휴가 대상) 발생 → 본인+관리자(approval.manage) 알림, dedup_key 주 단위.
- 대사 뷰: `AttendanceBoard`에 "신청 대비 실측" 탭 — 주별 승인 초과근무 vs 실측 초과, 무단 초과(실측만)·미실행(신청만) 플래그.
- 팀 익명 지표: `/approval/insights`에 부서별 주당 평균 초과·심야 빈도 추이 카드(개인 미식별).
- **컴플라이언스 증빙 연동**(§4 AX-P4 보정 사항의 구현):
  - 특별휴가 산정에 **가산율 환산 옵션**(연장 1h=1.5h·야간연장 2.0h — `overtime_policies`(089)에 환산 배수 정책 추가, 기본은 사규 확정값. 현행 1:1이면 서면합의 문안과 일치시킬 것).
  - **특별연장근로 인가 건 관리**: 인가번호·사유(돌발상황/업무량 폭증)·대상 기간·근로자 동의·건강보호조치·서류 첨부(S3)를 등록하고 해당 주차 실측과 연결 — 52h 초과 주가 인가 범위 내인지 대사 뷰에 표시(연 90일 사용량 카운터 포함).
  - **서면합의·동의서 보관**: 보상휴가제 서면합의서·개별 동의서를 문서로 등록(유효기간·서명일) — 초과근무 산정 화면에서 "합의 유효" 상태 배지.
  - **특별휴가(보상휴가) 정산 추적**: 부여분·사용분·미사용 잔여를 추적(보상휴가는 촉진 불가·미사용분 임금 정산 의무) — 연차 대장과 별도 원장.
  - 세부 스키마·마이그레이션은 **노무사 상담 결과(서면합의 문안·환산 배수 확정) 이후** 확정 — P4 착수 전 사용자 회신 필요 항목.
- **전제**: ADT 엑셀 업로드 실증 완료(현재 사용자 확인 대기 중) + 서면합의 문서화(노무사 상담) 진행.

### 9-7. 공통·순서
