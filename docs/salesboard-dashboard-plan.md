## 2. 이번 요청 범위(1단계) — 목록 검색성·열 정리

### 2-1. 목록 왼쪽 태그 필터 패널
- 영업건 리스트 카드 왼쪽에 세로 태그 패널(폭 약 150px)을 둔다. 상단 필터 줄(제목·사업장 검색, 담당, 연도)은 그대로 둔다.
- **지역권** 태그: 공공입찰 화면과 같은 7권 — 수도권 / 강원권 / 충청권 / 경북권 / 경남권 / 전라권 / 제주권 (+ 시도 없는 건은 "미상"). 판정은 `facilities.region_sido` → 시도 약칭(`lib/catalog/regions.ts`의 `shortSido` 재사용) → 7권 매핑. 매핑 상수와 함수는 클라이언트에서 import 가능한 `lib/sales/regions.ts`에 둔다(`lib/bid/bid-queries.ts`는 DB 모듈을 import하므로 클라이언트에서 쓸 수 없음).
- **업종분류** 태그: `sales_projects.service_category` 4종 — 통합허가 / 화관법 / ESG·탄소중립 / 기타(미지정은 "미분류").
- 동작: 태그 다중 선택, 같은 그룹 안은 OR, 그룹 사이는 AND. 선택된 태그는 채움색, 그룹 머리에 선택 수 표시, 상단 "초기화"가 태그도 함께 비운다. 각 태그에 현재 조건의 건수를 작게 표시한다.
- 데이터: `PROJECT_SELECT`에 `f.region_sido`를 추가해 `SalesProject.regionSido`로 내려주고, 지역권은 클라이언트에서 파생한다. 필터는 현행과 같이 클라이언트 측(전건 fetch 후 필터)으로 유지한다.
- 많아질 때 대비: 목록에 공용 `useClientPaging`(`components/ui/PaginationControls.tsx`) 쪽 나눔을 적용한다(행 밀도는 10-21 규칙과 동일). 영업건이 수천 건 규모가 되면 `/api/sales/projects`에 `regionGroup`·`serviceCategory` 서버 필터를 추가하는 것을 후속으로 둔다.

### 2-2. 검색란 너비
- "제목·사업장 검색" 입력을 180px → 300px로 넓힌다(좁은 화면에서는 줄 바꿈).

### 2-4. 매뉴얼 동기화(같은 커밋)

## 3. 2단계 — 상단 KPI 띠(2026-10-26 구현)
- 위치: 페이지 헤더 아래, 탭 패널·목록 위에 1줄 5칸(칸 높이 약 74px, `xl` 미만은 3열·2열로 wrap).
- 지표(모두 현재 목록 응답과 탭 패널 응답에서 파생, 새 API 없음). 목록 필터(검색·담당·연도·태그)와 무관하게 보이는 영업건 전체 기준, 날짜는 KST:
  1. 진행 중 영업건 — status가 closed가 아니고 단계가 수주·실주가 아닌 건. 보조 줄 = 단계별 내역(보류는 있을 때만)
  2. 이번 달 신규 — opened_at(없으면 created_at) 당월. 보조 줄 = 지난달 건수
  3. 투찰 예정(14일) — 탭 패널 upcoming-bids와 같은 모집단. 보조 줄 = 가장 가까운 D-day
  4. 올해 수주 / 실주 — 결과 스케쥴 날짜(`SalesProject.outcomeAt`, 서버 attachStepTypes에서 채움)가 올해인 수주·실주. 결과 스케쥴 없는 옛 건은 closed_at → opened_at로 판정
  5. 올해 수주율 — 수주 ÷ (수주+실주), 결과 없으면 —
- 칸 클릭 = 목록 필터(하나만, 다시 누르면 해제, 검색란 옆에 이름 칩 표시). 수주/실주 칸은 두 값을 각각 누른다. 투찰 예정 칸은 필터 대신 왼쪽 투찰 임박 탭을 연다.
- 숫자는 텍스트 색, 아이콘만 칸별 색. 상태색(수주 녹색·실주 빨강)은 라벨과 함께. 선택된 칸은 경계만 primary.

## 7. 후속(2026-10-29) — 세분류 줄·수천 건 대비
- **W5 세분류 줄**: 상위 3개 + `truncate`(나머지는 title·툴팁에만)였다. 분류당 세분류가 최대 5개라 **전부** 보이고, 항목(이름+건수) 단위로 줄을 바꾼다(`whitespace-nowrap` + `flex-wrap`). 이름 축약 없음. 1366 폭(레일 76px)에서 통합허가 5개 = 2줄, 1920 폭은 1줄.
- **목록 서버 필터**: `/api/sales/projects` 에 `limit` 을 주면 검색·담당·연도·지역권·업종분류·KPI·도달 단계 필터와 쪽 나눔을 서버가 하고 `{projects(한 쪽), total, offset, visibleTotal, regionCounts, categoryCounts}` 를 돌려준다. `limit` 없으면 예전 응답(`{projects}` 전건) 그대로 — 연결 선택기·모바일이 쓴다.
- **집계 API** `/api/sales/board-stats`: KPI 띠·W4~W7 숫자. 판정은 `lib/sales/board.ts`(예전 SalesBoard·SalesInsights 판정을 그대로 옮김)라 목록·집계·화면이 같은 식을 쓴다. 가시성 scope 는 `lib/sales/visible-projects.ts` 로 모아 두 API가 같이 쓴다.
- **SQL 로 옮기지 않은 이유**: 단계(`computeStage`)·도달 단계·`outcomeAt`·최종 투찰가가 KST 현재 시각과 스케쥴 날짜 비교로 정해져(JS) SQL 로 옮기면 경계 불일치 위험이 크다. 서버 JS 로 판정해도 5,014건·스케쥴 20,019건에서 필터 ~10ms·집계 ~8ms라 충분하다. 지역권도 `salesRegionGroupId` 를 그대로 써 클라이언트와 결과가 같다.
- **측정(일회용 PG, 5,014건)**: 예전 목록 응답 3.30MB → 쪽 50건 32.9KB + 집계 1.4KB. `attachStepTypes` 는 `IN ($1…$n)`(영업건 수만큼 바인드 파라미터, PG 한도 65,535) → `= ANY($1::text[])` 1개.
- **대조**: 예전 클라이언트 판정과 새 서버 판정을 14건 시드·5,014건 합성 데이터에서 필터 조합 57,600개씩 비교해 불일치 0. 단위 테스트 `npm run test:sales-board`.
- **남은 것**: `listPendingProgressReports` 는 영업건마다 상세·스케쥴을 따로 읽는다(N+1). 집계 API가 경과 보고 탭과 같은 모집단을 쓰려고 이를 한 번 더 부르므로, 미보고 영업건이 많아지면 먼저 이 쿼리를 한 번에 읽도록 고친다. `listUpcomingBids` 는 같은 사업장의 영업건마다 발주 한 줄씩 나온다(합성 데이터에서 226KB).

## 8. 실데이터 점검 후속(2026-10-29) — 지역권·단계 판정·결과 기준·브리핑 신선도
스테이징 읽기 전용 점검(영업건 1건, 사업장 2,073곳)에서 나온 결함을 고쳤다.
- **지역권 주소 대체**: `facilities.region_sido` 가 비면 `site_address` 맨 앞의 시도(`shortSido`, 공백 무시)로 읽는다(`lib/sales/queries.ts` `projectSido`). `광주시 …`는 경기 광주시라 제외. 시도 빈 값이 사업장 328/2,073(15.8%)·계약 거래처 223/359(62%)였고, 주소 맨 앞에 시도가 있는 곳은 236곳. 시군구로 시작(11)·회사명이 주소칸(42)·주소 없음(39)은 여전히 미상.
