# 외부 메일 프로그램(POP3/IMAP/SMTP) 연동 — 구성안 (보류)

2026-10-21 사용자 결정(F-13 잔여): **이번에는 구축하지 않는다.** 메일 설정 화면의 "준비 중" 안내는 숨겼고, 착수할 때 이 문서에서 출발한다.

## 1. 현재 구조와 걸림돌

- 수신: SES Receipt Rule → S3 원문 + SNS→SQS → next tick 이 파싱해 `mail_messages`·첨부·폴더에 적재(`lib/mail/inbound.ts`, `docs/company-email-blueprint.md` §4-P2).
- 발신: 웹 쓰기 창 → SES `SendRawEmail`.
- 메일함의 원본은 **DB(`mail_messages`·`mail_folders`·첨부 S3)** 이다. 표준 메일 서버(Dovecot 등)의 저장소(Maildir)가 따로 없으므로, 아웃룩이 붙으려면 DB를 IMAP 으로 보여 주는 계층이 필요하다.
- 직원 인증은 앱 로그인(next-auth)뿐이다. IMAP/SMTP 는 아이디·비밀번호 방식이라 **메일 전용 앱 비밀번호**가 별도로 필요하다(앱 로그인 비밀번호를 프로토콜에 그대로 쓰지 않는다).

## 2. 선택지

| 안 | 구성 | 장점 | 부담 |
|---|---|---|---|
| A. IMAP 게이트웨이(권장) | ECS 상시 서비스 1개(Node IMAP 서버 라이브러리) + NLB(TCP 993/465) → DB·S3 를 IMAP 폴더·메시지로 노출, SMTP 제출은 SES 로 중계 | 웹·모바일과 메일함이 하나로 유지 | IMAP 상태(UID·플래그·IDLE) 구현·검증량이 큼, 상시 비용 |
| B. 표준 메일 서버 병행 | Dovecot+Postfix 컨테이너, SES 수신분을 Maildir 에도 기록 | 프로토콜 완성도 | 메일함 이중화(읽음·삭제 동기화 문제), 운영 난도 |
| C. 외부 호스팅 이전 | WorkMail·Google Workspace 등 | 구축 없음 | 앱 메일 기능(수신확인·결재 연계·용량 배분)과 분리, 계정당 비용 |

## 3. A안 착수 시 필요한 것

1. 메일 전용 앱 비밀번호(계정별 발급·폐기, 해시 저장) — 새 마이그레이션.
2. 게이트웨이 서비스: TLS 인증서(ACM 은 NLB TLS 종료 가능), 접속 기록(개인정보 접속기록 규칙과 같은 수준), 로그인 실패 잠금.
3. UID 안정성: `mail_messages` 에 폴더별 단조 증가 UID·UIDVALIDITY 컬럼.
4. SMTP 제출: 인증된 발신자=본인 주소만 허용(위조 방지), SES 발신 한도 공유.
5. 보안 검토: 포트 개방(993/465), 무차별 대입 대응, 퇴사자 즉시 차단.
6. 비용: NLB + Fargate 상시 1태스크(스테이징 기준 월 수만 원대) — 착수 전 견적.

## 4. 당장의 안내

- 매뉴얼 메일 기사는 웹메일·모바일 앱 사용만 안내한다(외부 프로그램 언급 없음).
- 기존 메일을 옮겨 오는 일은 [메일 가져오기](mail-import-blueprint.md)(아마란스 백업 ZIP·.eml, IMAP 가져오기)로 한다 — 이것은 바깥 서버에서 **가져오는** 기능이라 이 문서의 범위가 아니다.
