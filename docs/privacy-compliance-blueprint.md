## 3. 설계 원칙 (전 모듈 공통 — 신규 기능 개발 시 준수)

1. **실시간 훅 금지**: 전송 파이프라인(SMTP·웹소켓·메시지 발송 경로)에 inline 감시 로직을 넣지 않는다. 스캔이 필요하면 저장 완료 후 비동기 배치.
2. **본인 스코프 기본**: 통신 데이터(메일 본문·메신저 메시지)는 본인/방 멤버 스코프를 유지한다. 관리자용 전사 조회 API 를 만들지 않는다.
3. **메타와 본문의 2단 분리**: 관리 기능(파일함 등)은 메타데이터+파일 단위까지만. 메일 본문·대화 내용 접근 기능은 break-glass(§4 P2) 없이 만들지 않는다.
4. **열람도 기록**: 타인 데이터에 닿는 모든 조회·열람·삭제는 `audit_log` 기록을 동반한다(파일함은 적용 완료 — `file_library_open`/`file_library_delete`).
5. **자동 결정에 사람 개입**: 자동 탐지(향후 DLP 류)가 계정 정지·인사 조치로 직결되는 설계 금지(개보법 §37조의2).
6. **사후 통지**: 표적 조사 종료 후 대상자 통지 절차를 둔다(§4 P2 워크플로에 내장).
7. **퇴직자**: 계정 잠금(즉시)과 데이터 열람(break-glass)을 분리한다.
8. **문서 우선**: 모니터링 성격의 신규 기능은 취업규칙·처리방침·서약서 문안 반영 후 배포한다.
