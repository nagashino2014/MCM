# 양식별 고정 결재선 계획 (2026-11-03)

상태: **FL-1~FL-3 구현·리허설 통과(2026-11-03), 미커밋·335 미적용·미배포** · 상위 문서: [e-approval-blueprint.md](e-approval-blueprint.md), [e-approval-delegation-blueprint.md](e-approval-delegation-blueprint.md)

## 1. 배경

전자결재 양식은 지금 기안자가 결재선을 자유롭게 지정한다. 다우오피스를 쓸 때처럼 결재자를 빠뜨리거나 순서를 뒤섞는 일이 잦아,
양식마다 결재선을 고정한다. 사람이 바뀌어도 관리자가 화면에서 고칠 수 있게 규칙은 데이터로 둔다.

## 3. 설계

### 3-1. 데이터 (마이그레이션 335, 멱등)

- `approval_line_templates` — 양식별 고정 결재선 1행.
  - `form_id` PK · `steps jsonb` = `[{ "role": "dept_head" | "exec" | "ceo" | "manager", "proxyUserIds": [...] }]`
  - `enforce_when jsonb` — `null` 이면 항상 강제. 계약서·견적서는 `{ "field": "doc_stage", "equals": "final", "whenMissing": "enforce" }`
  - `enabled` · `updated_by` · `updated_at`
- `approval_line_role_users` — 역할별 담당자.
  - `(role, dept_id)` PK. `dept_id='*'` 는 기본값, 부서 행은 기본값을 덮어쓴다.
  - 시드: `ceo/*` 이유억, `exec/*` 정득종, `exec/carbon-neutral-lab` 신총식, `manager/*` 이재영.
- `approval_steps.line_role text`(NULL 허용) — 단계가 어떤 역할로 들어갔는지 기록한다. 화면에 "부서장·임원" 같은 표기를 하는 데 쓴다.
- 301 처럼 외래키는 두지 않는다. 시드는 `ON CONFLICT DO NOTHING` 으로 넣어, 운영자가 바꾼 값을 재실행해도 보존한다.

### 3-2. 해석 규칙 (`lib/approval/fixed-line.ts`, 순수 함수 + DB 로더)

1. 기안 부서는 기안자의 주 소속(`employee_profiles.dept_id`)이다. 겸직 부서로 기안하는 기능은 없으므로 주 소속만 본다.
2. 역할은 다음 순서로 푼다.
   - 부서장: 기안 부서에서 오늘 유효한 head 보직. 0명이거나 2명 이상이면 상신을 막고 이유를 보여 준다.
   - 임원: 부서 행이 있으면 그 행, 없으면 `*` 행.
   - 대표이사: `ceo/*` 행.
   - 관리자: `manager/*` 행.
3. 기안자의 지위는 대표이사 > 임원 > 부서장 > 직원 순이다. 기안자 지위가 같거나 높은 사다리 역할(부서장·임원·대표이사)의 단계는 뺀다.
4. 단계를 빼서 결재선이 비면, 기안자보다 한 칸 위의 사다리 역할을 넣는다. 예: 부서장이 쓴 휴가신청서는 임원에게 간다.
5. 연달아 같은 사람이 들어가면 한 번만 남긴다. 예: 연구소 직원의 계약서는 신총식 → 이유억이다.
6. 결재선을 하나라도 풀지 못하면(공석·매핑 누락·퇴사·계정 없음) 상신을 막고 이유를 보여 준다.

### 3-3. 강제 지점

- **저장(saveDoc)**: 강제 대상 양식이면 요청한 결재선 대신 해석한 결재선을 쓴다.
  - 웹·모바일·서버 자동 기안 모두 여기를 지나므로 경로가 하나로 모인다.
  - 해석이 실패해도 임시저장은 되고, 결재선은 비워 둔다.
- **상신(POST submit·submitDoc)**: 상신 시점에 다시 해석한다.
  - 요청 결재선이 비어 있지 않은데 해석 결과와 다르면 400 으로 거부한다. 메시지에 정해진 결재선을 함께 보여 준다.
  - 해석이 실패하면 이유를 보여 주고 거부한다.
  - 반려 후 재상신할 때도 다시 해석하므로, 그사이 바뀐 보직이 반영된다.
- 이미 진행 중인 문서는 바꾸지 않는다. 스테이징 기준 진행 중 문서는 휴가신청서 1건이다.
- 참조·열람자는 지금처럼 자유롭게 지정한다.

### 3-4. 지정 대결자 (관리자 양식 4종 → 이도희)

관리자 양식은 단계가 이재영 1명뿐이어서 그 단계가 곧 최종 순번이다. 현재 D-2 규칙에서는 이재영이 부재여도 대결이 일어나지 않는다.
고정 결재선 단계에 `proxyUserIds` 를 둔 경우에만 D-2 의 예외로 대결을 허용한다(아래 결정 Q1).

### 3-5. 화면

- 결재선 카드를 공용 컴포넌트 `FixedLineCard` 와 훅 `useFixedLine(formId, values)` 로 만든다.
  - 고정 양식에서는 행 선택·삭제·결재자 추가·결재선 프리셋을 숨기고 잠긴 결재선을 보여 준다.
  - 각 단계에 역할(부서장·임원·대표이사·관리자)과 "대결: 이도희"를 표기한다.
  - 해석에 실패하면 빨간 안내를 띄우고 [상신]을 막는다.
  - 다섯 작성 화면에는 이 컴포넌트만 끼운다. 기존 카드 위치·폭(340px)은 그대로 둔다.
- 관리 화면 `/approval/fixed-lines`(결재 운영 메뉴, `approval.manage`):
  - 양식별 단계·강제 조건·지정 대결자 편집
  - 역할 담당자(대표이사·관리자·부서별 임원) 편집
  - 부서 × 양식 해석 미리보기 표(공석은 빨간 표시)
- 매뉴얼: 결재 기사(`articles/approval.ts`·`approval-ops.ts`)와 `approval.draft-line` 도움말을 고치고 changelog 에 한 줄을 남긴다.

### 3-6. 계약서 버전 관리 세션과의 접점

- 계약서·견적서는 `enforce_when = { field: "doc_stage", equals: "final", whenMissing: "enforce" }` 로 둔다.
  - 버전 관리 세션이 `field_values.doc_stage` 에 `"draft"` 를 넣은 문서만 강제에서 빠진다.
  - 값이 없으면 최종안으로 보고 강제한다.
- 필드 이름과 값은 관리 화면에서 바꿀 수 있다. 저쪽 세션이 다른 키를 쓰면 마이그레이션 없이 데이터만 고친다.
- 겹치는 파일: `QuoteBoard.tsx`·`AgreementBoard.tsx`·`ApprovalLetterBoard.tsx`.
  - 버전 관리 세션 worktree 는 지금 `ApprovalLetterBoard.tsx` 에 4줄(수신처 도움말 정렬)을 고친 상태다.
  - 이쪽은 결재선 카드 블록만 교체하므로 충돌 범위는 작다. 먼저 머지되는 쪽을 다른 쪽이 받아 맞춘다.

- 통합(사본, 자격증명 차단):
  - 저장할 때 요청 결재선을 규칙 결과로 바꾼다.
  - 변조한 결재선은 상신할 때 거부한다.
  - 부서장이 2명이면 상신을 막는다.
  - 이재영이 부재면 지출 결의서를 이도희가 대결한다. 처리 유형은 proxy 로 남고 문서가 승인된다.
  - 상신 뒤 부재를 등록하면 재라우팅으로 이도희에게 넘어간다.
  - 결근사유서는 지정 대결자가 없어 이재영에게 남는다.
  - 계약서 초안은 강제하지 않는다.
  - 퇴직원은 자유 지정이다.
- 화면: 일회용 사본에 붙인 로컬 앱으로 다음을 확인했다.
  - 기안(휴가신청서)의 잠긴 결재선: 라이트·다크
  - 고정 결재선 관리 화면: 다크·라이트, 편집 패널, 미리보기 35행
  - 새 API 응답은 모두 200 이었다.
