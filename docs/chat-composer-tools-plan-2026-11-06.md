# 대화방 입력창 도구 권장안 (2026-11-06)

대화방 메시지 입력창에 어떤 기능을 붙일지 정하기 위한 조사 결과와 권장안이다. 코드는 아직 고치지 않았다.
참고 화면은 다우오피스 메신저 입력창(더하기·멘션·글자 서식·이모티콘·예약 발송·파일 첨부·화면 캡처·AI 요약)이다.

웹 앱(`frontend/app`)에는 메신저 화면이 없다. 메신저는 모바일 앱 코드 하나이고 위젯·PWA 는 그 웹 번들(`frontend/public/m-app`)을 쓴다. 따라서 입력창을 한 번 고치면 세 곳에 모두 반영된다.

## 2. 후보 평가

환경 표기: 앱 = 모바일 네이티브, 위젯 = 데스크탑 위젯, PWA = 브라우저 앱. ○ 가능, △ 조건부, ✕ 불가.

주의할 점
- 사진: iOS 시스템 사진 선택기가 결과를 잃는 문제로 명함 화면은 자체 카메라를 쓰고 iOS 에서 앨범 버튼을 숨긴다(`card.tsx:75`, `:343`). 같은 제약이 대화방에도 적용될 수 있어 실기 확인이 필요하다.
- 멘션: 1대1 방에서는 의미가 없어 그룹방에서만 켠다. 마이그레이션 없이 하면 "나를 부른 메시지만 모아 보기"는 못 한다(필요하면 후속으로 열 추가).
- Enter 전송: 한글 조합 중 Enter 가 글자 확정과 겹치지 않게 처리해야 한다. 휴대폰 화면 키보드에서는 지금처럼 줄바꿈으로 둔다.

주의할 점
- AI: 대화 내용이 외부 AI 서비스로 전송된다. 사용자가 누를 때만, 본인이 멤버인 방만 처리하도록 하고 비용은 기존 예산 한도를 따른다. 요약은 "읽는" 기능이라 입력창이 아니라 방 상단 메뉴(⋯)에 두는 편이 맞다.
- 공유 카드: 받는 사람에게 열람 권한이 없으면 카드는 보이되 열 때 각 화면의 권한 안내가 나온다. 일정·설문·메일은 앱 내 이동 경로가 아직 없어 1차 대상에서 뺀다.

### 입력창 밖이지만 함께 볼 것

- 반응(공감)·내가 보낸 메시지 삭제: 참고 화면처럼 "넵 알겠습니다"가 반복되는 대화를 줄인다. 삭제는 열이 이미 있어 API 만 추가하면 되고, 반응은 새 표가 필요하다.
- 위젯에서 답장·할 일로 만들기: 지금은 메시지를 길게 눌러야 메뉴가 나와 마우스로는 찾기 어렵다. 마우스를 올리면 나오는 작은 버튼이 필요하다.

## 3. 배치안

원칙: 항상 보이는 버튼은 지금보다 하나만 늘린다. 나머지는 더하기 메뉴 안에 둔다.

```
[＋] [📎] [😊] [ 메시지를 입력하세요            ] [전송]
```

- 항상 보임: 더하기(신규), 파일 첨부(유지), 이모티콘(유지), 전송(유지)
- 버튼 없이 동작: `@` 를 치면 멤버 후보가 뜬다(그룹방). Enter 전송. 붙여넣기·끌어다 놓기(기존)
- 더하기 메뉴(아이콘 타일 3열): 사진 촬영, 앨범(앱에서만 보임), 문서 공유, 문서함, 회의 잡기, 문장 다듬기 — 고른 기능만 넣는다
- 방 상단 메뉴(⋯): AI 대화 요약

## 4. 권장 묶음

- 묶음 가 (권장): Enter 전송 + 더하기 메뉴 + 사진 촬영·앨범 + 멘션 + 여러 파일 첨부. 마이그레이션 없음, API 는 멘션 알림만.
- 묶음 나: 사내 기록 공유 카드 + 문서함 첨부. API 변경, 마이그레이션 없음.
- 묶음 다: AI 대화 요약 + 문장 다듬기. API 신규, 마이그레이션 없음.
- 보류 항목 중 꼭 필요한 것이 있으면 따로 지정.

## 5. 구현 전 확인 사항

- 다른 세션이 같은 대화방 파일(`[roomId].tsx`, `(tabs)/chat.tsx`, `platform.ts`)의 모서리·선택 색·새 대화 창을 고치는 중이다. 2026-11-06 확인 시점에 그 변경은 원격에 올라와 있지 않았다. 그 변경이 main 에 들어온 뒤 착수해야 충돌이 없다.
- 마이그레이션이 필요해지면 번호는 341 부터다(원격 전 브랜치 최대 340, 2026-11-06 확인).
- 위젯·PWA 반영은 웹 번들 재생성(`npm run export:web`)과 next 배포, 앱 반영은 OTA 발행이 필요하다. 사진 촬영 권한 문구가 앱 설정에 이미 있는지는 구현 때 확인한다.

## 6. 결정과 구현 결과 (2026-11-06)

사용자 결정: 묶음 가와 묶음 나를 구현한다. 묶음 다(AI)와 보류 항목은 하지 않는다.

구현한 것
- Enter 전송(PC), 더하기 메뉴, 사진 촬영·앨범(앱), 멘션과 멘션 알림, 여러 파일 첨부(10개), 문서 공유 카드, 개인 문서함 첨부.
- 마이그레이션은 없다. 서버 변경은 메시지 전송 API(멘션 알림, 카드 입력, 문서함 파일 입력)와 알림 종류 `chat.mention` 추가다.

계획과 달라진 점
- 문서 공유 카드의 종류는 결재 문서·할 일·사업장이다. 계약은 앱에 상세 화면이 없어 뺐다.
- 카드 제목은 보낸 사람이 자기 권한으로 조회한 목록에서 고른 글자를 그대로 저장한다(할 일 연결과 같은 방식). 서버는 종류와 식별자 형식을 검사하고 이동 경로를 직접 만든다. 서버가 문서 제목을 다시 조회하지는 않는다.
- 사진 촬영은 명함·영수증 화면과 같은 자체 카메라를 쓴다. 앨범은 같은 이유(iOS 사진 선택기 문제)로 안드로이드에서만 보인다.
- 멘션 알림 대상은 서버가 본문의 `@이름`을 방 멤버 이름과 맞춰 정한다. 앱이 대상을 따로 보내지 않는다.

확인하지 못한 것
- 휴대폰 실기(사진 촬영·앨범·멘션 푸시 수신), 실제 한글 입력기에서의 Enter 전송, 실제 서버·DB 에서의 멘션 알림과 문서함 파일 복제.
