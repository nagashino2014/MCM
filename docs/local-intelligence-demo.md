# RAG · 영업 발굴 로컬 실증

접속: **http://127.0.0.1:4174/sales/rag?tab=scheduled**

실제 모드는 기존 수집 DB의 공개 정보를 로컬 DB로 복사하고, 실제 Anthropic API로 정기 브리핑을 만든다. 관심 분야·영업 연결·후속 활동·보고서·사내 수신함은 로컬에 저장된다. 로그인은 가상 검토자 `u1`로 고정되어 있으며 운영 MCM 전체 메뉴를 실행하는 환경은 아니다.

**최신 검증 결과(2026-10-31):** 원자료 31건을 정정·검토한 뒤 실제 AI로 새 보고서를 발행했다. 고정 근거 25개에서 출처 10개를 인용해 핵심 동향 5개·투자 항목 4개·시사점 6개로 정리했으며, 수집 자료 범위 내 독립 내용 검토를 통과했다. 아래 ‘실제 생성·화면 검증 결과’에서 최신 보고서와 검증 한계를 확인한다.

## 실제 모드 시작

작업본 루트에서 실행한다. PostgreSQL 17, frontend 의존성, 원본 DB 연결에 필요한 AWS CLI·Session Manager Plugin 및 AWS 로그인이 준비되어 있어야 한다.

```powershell
.\scripts\start-local-intelligence-demo.ps1 -Real
```

기본 설정 파일은 `C:/CodingProject/MCM/frontend/.env.local`이다. 원본 DB 접속 정보, Anthropic API 키, 공식 정보원 인증정보 암호화에 필요한 `AUTH_SECRET`만 선택해 메모리로 읽으며, 파일 전체를 실행하거나 비밀값을 문서·로그·새 설정 파일에 복제하지 않는다. 다른 파일을 사용하려면 다음과 같이 지정한다.

```powershell
.\scripts\start-local-intelligence-demo.ps1 -Real -SourceEnvFile "C:/path/to/frontend/.env.local"
```

시작 스크립트는 `scripts/start-intelligence-source-tunnel.ps1`을 먼저 실행한다. 원본 DB 연결은 로컬 루프백 주소의 `15432` 포트만 허용하며, 기존 연결을 재사용하거나 AWS SSM 터널을 숨김 창으로 연다. 직접 원격 DB 주소를 지정하면 거부한다. 별도 준비가 필요할 때 이 도우미를 직접 실행할 수 있다.

서버는 숨김 창으로 시작한다. 동일 모드가 이미 실행 중이면 기존 주소를 반환하며, 다른 모드가 실행 중이면 먼저 종료하라는 안내를 표시한다. 기동 시 원본 자료를 갱신하고 기존 로컬 입력은 보존한다.

원본 연결을 준비할 수 없을 때는 이미 가져온 실제 자료로 이어서 검토할 수 있다.

```powershell
.\scripts\start-local-intelligence-demo.ps1 -Real -UseStoredData
```

이 모드는 원본 DB 갱신을 생략하며 화면에 보존된 실제 자료를 사용 중임을 표시한다. AI 생성에는 여전히 실제 API와 비용이 적용된다. 자료의 최신성은 마지막 가져오기 시각을 기준으로 판단하고, 갱신하려면 원본 연결을 복구한다.

## 데이터와 비용 범위

원본 DB 연결은 기본 설정과 실제 트랜잭션 모두 **READ ONLY**로 고정하고 읽기 전용 여부를 확인한다. 복사 범위는 최근 **180일, 최대 2,000건**이다. 뉴스 이외의 자료를 우선 선택하고 남은 자리를 최신 뉴스로 채운다. 원본 영업건·계약·직원·고객 연락처 전체를 복사하지 않으며, 화면에서 새로 만든 영업건과 활동도 원본 DB에 반영하지 않는다.

2026-10-30에 확인한 복사 결과는 다음과 같다. 전체 5,678건 중 선택한 2,000건이므로 시장 전체나 전체 뉴스의 완전한 집계로 해석하지 않는다.

| 정보원 | 180일 범위의 원본 건수 | 로컬로 복사한 건수 |
| --- | ---: | ---: |
| DART | 878 | 878 |
| EIASS | 113 | 113 |
| 고시 | 155 | 155 |
| 보도자료 | 33 | 33 |
| 뉴스 | 4,499 | 821 |
| 합계 | 5,678 | 2,000 |

별도로 신규 공식 커넥터를 통해 실제 수집한 **KDI 자료 3건**이 저장되어 있다. 위 2,000건의 원본 복사 집계와는 구분한다. 같은 원본을 다시 가져왔을 때 변경 신호와 신규 프로젝트가 각각 0건임을 확인했으며, KDI 자료도 유지된다. 화면의 수집 시각·자료 수·정보원별 집계는 가장 최근에 완료한 가져오기 이력을 기준으로 표시한다. 이미 가져온 신호가 원본에서 제외·기각·중복·삭제되었는지도 별도로 확인해 로컬에 반영한다. 기간이나 2,000건 선택 범위 밖의 정상 자료와 사용자가 검토한 프로젝트는 보존한다.

매번 선택하는 최대 2,000건과 로컬에 누적 보존된 자료 수는 다를 수 있다. 갱신 때 이전의 정상 자료를 자동 삭제하지 않으므로 상단의 전체 신호·프로젝트 수가 2,000건을 넘을 수 있으며, 가져오기 이력에는 해당 회차의 선택 범위와 건수를 별도로 표시한다.

자동 프로젝트는 원신호별 초기 후보이므로 화면의 개수가 서로 다른 확정 투자사업 수를 뜻하지 않는다. 원문을 검토해 같은 사업을 병합할 수 있다. 투자 지역이 원신호에 없으면 미확인으로 두며 연결된 사업장 주소를 투자 지역으로 대신 쓰지 않는다. 지역 조건을 지정하면 지역 미확인 자료는 제외된다.

실제 모드의 저장소는 `127.0.0.1:55439/intel_live`, 예시 모드는 별도 DB `127.0.0.1:55439/intel_demo`이다. 예시 보고서와 예시 프로젝트는 실제 모드로 복사하지 않는다. 시험 담당자·사내 수신함은 가상 계정이다.

AI는 기본 모델 **`claude-sonnet-5`**로 실제 호출하며 실제 비용이 발생한다. 적용 모델은 AI 설정을 따르고 마지막 호출 모델·비용은 사용 이력에서 확인한다. 초기 로컬 월간 예산은 **미화 5달러**, 한도 도달 시 추가 호출 차단으로 설정되어 있다. 이는 로컬 기록을 기준으로 한 호출 제어이며 Anthropic 계정 전체의 청구 한도를 설정하는 기능은 아니다. 실패 시 실패 상태와 원인을 표시하고 예시 문구로 대체하지 않는다.

정기 보고서 전달은 **로컬 사내 수신함만** 허용한다. 보고서의 ‘공유’에서는 RAG 공유 목록 등록에 더해 **로컬 앱 메일함·1:1 메신저**에 실제 저장할 수 있다. 모바일 푸시를 선택해도 로컬에서는 발송하지 않고 생략 사유를 표시한다. 외부 이메일·실제 모바일 푸시는 실증하지 않았다. 기본 관심 분야의 정기 실행은 꺼져 있으며 사용자가 활성화한 일정만 실행한다.

브리핑 열람·생성·공유 권한은 기존 영업 업무 권한과 분리했다. 보고서는 본인·현재 정기 수신자·명시적으로 공유받은 사람만 열람하고, 재공유는 소유자만 할 수 있다. 정기 보고서를 개별 공유해도 관심 분야 설정이나 다른 보고서 접근권한을 주지 않는다. 메일의 ‘브리핑 보고서 열기’는 실제 공유 전달 기록과 현재 권한을 확인해 표시하며, 메신저 카드도 문서를 열 때 권한을 다시 검사한다.

## 직접 눌러볼 순서

1. **자료 확인:** 상단의 실제 모드 표시, 원본 가져오기 시각과 자료 수를 확인한다. ‘수집 DB 자료 갱신’은 같은 180일·2,000건 범위에서 원본을 다시 읽는다.
2. **관심 분야 설정:** 관심 분야를 선택하거나 추가해 업종·지역·규모·정보 유형을 저장한다. 우선 정기 실행을 끈 상태로 ‘대상 미리보기’에서 실제 대상과 출처를 확인한다.
3. **지금 생성:** 실제 AI 호출을 시작한다. 요청은 대기 회차를 바로 반환하며 서버가 뒤에서 생성한다. 화면은 약 15초마다 상태를 확인한다. 자료가 많으면 나누어 분석한 뒤 하나의 보고서로 통합한다. 각 AI 호출은 최대 약 4분이 걸릴 수 있어 전체 보고서 생성 시간은 이보다 길어질 수 있다. 핵심 동향은 최대 15개로 압축하고 영업 시사점은 우선 검토·확인 필요·참고 순서로 정리한다. 대기 중 중복 생성을 누르지 않는다. 완료되면 발행본·근거·PDF와 ‘시험 수신함’의 전달 결과를 확인한다.
4. **예약 실행:** 주기를 매일로, 시작일을 오늘로, 시각을 현재 한국 시각보다 몇 분 뒤로 설정하고 정기 실행을 켠다. 서버는 실제 KST 시각에 따라 30초마다 확인하며 시간을 가속하지 않는다. 예약도 실제 AI 비용이 발생한다. 검토가 끝나면 해당 관심 분야의 정기 실행을 끈다.
5. **영업 연결·후속 활동:** 보고서의 ‘투자 프로젝트 보기’로 프로젝트를 열고 서비스 가설·점수·개인 우선순위를 검토한다. 원문 출처와 프로젝트 이동은 구분된다. 사업장과 근거를 확인한 뒤 기존 영업건 연결 또는 신규 영업건 생성을 시험하고, 담당자와 시작·종료 일시를 확정해 후속 활동을 채택한다. ‘영업건 보기’에서 로컬에 저장된 예정 활동을 확인한다.
6. **보고서 공유:** 본인 보고서에서 ‘공유’를 열고 조직도에서 시험 수신자를 고른다. RAG 공유 목록은 항상 등록되며 앱 메일함·모바일 푸시·메신저를 추가 선택한다. 채널별 완료·실패·생략·전달 확인 필요 상태를 확인한다. 메신저는 기존 1:1 방을 재사용하거나 새로 만들며 보고서 링크 카드를 제공한다. 실패 전송 재시도는 성공한 채널을 다시 보내지 않는다. 전달 확인 필요 상태는 이미 도착했을 수 있어 자동 재전송하지 않는다.
7. **신규 사업장·공식 정보원:** 후보의 원문·회사명·주소를 검토해 보류·기존 연결·신규 등록을 시험한다. 공식 수집은 실제 모드에서만 열리며 사용 권리 확인, 활성화 및 필요한 인증정보 설정을 통과해야 한다. 각 정보원의 시험 결과와 최근 수집 상태를 확인한다.

발행된 브리핑은 복사 범위와 사용 가능한 근거에 한정된다. 기존 여섯 정보원의 원문 전체를 자동으로 AI에 보내지 않으며, 공식 자료도 현재 권리와 사용 가능 상태를 확인한다. ‘사용 가능한 근거 없음’이나 부분 수집 경고가 나오면 대상과 정보원 설정을 먼저 확인한다.

## 종료·다시 시작·문제 확인

```powershell
.\scripts\stop-local-intelligence-demo.ps1
```

종료 스크립트는 실증 화면 서버만 정지한다. DB 자료와 PostgreSQL은 보존되며 원본 연결용 터널도 자동으로 종료하지 않는다. 다시 `-Real`로 시작하면 저장한 설정과 결과를 이어서 사용한다.

DB 데이터 디렉터리는 Windows 임시 폴더의 `mcm-intel-phase1-pg`이다. 서버 로그는 `frontend/.next/local-intelligence-demo/server.log`와 `server-error.log`, 터널 로그는 같은 폴더의 `source-tunnel.log`와 `source-tunnel-error.log`에서 확인한다. AI 실패는 회차 상세의 실패 사유와 마지막 AI 호출 이력도 함께 확인한다. 비밀키나 원본 접속 비밀번호를 화면 캡처·문서·로그에 붙여 넣지 않는다.

도구는 localhost에만 바인딩하고 다른 Host·출처의 쓰기 요청을 거부한다. 실제 업무 함수의 권한·중복 방지·변경 버전 검사는 유지되지만, 시험 계정으로 로그인하는 독립 실증 서버이므로 운영 인증 검증을 대체하지 않는다.

## 제목·요약 불일치의 원인과 정정 기준

원본 뉴스 30건의 제목·공개 검색 발췌·기존 분류를 읽기 전용으로 대조한 결과, 로컬 복사 과정에서 내용이 달라진 사례는 없었다. 자동 프로젝트의 요약도 가져온 신호와 일치했다. 문제는 그 이전 분류에서 인사·주택 분양·안전 기사에 인용된 배경 투자를 기사의 중심 사건으로 바꾸거나, 정부 촉구·생산 협의를 확정 사업으로 해석한 데 있었다. 여러 기업의 공시를 묶은 기사에서 계약 주체를 SK하이닉스로 잘못 보완한 사례도 확인했다.

후속 검토에서는 보도자료 1건의 저장된 발행처 본문 1,297자를 별도로 대조했다. 국가산단의 LNG 발전소 3사와 별개 SK하이닉스 단지의 방류·가동 목표를 한 사업으로 합친 오류가 확인됐다. 장관 현장 방문과 지역 소통이 중심인 이 자료는 배경으로 정정했다. 공식 본문이 있더라도 문단마다 다른 기업·시설·지역을 합치면 안 된다. 최초 뉴스 30건 감사 파일은 변경하지 않고 보도자료 감사 파일과 해시를 따로 보존했다.

이번 정정은 원본 수집 DB를 **READ ONLY**로 조회하고 별도 로컬 DB에서 검증한다. 원본 운영 DB의 기사·분류·프로젝트를 고치지 않는다. 정정 전 제목·요약·분류와 검토 결과는 로컬 정정 원장에 남겨 전후를 추적한다. 기존 발행본의 본문·당시 근거와 원자료도 보존한다.

재발 방지 기준은 다음과 같다.

- 뉴스 검색 발췌와 보도자료 목록·RSS 요약은 기사 본문 전체가 아니다. 이 자료만으로는 최대 ‘후보’까지만 분류하고, 발행처의 본문을 직접 확보한 경우에만 근거와 확신 수준에 따라 ‘확정’을 허용한다.
- 기사 중심 사건과 배경 언급을 나눈다. 정부의 요구·전망·협상·검토를 회사의 투자 결정·착공으로 승격하지 않으며, 여러 기업이 나오는 기사에서 계약 주체를 추정하지 않는다.
- 모델은 제공된 근거를 선택하고 서버는 해당 원문 문구를 그대로 연결해 대조한다. 제목만으로 투자 사실을 채택하지 않는다. 인용문이 일치하더라도 주체·시점·사업 범위를 별도로 확인하며, 줄임표를 넘어 빠진 행위를 다른 문장으로 채우지 않는다.
- 투자 카드에는 해당 시설에서 확인된 개별 투자액만 표시하고, 없으면 미확인으로 남긴다. 전사 투자액과 여러 사업의 합계는 카드 본문에 섞지 않고 필요한 경우 핵심 동향에서 범위를 명시한다. ‘투자 규율 유지’는 금액이나 개별 계획의 유지 확인으로 바꾸지 않는다. 이 기준을 최종 실제 발행본에서도 확인했다.
- 품질 보류 자료는 새 검색·브리핑·검색용 적재·발굴 후보와 관련 프로젝트 분석에서 제외한다. 새 분석에는 정정된 현재 자료를 사용하며, 정정 전 검색 자료가 다시 섞이지 않도록 한다. 품질 표시가 없는 과거 자료 전체를 일괄 제외하지 않는다.
- 기존 보고서에 보류 근거가 있으면 추가 분석·해당 실행 재시도를 중단하고, 검증을 마친 자료로 새 브리핑을 생성하도록 안내한다. 과거 보고서를 새 내용으로 덮어쓰지 않는다.

공유·메일·메신저·권한의 별도 회귀 결과는 공유 DB 11개, 메일 링크 UI 3개, 대화방 답장 경계 4개, 브리핑 권한·메뉴 16개 통과다. 여기에는 실제 공유 기록이 없는 가짜 메일 링크 차단, 다른 메일함·대화방 접근 차단, 정보원 권리 회수, 프로세스 중단 뒤 전달 상태 복구가 포함된다. 이 검증과 로컬 실증을 위해 운영 DB·AWS 서비스·EventBridge·실제 직원 알림은 변경하지 않았다.

정기 브리핑 단위·DB 통합 검사는 33개, AI 게이트웨이의 실제 요청 본문을 모의 전송으로 확인하는 검사는 6개가 통과했다. 최종 원자료 대조·금액 범위·공장명·시점·인용 기간 정책을 포함한 단위 검사는 41개를 통과했다. 단위 항목은 앞선 통합 검사와 일부 겹치므로 합산하지 않는다. 모바일 타입 검사와 웹 내보내기 50개 경로도 통과했으며, 이를 실제 휴대전화의 푸시 수신 검증으로 간주하지 않는다.

## 비용 없는 예시 모드와 회귀 검증

예시 모드는 `-Real` 없이 시작한다. 실제 모드가 켜져 있으면 먼저 종료해야 한다.

```powershell
.\scripts\stop-local-intelligence-demo.ps1
.\scripts\start-local-intelligence-demo.ps1
```

이 모드는 `intel_demo`에 가상 자료를 사용하고 서술을 ‘로컬 예시 문구’로 표시한다. 외부 AI·공식 수집·이메일·푸시는 연결하지 않는다. 집계, 저장, 발행, 로컬 사내 수신함 전달은 실제 처리 함수를 사용한다.

예시 서버가 켜진 상태에서 frontend 폴더에서 실행한다.

```powershell
npm run test:intel-local
node scripts/test-local-intelligence-schedule.mjs
```

두 스크립트는 첫 조회에서 서버 모드가 `demo`, DB가 `intel_demo`, 외부 서비스 연결이 꺼짐을 모두 확인해야 진행한다. 실제 모드이거나 모드 확인이 불가능하면 자료 저장·예약 등록·브리핑 생성 전에 종료한다. 첫 검사는 이름에 ‘직접 실증’이 붙은 가상 자료를 저장한다. 예약 검사는 다음 분의 실제 예약 시각을 기다린 뒤 해당 프로필을 다시 중지한다.

2026-10-30 예시 모드에서 실제 브라우저의 관심 분야 저장·새로고침 유지, 예시 발행·사내 수신함·PDF, 개인 우선순위, 새 영업건 생성과 예정 활동 채택을 확인했다. 19:35 KST 예약도 실제 30초 타이머를 거쳐 발행·전달되었으며 검증용 프로필은 다시 중지했다. 이 결과는 실제 AI 보고서 품질 검증과 구분한다.
