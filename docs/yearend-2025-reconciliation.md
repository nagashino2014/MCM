# 2025 귀속 연말정산 — 앱 계산 vs 세무법인 원천징수영수증 대사

작성 2026-09-14. 자료: `V:\업무자료\경리업무\연말정산자료\2025년` (근로소득원천징수영수증 계속근무자 33·퇴직자 7, 세무법인 총괄표 `연말정산현황_2025년 계속근무자_v5.pdf`, 홈택스 간소화 PDF 31, 소득세액공제신고서 xlsx). 앱 쪽은 staging DB의 2025년 확정 급여대장 12개(4,573 라인)와 `yearend_tax_params`(2025), `yearend_settlements`(저장 2건).

## 1. 요약

- 앱 엔진(`lib/finance/yearend.ts`) 자체는 세율·근로소득공제·산출세액·표준 항목에서 세무법인과 원 단위로 일치한다. 세무법인이 쓴 총급여·기납부·보험료(base)와 같은 입력을 넣고 로직 갭 4종(§4)을 보정하면 **30명 중 28명이 결정세액 0원 차이**, 나머지 2명도 1.6만·1.1만 원(근로소득세액공제 한도식·감면 근사)이다.
- 따라서 화면에서 보이는 큰 차이(예: 이재영 앱 환급 3,971,256 vs 실제 추납 2,351,470)는 **급여대장 자동집계**(총급여·기납부·4대보험료) 차이가 주범이고, 그 다음이 미구현 로직(중소기업 취업자 감면·표준세액공제 규칙·문화체육)이다.
- 30명 합계 기준 차감징수세액의 절대 오차는 앱 현재 20,406,391원 → base만 세무법인 값으로 바꾸면 10,268,521원 → 로직 갭까지 보정하면 27,048원.
- 4대보험료가 급여대장과 다른 이유: 세무법인은 **건강·장기요양·국민연금을 홈택스 간소화(공단 고지액, 정산분 포함) 그대로**, **고용보험만 급여대장 공제액**으로 잡았다(§3-②). 앱은 대장 공제액에 '정산-*' 열을 합산한다.
- 인정상여(이재영 15,850,710)는 급여대장 밖 소득처분이라 앱에 없었다. 이번에 입력 필드 `deemedBonus`로 총급여에 가산하도록 반영했고, 기납부에서 '정산-근로소득세'를 제외하도록 고쳤다(§5). 이 두 가지로 이재영은 앱 엔진에서 결정세액 10,640,875·추납 2,351,470이 그대로 재현된다.

## 2. 방법

1. 원천징수영수증 1~3쪽을 pdfplumber로 파싱(1쪽 급여·상여·인정상여·비과세·결정/기납부/차감·4대보험, 2쪽 정산명세, 3쪽 실제 지출액). 세무법인 총괄표(4쪽 표)와 교차 검증해 33명 전원 일치.
2. 앱 자동집계(`buildYearendBase`)를 같은 SQL로 재현하고, 엔진을 Python으로 원 단위 포팅(`computeYearend`)해 세 시나리오를 계산.
   - **A = 앱 현재**: 앱 자동집계 base + 세무법인이 실제 사용한 공제 입력(3쪽 지출액·2쪽 인원수·총괄표 역산)
   - **B = base 교체**: 세무법인 base(영수증 총급여·주현 기납부·영수증 보험료) + 같은 입력 → 남는 차이는 엔진 로직
   - **C = 세무법인 확정**(영수증). 추가로 **D = B + 로직 갭 보정**으로 잔여 차이가 0에 수렴하는지 확인.
3. 원인 확인을 위해 원본 급상여대장 xlsx(1·2·3·4·5월)와 간소화 PDF의 건강보험·국민연금 페이지를 직접 대조.

## 5. 인정상여 처리와 이번 코드 수정

이재영 영수증: 급여 80,000,000 + 상여 1,000,000 + **⑮인정상여 15,850,710** = 총급여 96,850,710, 과세표준 71,107,815, 산출세액 11,305,875(24% 구간), 결정세액 10,640,875, 기납부 8,289,400(월 소득세 합), **추납 2,351,470**. 인정상여는 2025 사업연도 법인세 세무조정에서 상여 처분된 금액을 세무법인이 연말정산에 선반영한 것으로, 급여대장에 없고 원천징수도 되지 않아 결정세액이 그대로 추납된다. 별도로 2025년 3월 대장의 '정산-근로소득세' 2,899,660은 2024 귀속 인정상여(2025.3 법인세 신고 시 처분)에 대한 원천징수분으로 추정된다(사용자 확인 요망).

수정(미커밋, `npx tsc --noEmit` 해당 파일 오류 없음):

- `frontend/lib/finance/yearend.ts` — `YearendInputs.deemedBonus`(인정상여)·`deemedBonusWithheld`(인정상여 기원천징수 소득세) 추가. `computeYearend`가 총급여 = 대장 과세 합 + 인정상여로 계산하고 결과에 `deemedBonus`를 보존. `buildYearendBase`의 기납부를 `income-tax`만 집계(`settle-income` 제외). 이어서 §6 P1(정산열 제외·보험료 납부액 입력)도 같은 파일에 반영.
- `frontend/components/payroll/YearendBoard.tsx` — 공제 입력 그리드 맨 앞에 인정상여 2필드, 목록·브레이크다운에 "급여대장 + 인정상여" 표기.

검증(엔진 재현): 이재영에 세무법인 base + 인정상여 15,850,710 → 결정세액 10,640,875·추납 2,351,475(세무법인 2,351,470, 5원은 영수증 기납부 표기 반올림). 다른 29명은 인정상여 0이므로 영향 없음. 앱 저장 2건(이재영·강소현 draft)은 Claude 간소화 PDF 파싱 입력(카드 항목·의료비 실손 미차감)이 세무법인 입력과 달라 재계산이 필요하다.

## 6. 수정 현황과 남은 항목(우선순위)

**P1 집계 규칙 — 2026-09-14 반영(마이그 222 + 코드)**

- (a) 임포터 `ROW2_OVERRIDES`: 25년02월 대장 2단 '정산-건강보험'/'정산-국민연금' → `yearend-income`/`yearend-local`. 이미 적재된 행은 마이그 `222_yearend_2025_ledger_fixes.sql` §1이 1:0.1 쌍 조건으로 교정.
