# MCM UI 기준 — Precision v1.0

- 갱신: 2026-09-10 · 후속 요청: 기본 구조 보존, 버튼·태그형 버튼·탭 반경 8px 통일, 기존 블루·보라 버튼 색 유지, 6개 메뉴 샘플 제공 · 최초 요청: MCM 웹앱 전체 UI 정비 및 과도한 설명문 축약/도움말 전환
- 시각 참조: KESI-IEPS Precision UI Handoff v1.0, T-003 / ADR-009 / 2026-09-07
- 적용 제품: MCM 웹앱. 별도 KESI-IEPS 플랫폼의 메뉴·데이터·기술 스택은 가져오지 않는다.
- 기존 Modernize/Soft Glass Ink 규칙 중 아래와 충돌하는 시각 규칙은 이 문서가 대체한다. cdash API, 업무 기능, 권한, 데이터 계약은 유지한다.

## 1. 판정 원칙

**최우선 사용자 지시(2026-09-10): 지시 없는 UI 구조 변경은 엄격히 금지한다.** 기존 트리뷰·상세 양식·카드 수와 위치·분할 비율·탭·표 열·메뉴 체계·스크롤 부모를 보존한다. 허용 범위는 글자, 색, 테두리, 배경, 작은 간격, 설명문 축약과 `?` 도움말이다. 핸드오프의 폭·배치 수치를 기존 화면에 강제하지 않는다. 구조 변경은 아래 §7의 명시적 두 예외에만 적용한다. 샘플에도 같은 원칙을 적용한다.

표·목록·입력과 현재 작업 위치를 먼저 읽을 수 있어야 한다. 화면의 개성이나 장식보다 반복되는 규칙을 우선한다. 신규 화면도 아래 기준을 통과해야 한다. 예외는 대상·이유·검증 결과를 이 문서의 예외 목록에 남긴다.

라이트와 다크에 동일한 의미 토큰을 사용한다. MCM의 `--cd-*` 소비 API를 유지하며 색·표면의 원천은 `frontend/components/cdash/`에 둔다. 페이지 CSS는 공통 토큰이나 같은 클래스의 시각 값을 재정의하지 않는다.

**버튼 반경 후속 지시:** `frontend/app/globals.css`의 `--mcm-action-radius: 8px`를 일반·작은·아이콘·태그형·필터·탭 버튼 모두의 네 모서리에 적용한다. `--cd-radius-control`도 이 값에 연결한다. 반경 속성만 공용 `!important` 규칙으로 고정해 `rounded-xl`, `rounded-full`, 페이지 CSS, 인라인 스타일이 덮어쓰지 못하게 한다. 버튼으로 쓰는 링크·업로드 label 등에는 `cd-action`을 부여한다. 연결형/밑줄형 탭의 배치·테두리·선택 방식은 보존하면서 반경만 통일한다. 표시 전용 배지, 아바타, 스위치 노브, 도표, 문서 콘텐츠는 동작 버튼으로 취급하지 않는다.

글꼴은 Inter / Noto Sans KR / Pretendard / Malgun Gothic / system-ui 폴백을 사용한다. 이번 작업에는 폰트 다운로드·새 라이선스 의존성을 추가하지 않는다. 제품 기기에서 사용된 실제 폰트와 200% 확대 판독성을 검증 기록에 남긴다.

## 2. 메뉴

- 그룹 → 부모 → 들여쓴 자식의 위계를 유지한다. 자식은 1px 안내선과 일정한 들여쓰기를 쓴다.
- 부모 13px, 자식 12~13px, 그룹 11px 이상. 기존 반응형 레일·메뉴 형태를 보존하면서 글자 대비를 정리한다.
- 현재 항목은 면·경계·블루 글자로 표시하고 `aria-current="page"`를 제공한다. 부모는 해당 자식의 위치를 표시하되 여러 관련 없는 부모를 동시에 활성화하지 않는다.
- 펼침은 `button` + `aria-expanded` + `aria-controls`. 이동은 링크. 현재 경로의 부모는 자동으로 펼친다.
- 경로는 세그먼트 기준으로 비교한다. `?tab=` 메뉴는 query도 비교하고, 여러 후보 중 가장 구체적인 경로가 우선한다. 페이지 상세에서도 소속 메뉴를 잃지 않는다.
- 메뉴 설정의 부모 23개·자식 65개, URL·역할 조건을 보존한다. 시안의 축약 메뉴를 복제하지 않는다.
- 스크롤 가능한 메뉴의 끝까지 키보드·터치로 접근할 수 있어야 한다. 드로어는 이름·닫기·Escape·포커스 복귀를 제공한다.

## 3. 설명문과 `?` 도움말

| 정보 | 처리 | 예 |
|---|---|---|
| 제목을 반복하는 소개 | 삭제 또는 짧은 한 문장 | ‘계약을 관리하는 화면입니다’ |
| 기능 사용법·용어·배경·산식의 상세 | 제목/필드 옆 `?` 팝업 | ‘수집은 목록을 가져오고 파싱은 원문에서 항목을 추출합니다’ |
| 현재 범위·발신자·선택 수·필터 조건 | 화면에 간결하게 유지 | ‘표시 20 / 전체 156’ |
| 오류·저장 실패·필수 형식·권한 제한 | 해당 컨트롤 근처에 상시 표시 | ‘저장하지 못했습니다. 입력은 유지됩니다’ |
| 전송·삭제·확정 영향 | 실행 전에 상시 표시 | ‘승인 후 외부로 자동 발송됩니다’ |
| 개발 단계·내부 구현 설명·미연동 KPI | 설명 축약 가능. 기존 카드 자체는 임의 삭제하지 않음 | ‘CONCEPT’ 표시와 카드 수·위치는 유지 |

`?`는 클릭·Enter/Space로 열고 Escape·외부 클릭·닫기 버튼으로 닫는다. 아이콘에 ‘계약 관리 도움말’처럼 대상 이름을 붙인다. hover tooltip만으로 긴 문장을 제공하지 않는다. 팝업은 불투명·최대 360px·화면 좌우 여유 16px이며 긴 내용은 내부 스크롤한다. 닫기와 Escape 후 원래 버튼으로 포커스를 복원한다. 여러 설명을 단순히 하나의 거대한 도움말로 몰아넣지 않고 관련 제목·필드에 연결한다.

상시 설명은 간단히 쓰되 글자 수에 맞춰 자동으로 자르지 않는다. 경고와 도움말은 색상만으로 자동 분류하지 않고 내용·실행 영향을 검토한다.

## 4. 상태와 반응형

- 선택형 태그·필터·탭 버튼은 단일 테두리와 같은 계열의 옅은 그라데이션으로 표시한다. `.cd-chip` 등 기존 공용 패턴 또는 `.cd-choice[data-active="true"]`를 사용하며 개별 색은 `--cd-choice-color`에 연결한다. 기본 농도는 카드색에 선택색7%→14% 혼합이다. 배치·버튼 크기·선택 조건·연결형/밑줄형 탭 구조는 유지한다.
- 버튼 선택 상태에 바깥 box-shadow/ring을 추가하지 않는다. 키보드 포커스는2px outline을 offset -2px로 테두리 안에 겹쳐 표시한다. 문서 편집 셀·입력 필드·달력 오늘 날짜 등 다른 목적의 강조는 별도 유지한다. 색상 견본 버튼에는 견본을 가리는 선택 그라데이션을 적용하지 않는다.
- 대시보드 지역 태그는 원본 주황 계열 `#fa896b`/배경 `#fbf2ef`, 미수금1~2개월은 `#ffae1f`,2개월 이상은 `#f3704d`를 전용 토큰으로 유지한다. 공통 warning/error 토큰 변경으로 이 업무 색을 덮어쓰지 않는다. 지도와 범례의 원본 `rgba(250,137,107,…)` 농도 수식은 유지한다.
- 영업활동 진행상황 단계 태그의 테두리는 현재 녹색 `#7EBA56`, 지난 단계 회색 `--cd-muted`, 예정 단계 파랑 `--cd-primary`이다. 기존 단계 판정·정렬은 유지하고 경과 미입력 경고는 태그 안의 작은 붉은 표시와 문구로 분리한다.
- 앱 데이터 표의 열 머리글에는 본문과 구분되는 불투명 중립색을 사용한다. 공통 `.cd-table > thead`와 명시적 `.cd-table-head`를 `--cd-table-header-bg`에 연결한다. 기존 의미색 헤더와 실제 문서·인쇄 서식은 유지한다.
- 표와 그 위 검색·필터·작업 메뉴 사이에는 기본 12px 간격을 둔다. 이미 12px 이상이면 중복 여백을 추가하지 않는다. 필요한 기존 wrapper에만 `.cd-table-section` 또는 동일한 간격을 적용하며 스크롤 부모·표 열·분할 구조는 바꾸지 않는다.
- FHD 전수 점검은 CSS viewport 1920×1080에서 수행한다. 소스 검사, 가상 데이터 검증, 로그인한 운영 화면 검증을 구분해 기록한다. 구조 수정이 필요한 화면은 문제·영향·최소 수정안을 사용자에게 제시하고 승인 전에는 구조를 변경하지 않는다.

- 빈 목록과 검색 0건을 구분하고 다음 행동을 제시한다. 실제 0과 조회 실패를 혼동하지 않는다.
- 저장 중에는 중복 요청을 막고 서버 성공 전 완료 문구를 표시하지 않는다. 실패·충돌 때 입력을 보존한다.
- 체크박스 선택과 상세 열기를 분리하고 상세 종료 후 목록 필터·페이지·스크롤·포커스를 유지한다.
- 기존 반응형 분기와 표의 열을 유지한다. 가상 목록의 높이와 스크롤 부모를 임의로 바꾸지 않는다.
- 모달·드로어는 불투명 면, 배경 스크롤 차단, 포커스 가두기/복귀. 가림막은 24%, 블러 없음. 팝업·시트의 중립 그림자만 허용한다.

## 5. 인수와 재발 방지

1. 기준 커밋·변경 파일·적용 화면을 기록한다. 빌드 성공만으로 타입·접근성 검증을 대신하지 않는다.
2. 메뉴의 모든 설정 URL과 query/상세 경로/역할을 검사한다. 메뉴 설정 변경은 별도 요구가 있을 때만 한다.
3. 1440×1080, 1024×768, 390×844에서 Light/Dark와 메뉴/필터/도움말/시트를 확인한다. 200% 확대와 Tab/Shift+Tab/Enter/Space/Escape도 확인한다.
4. 기본 면의 computed background 불투명·backdrop-filter 없음, 표 행/입력 치수를 검사한다. 그라데이션은 §6의 앱 바탕·주요 버튼 및 선택형 버튼 예외에만 적용한다.
5. 보조 설명은 필요할 때 열 수 있고 실행 영향·오류는 닫혀도 보이는지 확인한다.
6. 재현 가능한 검사 명령과 이미지·실패·미검증 항목을 남긴다. 인증·API·운영 데이터 확인이 없으면 그 한계를 명시한다.

| 도면·차트·지도 데이터, 날씨의 상태 삽화 | 데이터/상태를 나타내는 색과 그래픽 | 데이터 의미와 기존 시각 자산을 보존한다. 카드·버튼의 장식 효과 예외로 확장하지 않는다 |
| 문서 미리보기/인쇄 결과 | 서식의 크기·색·글꼴 | 앱 UI 규칙을 문서 양식에 덮어쓰지 않는다 |
| 전체 폭이 필요한 캔버스·분할 작업면 | 작업 영역 폭·독립 스크롤 | 일반 정보 페이지 최대 폭을 강제하면 표/가상화/편집 동작이 손상될 수 있다 |

추가 예외는 임의 CSS로 만들지 말고 적용 이유와 검증 근거를 기록한다.

## 7. 구조 보존 및 사용자가 지시한 두 예외

- 모든 메뉴에 구조 보존을 적용한다. 계약 관리는 기존 트리뷰와 우측 계약 상세 양식을 그대로 쓴다. 새 가로 메뉴는 만들지 않으며 샘플 전환 바도 제거한다.
- `/contracts/billing`: 연결형 6탭, 지도·목록·요약·상세 구조 보존. 공용 underline/pill 탭도 원래 variant를 유지한다.
- **예외 1 — 계약 대시보드:** FHD에서는 미수금·수금내역을 하단 행으로 이동한다. CSS viewport 1600~2559px은 3열+하단 내역, 2560px 이상은 원본 4열. 차트·카드 내용은 유지한다.
- **예외 2 — 영업 상세:** FHD에서는 영업활동 이력·담당자를 달력/사업장 정보 아래로 이동한다. 1600~2559px에서 하단 두 카드를 나란히, 2560px 이상에서 원본 640px 우측 패널·7:3 배치. 좁은 화면은 위아래로 쌓는다.
- 분기는 모니터 사양이 아닌 CSS 가용 폭 기준이다. 4K 모니터도 배율·창 크기로 가용 폭이 좁으면 FHD 배치를 사용한다.
- 제공된 운영 URL은 로그인으로 전환되어 실제 사업장 데이터는 열람하지 못했다. 샘플은 실제 원본 컴포넌트와 가상 데이터로 확인하며 운영 데이터 검증과 구분한다.
