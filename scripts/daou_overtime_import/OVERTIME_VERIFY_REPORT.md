# 초과근무수당 산정 검증 리포트 (2026년 5월분)

> 목적: 급여대장의 초과근무수당을 **신청 기록 × 근태 기록 대조**로 산정하도록 하고,
> 세무사가 작성한 실측 대장과 대조해 산식을 확정한다.
> 데이터: 다우오피스 초과/휴일근무신청 → MCM 전자결재(`frm-overtime-request`) 마이그레이션분.

## 1. 마이그레이션

- 원본: `data/daou/docs/<id>/detail.json`(다우 반출본)의 본문 HTML 표.
- 대상: 신청일 2026-04-26 ~ 05-27 중 **근무일이 2026-04-26 ~ 05-25**(급여 귀속 구간)인 건.
  신청일을 27일까지 넓힌 이유 = 25일 근무를 27일에 사후 신청한 사례 포함(앱 전환 후에는 사후 신청 불허 예정).
- 결과: 신청 66건 중 **58건 적재**(전원 매칭, 스킵 0·승인자 매칭 실패 0), 15명 · 신청시간 합계 196h.
- 스크립트: `parse_overtime.py`(파싱·dry-run) → `import_overtime.py --apply`(적재, 멱등 `doc_id=ovt-daou-<다우문서ID>`).

- **사규(신청서 본문 명시)**: 초과근무 시작 19:00(석식 후) · 야간 22:00~06:00 · 휴일근무 별도 ·
  **초과근무수당 지급 상한 월 20시간**. 다만 5월 실측은 상한 초과분(이근형 32.5h·이윤재 33h)도 전액 지급 —
  상한 미적용 관행으로 보이며, 시스템 반영 여부는 사용자 확인 필요(현재 미구현).

## 5. 근태 대조 완성 (2026-08-15 2차 — 5월 근태 적재 후)

5월 근태기록(`V:\...\초과근무수당\월별근태기록\2026\5월`, 본사 통합본 1 + 개인본 5)을 업로드하고
**신청 시간대 ∩ 실제 재실 시간대**의 일자별 교집합으로 산정하도록 완성했다.

### ⚠ 발견: 울산지사 사번 충돌로 인한 근태 오염
울산지사 단말이 본사와 **별개의 사번 체계**를 쓴다 — 울산 0008=최태헌인데 본사 0008=한도경.
개인 파일을 그대로 올리면 `(adt_emp_no, work_date)` PK 가 겹쳐 **본사 직원 근태를 덮어썼다**.
실측 충돌 5건: 0004(권오종↔신석헌) · 0005(이일국↔이홍길) · 0007(조옥환↔김민지) · 0008(한도경↔최태헌) · 0009(한상순↔김성은).

조치:
- 파서(`lib/adt/excel.ts`)가 **지사 파일(부서 열 없는 개인 조회본)** 을 감지해 사번에 `U` 접두어를 붙인다.
- 별칭 표 `attendance_emp_aliases`(마이그 166)로 `U0005→이홍길` 등을 매핑. 한 직원이 본사·지사 사번을 함께 가질 수 있다.
- 이홍길 프로필의 ADT 사번이 울산 번호(0005)로 잘못 등록돼 있어 본사 번호(0064)로 정정.
- 오염 구간(2026-04-26~05-25) 삭제 후 재적재 → **사번 충돌 0건**, 권오종·한도경 근태 복구, 최태헌 수당 756,000원(실측 일치) 회복.

## 6. 산정 기준 확정 — 개인별 소정근로 종료 시각 (2026-08-15 3차)

§5 의 "신청 시간대 ∩ 재실 시간대" 는 **초과근무 시작 시각을 신청서 문구에 맡긴** 계산이라 과소 산정이 났다.
사용자 확정 기준은 **개인별 소정근로 종료 이후 전부가 초과근무**다.

- 8시 출근 → 17:00 소정 종료 → **17:00 부터 초과근무**. 예) 이승한 4/27 재실 17:00~20:01 · 신청 3h
  → 종전 2h(18~20시 교집합) → **3h 전량 인정**(실측 80,100원과 일치).
- 인정분 = 초과 가능 구간 [소정 종료, 퇴근] 안에서 **신청 시간을 상한**으로 배분한다
  (신청 시간대와 겹치는 부분 먼저, 모자라면 소정 종료 직후부터 채움).
- **휴일**(토·일·공휴일·근로자의 날)은 소정근로가 없어 재실 전체가 대상 —
  5/1 근로자의 날 2건(이근형 7h · 한도경 6h)이 종전 로직에서 미근무로 떨어지던 문제가 해소됐다.
- 출근 유형은 4종 선택식(조기 8시 / 정시 9시 / 10시 / 10시 육아단축)으로 인원별 설정(마이그 167).
  미설정자는 조기출근(8시). 화면: 근태·초과근무 관리 → 산정 정책 탭.

### 예외 승인
지문 미태그 등으로 근태와 신청이 어긋난 건은 관리자가 **예외 승인**(신청 전량 인정) / **반려**(전량 불인정) 할 수 있다
(`overtime_match_overrides`, 신청 대조 탭). 배민경 4건(4/26·27·28, 5/7)은 실근무 확인 후 예외 승인 처리 —
**409,500원으로 실측 대장과 일치**. ※ 2026-09 앱 정식 전환 이후로는 근태 미태그 건을 예외 없이 미근무 처리할 방침이라,
이 기능은 과도기 보정 수단이다.

## 7. 구현 반영

- `lib/payroll/overtime.ts`
  - `matchOvertimeRequests()` — **신청 1건 × 그 날 근태의 일자별 대조**. 개인별 소정근로 종료 이후의 재실 시간
    안에서 신청 분을 상한으로 배분하고(`allocateSegments`) 판정을 남긴다
    (`full`/`short`/`absent`/`no-record`/`override`/`rejected`). 주 합계 min 은 일자 간 상쇄가
    생겨 쓰지 않는다(A일 미근무 + B일 초과가 서로 가려지는 문제).
  - `loadWorkSchedules()` — 인원별 출근 유형(마이그 167), 미설정은 조기출근(08:00~17:00).
  - `loadOffDays()` — 공휴일(외부 소스 + 근로자의 날 5/1) 집합. 휴일은 재실 전체가 초과근무 대상.
  - `overtimeAmounts()` — 위 대조 결과를 인원별로 합산해 금액 산출(22시 이후는 야간 2.0배).
    신청서 없이 근태만 있으면 **미산정**(사전 승인 없는 근무는 수당 대상 아님).
  - 같은 날 본사·지사 두 사번 행이 있으면 **출퇴근이 기록된 행을 우선**한다.
- `lib/payroll/generate.ts` — 대장 생성 시 결과를 반영하고 근거·차감분을 행 경고로 남긴다.
- `GET/POST /api/payroll/overtime-match?year=&month=` — 대조 내역·인원별 금액·요약 + 예외 승인/반려/해제.
- 화면 `/approval/attendance` — **신청 대조** 탭 신설(월 선택·KPI·인원별 금액·건별 판정·예외 승인),
  **산정 정책** 탭에 엑셀 업로드·산정 기준·직원별 출근 시각을 통합.
