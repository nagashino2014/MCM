## 3. 확정 결함

### F-1 (중대) 업무추진계획 3화면 — 좌 900px 고정으로 우측 상세가 664px로 압착

- 위치: `components/work-plan/ServiceWorkspace.tsx:258`, `OversightWorkspace.tsx:379`, `ExecWorkspace.tsx:101`
- 선언: `lg:grid-cols-[900px_1fr]` → FHD 실측 `gridTemplateColumns = "900px 664px"`
- 결과: 우측 `ReportEditor`의 날짜 입력이 **폭 59px / 내용 91px**로 잘린다(`2026-09-14`가 안 보임). 수행인력·추진내역 열도 함께 눌린다.
- 근본 원인: `ReportEditor.tsx:389`의 `md:grid-cols-2 xl:grid-cols-4`는 **뷰포트 기준** 브레이크포인트다. FHD에서는 실제 컨테이너가 664px뿐인데도 `xl`(≥1280)이 켜져 4열이 적용되고, 한 칸이 약 166px로 줄어 그 안의 두 날짜 입력이 59px씩 나눠 갖는다.
- 좌측은 카드 1장만 있어도 900px을 고정 점유하므로 넓은 화면일수록 낭비가 커진다.
- `lg`(1024px) 구간에서는 900px + 우측 약 100px로 더 심하게 깨진다.

### F-2 (정정: 결함 아님) 채용 템플릿 카드 미리보기

- 위치: `/admin/recruit/templates` (`components/recruit/DocCanvas.tsx` `DocMiniPreview`)
- 1차 측정은 "폭 69px / 내용 900px 잘림"이었으나, 900px 문서를 `transform: scale(250/900)`로 축소하는 **의도된 구조**다. 측정기가 축소 전 레이아웃 폭을 잘림으로 오인했다.
- 재측정: 축소된 문서가 250px 미리보기에 정확히 들어가 전체가 보인다(`docFullyVisible: true`).
- 남는 사항은 결함이 아닌 디자인 과제다: 카드 실폭 295px 대비 미리보기 250px로 우측 44px 여백. 루트 `min-h-screen p-6`도 셸 규약과 다르다. → 디자인 통일 단계로 이관.

### F-3 (경미) 권한 템플릿 카드 — 태그 행이 잘려 +N 이 가려짐

- 위치: `components/admin/users/PermissionManagementPanel.tsx:327`
- `flex-nowrap … overflow-hidden`에 표시 개수를 고정 계산해 넣어, 317px 폭에서 마지막 태그가 최대 123px 잘려 글자가 반쯤 보인다. "+N" 요약 규칙이 실제 폭을 반영하지 못한다.

## 4. 구조적 위험 (앱 전역)

Tailwind 3.4의 `sm/md/lg/xl/2xl`은 전부 **뷰포트 폭**을 본다. MCM은 좌목록 + 우상세 분할이 표준 패턴이므로, 분할 안쪽 컴포넌트는 뷰포트가 넓을수록 오히려 좁은 칸에 많은 열을 그리게 된다. F-1이 그 전형이다. 컨테이너 쿼리는 현재 미도입(`@container` 사용처 0건)이다.

FHD에서 고정·최소 폭이 큰 분할 선언:

| 화면 | 선언 | FHD 실측 |
|---|---|---|
| 업무추진계획 3종 | `lg:grid-cols-[900px_1fr]` | 900 / 664 |
| 계약 관리 | `xl:grid-cols-[minmax(360px,0.9fr)_minmax(560px,1.4fr)]` | 비율 배분, 문제 없음 |
| 계약 다운로드 | `xl:grid-cols-[minmax(360px,0.9fr)_minmax(620px,1.4fr)]` | 비율 배분, 문제 없음 |
| 사용자·권한 | `xl:grid-cols-[360px_minmax(0,1fr)]` | 360 / 1198 |

즉 고정 px 단일 값을 쓴 곳은 업무추진계획 계열뿐이며, 나머지는 `minmax`+`fr`로 이미 비율 배분된다.
