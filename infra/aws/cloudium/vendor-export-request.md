# 클라우디움 데이터 반출 — 벤더 문의용 정리

계약 종료에 대비해 보관 데이터를 자체 인프라(AWS S3)로 이전하려는데, 클라이언트단에서 대량 복사가 차단되어
반출 방법 확인이 필요한 상황. 아래는 **문의 메일에 그대로 붙여 쓸 수 있게** 정리한 실측 내용이다.

## 1. 대상 규모

| 항목 | 값 |
|---|---|
| 총 용량 | 5,230,692,544,851 B = **4,872 GB** (약 4.87TB) |
| 문서 수 | **1,193,509** |
| 폴더 수 | 226,114 |
| 평균 파일 크기 | 4.38 MB |
| 최상위 | `전사 폴더 > 한국환경안전연구원` (2020-07-30 개설) |

## 2. 증상 — 탐색기 외의 모든 프로그램에서 T: 접근 거부

클라이언트 로그인 상태에서 탐색기로는 T: 가 정상적으로 열린다. 그러나 명령줄 도구는 전부 차단된다.

| 실행 주체 | 결과 |
|---|---|
| explorer.exe | 정상 접근 |
| powershell.exe | `UnauthorizedAccessException` / `0x80070005` |
| robocopy.exe | `ERROR 5 (0x00000005) Accessing Source Directory T:\` — exit **16** |
| cmd.exe (`dir T:\`) | `Access is denied` (exit 1) |

### 배제한 원인
- **세션·권한 문제 아님** — 탐색기와 PowerShell이 동일 세션(1)·동일 사용자·둘 다 비관리자인데 결과가 갈린다.
- **프로세스 실행 자체는 막히지 않음** — cmd.exe 는 정상 실행되어 로그 파일을 생성했다.
  즉 "프로세스 차단"이 아니라 **"해당 프로세스의 T: 드라이브 접근 차단"** 이다.
- **경로 표기 오류 아님** — `T:\`, `"T:\."` 두 형식 모두 robocopy 가 `Source T:\` 로 정확히 인식한 뒤 거부됐다.

### 환경
- `PantaFSService`, `TEFSvrP64` (세션 0, 경로 조회 불가한 보호 프로세스) 상주
- `T:` 는 `Win32_LogicalDisk` 상 DriveType=3 이나 FileSystem·Size 가 비어 있는 필터 드라이버 가상 볼륨
- robocopy 실경로: `C:\Windows\System32\Robocopy.exe` (64비트). `C:\Windows\SysWOW64\Robocopy.exe` 도 존재

### 이미 시도한 설정 — 부분적으로 해결됨
관리 콘솔 **"보안 관리 > PC매체 제어 > 대상 응용 프로그램 설정"** 에 `robocopy` 를 "사용"으로 등록하고
**클라이언트 재로그인** 후, robocopy 의 T: 접근이 열렸다(`exit=0`).

그러나 두 가지 제약이 남아 실질적인 대량 반출이 불가능하다.

#### 제약 ① 디렉터리 열거가 차단된다 (핵심 문제)

| 시도 | 결과 |
|---|---|
| `robocopy T:\ ... /LEV:1` | 성공(exit 0)하지만 **목록이 비어 있음** — 최상위 폴더들이 보이지 않는다 |
| `robocopy T:\ ... /LEV:2` | 동일하게 빈 목록 |
| `robocopy T:\한국환경안전연구원 ... /LEV:1` | **성공 — 파일 2개가 정상 표시됨**(`test.xlsx` 9,505B / `이미지 파일.png` 7,047B) |
| `robocopy T:\한국환경안전연구원 ... /LEV:2` | 파일 2개만. **하위 폴더 226,114개가 전혀 표시되지 않음** |

즉 **경로를 직접 지정하면 그 폴더의 파일은 읽히지만, 하위 디렉터리 목록은 얻을 수 없다.**
탐색기에서는 폴더 구조가 정상적으로 보이므로, 열거 권한이 explorer 에만 있는 것으로 보인다.

→ 재귀 복사(`/E`)가 성립하지 않아, 폴더 226,114개의 경로를 모두 사전에 알지 못하면
   robocopy 로는 자동 반출을 할 수 없다.

#### 제약 ② 접근이 간헐적으로 거부된다

동일한 명령을 0.7초 간격으로 5회 반복한 결과:

```
시도 1 : exit=0
시도 2 : exit=16   <- Access denied
시도 3 : exit=0
시도 4 : exit=0
시도 5 : exit=0
```

허용 등록 후에도 접근이 산발적으로 거부된다. 119만 건을 복사하는 동안 반복 발생할 것으로 보인다.

> 참고: robocopy 기본 재시도값이 `/R:1000000 /W:30` 이라, 이 거부를 만나면 사실상 무한 대기에 빠진다.
> 테스트 시 반드시 `/R:0 /W:0` 등으로 낮출 것.

## 3. 벤더에 확인할 사항

1. **계약 종료 시 보관 데이터 반환 절차**가 계약서에 규정되어 있는가? 표준 절차는 무엇인가?
2. **일괄 반출(export) 도구**를 제공하는가? 4.87TB / 119만 건 규모를 처리할 수 있는가?
   - 원본 폴더 구조·파일명·타임스탬프가 보존되는가?
   - 산출물 형식은? (평문 파일 / 압축 / 전용 포맷)
3. **허용 등록한 프로그램에 디렉터리 열거 권한을 줄 수 있는가?** (제약 ① — 가장 중요)
   - 현재 robocopy 는 파일은 읽지만 하위 폴더 목록을 얻지 못해 재귀 복사가 불가능하다.
   - 응용 프로그램별 "수정" 화면에 열거/탐색 관련 세부 권한 옵션이 있는가?
   - explorer 처럼 폴더 구조를 볼 수 있게 하려면 어떤 설정이 필요한가?
4. **간헐적 접근 거부**(제약 ②)의 원인은 무엇인가? 동시 접근 수나 요청 빈도 제한이 있는가?
   대량 복사 작업을 위한 권장 설정이 있는가?
5. 서버 측에서 직접 추출하는 경로가 있는가? (백업본 반출 등)
   - 서버 저장소의 파일이 **암호화 상태**인가? 복호화 도구를 제공하는가?
6. **문서 개정 이력**도 함께 반출되는가? "문서 1,193,509"는 최신본만인가, 이력 포함인가?
   (이력 포함 시 실제 반출 용량이 크게 달라진다)

## 4. 진행 시 유의

- **해지 통보 전에** 요청할 것. 계약이 살아있고 협상력이 있을 때가 답을 받기 가장 쉽다.
- 서면(메일)으로 요청해 회신을 기록으로 남길 것.
- 반출 완료·검증 전까지 클라우디움 서비스를 종료하지 말 것. 병행 운영 기간 1~2개월 확보 권장.
