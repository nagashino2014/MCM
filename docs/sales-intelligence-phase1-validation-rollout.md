기준일: 2026-10-31. 구현 작업 위치: `worktrees/sales-intelligence-phase1`, 브랜치 `codex/sales-intelligence-phase1`, 기준 main `32d7a5c5`.

승인된 정기 브리핑 기본 묶음과 F01~F07, 공개 공식 정보원 보강 및 추가 요청된 개별 보고서 공유를 구현했다. 운영 DB 변경·AWS 적용·실제 직원 알림·커밋·푸시는 수행하지 않았다. 로컬 시험 계정의 사내 메일·메신저 저장은 실제로 검증했으며, 이 결과와 실제 서비스 활성화는 별도 단계다.

수동 AI 브리핑 화면은 유지한다. 정기 발행본은 당시 자료를 보존하며, 내부 영업 관계와 개인 우선순위 사유를 공통 보고서나 외부 알림에 포함하지 않는다. 조회·내보내기·발송 때 현재 수신 권한과 정보원 이용 권리를 다시 확인한다.

`intel.briefing.view/create/share` 권한을 분리하고 기존 임원·영업 템플릿에 멱등 추가한다. 명시적 거부 권한은 기존 영업 권한으로 우회하지 않는다. 보고서 소유자만 관리·공유하며 전사 역할도 타인의 비공개 보고서를 자동 열람하지 못한다. 정기 수신자로 자동 등록된 공유 기록과 소유자가 명시적으로 개별 공유한 기록을 구분하여, 정기 수신자 해제가 과거 자동 공유 때문에 무효화되지 않도록 했다.

개별 공유는 RAG 공유 목록을 먼저 등록한 뒤 선택 채널의 전달 결과를 저장한다. 메신저는 동일 사용자 쌍의 DM을 재사용하고 고정 문서 경로의 구조화된 카드만 제공한다. 사내 메일의 구조화된 열기 버튼도 실제 완료된 공유 전달·메일 소유자·현재 브리핑 권한을 확인한다. 메일 HTML iframe의 보안 설정은 완화하지 않았다. 성공 채널은 재시도에서 제외하며, 전달 중 실행 종료 시 내부 저장 채널은 안전 재시도 대상으로, 외부 푸시는 결과 불명으로 보존한다.

## 3. 공개 공식 정보원

| 정보원 | 구현 상태 | 활성화 조건 |
|---|---|---|
| KOSIS | 최대 2개 통계표·6개 시계열 JSON 수집 | 인증키, 기관/표/항목/분류 코드, 이용 권리, 실제 응답 검증 |
| 국가법령정보 | 법령 ID·행정규칙 LID를 사용하는 공식 API | OC 인증값, 대상 목록, 이용 권리, 실제 응답 검증 |
| KDI | 허용된 공식 페이지의 HTML 본문·발표일 수집 | 대상 주소·공공누리 등 이용 범위 확인 |
| 기업 공식 발표 | 허용된 기업 공식 주소의 HTML 본문 수집 | 도메인·대상 주소와 수집/보관/AI/사내보고 허용 근거 |
| KIET·KEA | 참고 링크 | 1차 자동 수집 대상 아님 |

수집·본문 저장·AI 분석·사내 보고서 이용 권리를 각각 관리한다. 인증키는 기존 서버 비밀값으로 암호화하고 화면에 원문을 반환하지 않는다. 공식 소스 설정·수집은 전사 범위의 영업 편집 권한이 필요하다. 기존 범용 스크래퍼를 통한 공식 소스 수정·실행은 막는다.

기존 수집기와의 호환을 위해 `scraper_sources.enabled`는 공식 소스에 대해 0으로 유지하고 새 설정의 활성값을 사용한다. 문서 정정은 별도 revision으로 보관한다. 본문이 A→B→A로 바뀌어도 마지막 정정을 보존한다.

공식자료는 새 권리 검증 경로에서만 AI에 전달한다. 기존 수동 RAG·임베딩 경로는 공식 신호를 제외한다. **공식 기업 발표를 활성화하기 전에 고정된 기존 intel 배치에도 이 임베딩 제외 변경을 반영해야 한다.** 이전 이미지가 공식 신호를 읽으면 제목 메타데이터가 기존 임베딩 경로로 전달될 수 있으므로, 앱만 갱신한 상태에서 공식 수집을 활성화하면 안 된다.

KDI의 실제 공개 HTML을 읽어 제목·공표일·개별 공공누리 1유형 표시를 확인했으며, KOSIS·법령 요청 매개변수는 공식 안내와 대조했다. 실제 KDI 수집과 LLM 작성은 아래 실제 자료 실증에서 추가 확인했다. 인증된 KOSIS·법령 응답, SES·앱 전달, 첨부 PDF·이미지 OCR·유료 기사 수집은 포함하지 않았다.

3. **활성화 전 앱 적용:** `INTEL_BRIEFING_ENABLED=false` 상태에서 새 화면·API·배치 번들을 적용한다. 수동 AI 브리핑, 기존 수집, 사업장·영업·계약 조회를 먼저 확인한다. 실제 적용 전에는 커밋·배포 승인과 운영 접근이 필요하다.
4. **전용 작업 정의:** 검증된 Next 작업 정의에서 `infra/aws/ops/prepare-intel-briefing-task.mjs`로 `*-intel-briefing` family의 검토용 JSON을 만든다. 기존 역할·비밀값·로그 설정과 고정 이미지 태그/digest를 보존한다. 생성기는 AWS에 등록하지 않는다. 검토 후 등록하고 숫자 revision ARN을 사용한다.
5. **최소 실행 권한:** `infra/aws/intel-briefing-worker.tf`는 전용 family의 `ecs:RunTask`와 기존 역할 두 개의 `iam:PassRole`만 추가한다. 전체 Terraform apply는 금지하며, 해당 리소스만 포함한 plan에서 MX·SES·Route53·bastion 등 다른 변경이 없는지 확인하고 승인된 범위만 적용한다.
6. **실제 소스와 채널 검증:** 인증키·이용 범위·대상을 저장하고 각 소스의 저장값 수집 확인으로 상태를 검증한다. 비활성/대기 소스를 ‘사용 가능’으로 간주하지 않는다. 승인된 시험 수신자에게 실제 AI 1회 생성, 사내 메일함·이메일·모바일 푸시·메신저·PDF와 현재 권한 회수를 확인한다. 로컬에서 생략된 모바일 푸시는 활성 기기·개인 수신 설정·실제 도착과 딥링크를 별도로 검증한다. 기존 방 재사용과 없는 방 생성도 확인한다.
7. **초기 자료 정리:** 기존 신호를 초기 기준으로 정리한다. 과거 자료 정리를 신규 중요 사건으로 대량 발송하지 않는다. 미매칭 사업장과 정보 부족 프로젝트를 담당자가 검토한다.
8. **시범 활성화:** 승인된 소수 프로필로 `INTEL_BRIEFING_ENABLED=true`를 설정한다. 최소 7일간 예약 누락·중복·배달 불명·비용·근거 오류·영업 전환을 관찰한다. 실제 반복 주기가 1개월인 프로필은 예약 계산 시험과 별도로 첫 실제 실행도 확인한다.

- 동일 회차·요청 재시도로 보고서/영업건/활동이 중복 생성되지 않는다. 수동 보고서가 정기 변경 기준을 소모하지 않는다.

- 정기 수신자 제외 시 자동 공유 기록으로 접근이 남지 않는다. 소유자가 별도로 명시한 개별 공유는 해당 보고서에 한정해 유지된다. 퇴사·열람권한 또는 정보원 권리 회수 후 조회·PDF·발송이 차단된다. 공개 점수·공유 보고서에 다른 사용자의 개인 조정 사유가 포함되지 않는다.
- 중요 알림은 야간에 전달하지 않으며 상한을 넘은 사건은 다음 날 묶음으로 보존한다. 묶음의 성공·불명 상태를 구성 사건에 반영한다.
- 중단할 때는 앱과 전용 작업의 기능 플래그를 끄고 활성 프로필을 중지한다. 이미 실행 중인 작업을 확인한 뒤 후속 조치를 결정한다. 생성 이력·배달 로그·원본 자료는 지우지 않는다. 새 스키마를 즉시 역삭제하는 방식으로 복구하지 않는다.
