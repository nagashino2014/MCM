- `/finance?tab=invoice` 거래 연결 표 '제거' 28px 미만 열 — 화면 낭독기 전용(`sr-only`) 머리글.

- `/finance?tab=vat` 쇼핑몰 전표 수집 `403 /api/receipts/shop/status` — 로컬 실행 전용 기능.

- 파일명·공고명·용역명 등 긴 이름의 말줄임(`truncate`) — 의도된 처리(제목 툴팁 있음).
- `/contracts/filings` 'IEPS 기술자 불러오는 중' — dev 서버 동시 부하로 25초 초과, 단독 재측정 시 정상 로드.

## 4. 남은 과제(이번 수정 범위 밖)

1. **`cd-input`/`cd-select` + 고정폭 클래스 64곳** — 같은 날 후속 처리(커밋 7f665c7a, 병합 c59a78b9): `.cd-input{width:100%}`가 `w-16`·`w-28`·`w-[120px]` 등을 덮던 곳 중 의도 폭이 맞는 25곳 + `w-auto` 2곳을 `!w-N` 으로 바꿨고, 나머지는 현재 100% 폭이 자연스러워 유지했다. 전역 `:where()` 안은 적용하지 않았다.
2. **잘못된 HTML 중첩(하이드레이션 경고)**: `/approval/forms` 양식 선택 상태와 `/finance?tab=expsettle` 에서 `<p>` 안에 `<div>`·`<ul>` 이 들어간다. 운영 빌드에서는 경고만 남지만 React가 해당 트리를 다시 그린다.
3. `/finance?tab=invoice` 진입 시 `POST /api/finance/tax-invoices` 를 자동 호출한다(검사에서는 차단). 조회 성격이면 GET 이 맞는지 확인 필요.
4. 모달 정적 점검(`fixed inset-0` 60건): 높이·폭으로 내용에 닿을 수 없는 모달 0건(F-10 2건 수정). `FacilityOrdersModal` 은 하단 상세가 `shrink-0` + 본문 `overflow-hidden` 이라 위 카드가 커지면 잘릴 수 있는 경계 사례(실측 미확인).
5. 범위 밖: 다크 테마, Windows 배율 125%(CSS 1536px), 모달 내부 실측.
