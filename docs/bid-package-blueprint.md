# 입찰 증빙서류 패키지 블루프린트

공공입찰(나라장터) 입찰 참여 시 제출하는 증빙서류 일체를 앱에서 생성·조립하는 기능.
2026-07-18 사용자 확정 결정 기반. 관련: `docs/` 없음(신규), 선행 자산은 §4 참조.

## 1. 확정 결정 (2026-07-18)

### 1-1. 진입점
- **공공입찰 메인(`/sales/bids` BidBoard) → 입찰공고 리스트 행 클릭 → 용역 상세 모달 → '입찰 서류 생성' 버튼**으로 진입.
- 진입 후에는 공공입찰 소스(`/sales/bids/sources`)·사업장 중복병합처럼 **메인과 구분되는 전용 페이지**로 이동.
  (전자들과 달리 메뉴 우상단 버튼이 아니라 상세 모달 내 버튼이 진입점.)
- 경로안: `/sales/bids/package?bidType=<t>&bidId=<id>` (대상 공고 컨텍스트를 갖고 진입).

### 1-2. 패키지 구성 문서 (7종 + 인력별 첨부)
생성 문서는 **HWPX 생성 → PDF 변환** 구조(증명서+명단과 동일 지향, §5-1 제약 참조):
1. 업체 연혁·일반사항
2. 신용평가 등급
3. 수행실적 총괄표
4. 수행인력 집계표
5. 수행인력 개별 이력사항
6. 개인정보 수집 및 이용 동의서
7. 보안 서약서

인력별 첨부(생성 아님, 업로드본 병합 — §1-4 배치 규칙):
- 엔지니어링 기술자 경력확인서 — **협회 다운로드본 단순 첨부**(자체 작성 아님)
- 졸업증명서, 자격증 사본

### 1-3. 양식 가변성 대응 = 매 입찰 양식 업로드 + LLM 분석 ★핵심 설계
발주처마다 양식이 대동소이하나 **완전히 동일한 경우가 드물다** → 하드코딩 위치 기입은 반드시 사고남.
- **워크플로**: 해당 공고 첨부(제안요청서 등)의 입찰 제출 서류 양식 파일을 업로드
  → LLM 분석으로 양식 내 각 서류의 **입력 항목·위치**를 파악
  → **표준화된 서류별 입력 항목 카탈로그**(§5-2, 사용자 양식 자료 분석 후 확정)와 대조·매핑
  → 항목 위치에 DB 데이터를 주입해 문서 생성.
- **변칙 양식 미세조정**: 표준 항목의 **추가/삭제가 가능**한 편집 UI 필수(매핑 결과를 사용자가 보정).
- **발주처별 양식 라이브러리(2026-07-18 추가 확정)**: 한 번 업로드·분석한 양식은 해당 **발주처
  (org_name)의 기본 입찰 서류 양식으로 등록** → 같은 발주처의 다음 입찰 건에서 **디폴트 옵션으로
  선택**(재분석 불필요). 발주처 양식이 변경될 수 있으므로 **재업로드(교체) 기능 온존**.

### 1-4. 인력별 첨부 배치 규칙
수행인력 집계표 작성으로 **수행인력이 확정**되면, 해당 인력만(참여 기술인력만 제출 대상) 인력별로:
1. **엔지니어링 기술자 경력확인서** — 존재하는 경우 가장 앞
2. **졸업증명서** — 복수 학위는 **박사 → 석사 → 학사** 순
3. **자격증 사본** — 순서:
   - 기술사: 대기관리기술사 → 수질관리기술사
   - 기사: 대기환경기사 → 수질환경기사 → 온실가스관리기사 → 폐기물처리기사 → 화공기사 → 토양환경기사 → 소음진동기사

(`roster_pdf` S3 저장, next:218), 계약서/계산서 병합(`document-bundle.ts` `mergePdfBytes`), 공고 첨부
다운로드(raw_json DocUrl/FileNm 추출).

## 3. 추가 확정 (2026-07-18 2차)

- **HWPX→PDF = (a) 두 벌 렌더 확정**: 제출 원본용 HWPX + 미리보기·병합용 PDF를 같은 데이터로 각각
  생성(증명서·명단에서 검증된 방식). 한글 COM 서버 변환은 쓰지 않는다.
- **문서-항목 태깅 보강 포함 확정**: `employee_documents`의 자격증 사본/졸업증명서를 학위·자격증
  항목과 연결(업로드 시 선택). 기존 데이터가 거의 없어 변경 부담 낮음.
  → 스키마 후보: 기존 `target_table`/`target_id` 컬럼 재사용(`employee_certifications`/
  `employee_educations` 참조) — hr-events 첨부 전례와 동일 패턴, 마이그레이션 최소화.

## 4. 표준 항목 카탈로그 (P0 확정 — 샘플 5벌 분석, 2026-07-18)

샘플: 양식1(서부발전 공주천연가스, 별첨 서식 2~9) / 양식2·5(【양식 2~4】 계열) /
양식3(별지 3~4호) / 양식4([서식 2~5], 발전사 계열). 전부 HWPX 파싱·셀 좌표 추출 검증 완료.

### 4-1. 양식 간 차이 분석

**서류 구성**: 표준 문서 타입 7종 + 조직도로 수렴하되 발주처마다 부분집합만 요구:
- 양식1: 일반현황·연혁 / 신용평가 / 실적총괄 / 집계표 / 개별이력 / 동의서 / 서약서 (풀셋)
- 양식2·5: 일반현황(확장형) / 실적(연도형) / 기술인력 보유현황(간이 집계) — 3종만
- 양식3: 개별이력(간이형) / 조직도(자유양식) — 2종만
- 양식4: 일반현황(확장형) / 신용평가(등급 체크표) / 실적총괄 / 집계표 — 4종

**같은 서류 내 항목 가감(대표 사례)**:
| 서류 | 양식1 | 양식2·5 | 양식4 |
|---|---|---|---|
| 일반현황 | 회사명·대표자·사업분야·주소·전화·설립년월·종사기간+연혁 | +사업자번호·면허/허가/등록증·**인적구성**·재정상황(자본금/매출액)·주요사업내용 | 양식2와 동일 골격 |
| 인적구성 구분 | — | 고급/일반(환통법) ↔ 계/임원/기술직/연구직/사무직(직군) | 특급/고급/중급/초급(엔지니어링) |
| 실적표 열 | 구분·용역명·개요·금액(백만원+%)·기간·참여인원·발주처·연락처 | 연도·사업명·금액(억원)·발주처·전화·**득점** | NO·구분·용역명·금액·기간·발주처 |
| 집계표 열 | 직위·성명·등급·학위·관련/소속경력·실적건수·참여기간 | 간이형: 구분(총괄/참여자)·성명·등급·득점 | +실적 **화력/비화력 분리**, 학위(자격증) 병기 |
| 개별이력 | 상세형(생년월일·학력·자격증·경력표) | — | — (양식3은 간이형: 연령·참여임무) |

→ 결론: **문서 타입은 7+1종으로 고정, 항목은 타입별 "필드 수퍼셋(pool)"에서 취사선택**되는 구조.
금액 단위(백만원/억원/천원), 등급 기준(env/eng/직군), 득점 열(발주처 평가란 — 빈칸 유지) 같은
**변형 축**이 존재 → 필드에 단위·기준 옵션을 붙인다.

### 4-2. 표준 문서 타입 8종 + 필드 수퍼셋 (프리셋 확정)

괄호는 데이터 소스. **[신규]** = 현재 DB에 없어 자사 프로필/보강 필요.
1. `company_profile` 일반현황·연혁: companyName·ceoName·bizField·address·phone(자사 상수) /
   bizRegNo(상수) / foundedYm·industryYears(자동계산) / **licenseList[신규]** /
   **staffComposition**(기준 옵션: env_grade|eng_grade|직군 — employee_profiles 집계) /
   **finance(연도·자본금·매출액)[신규]** / **historyList[신규]** / **mainBusiness[신규]**
2. `credit_rating` 신용평가: corpBondGrade·corpCreditGrade **[신규]** + 증빙 PDF 첨부. 등급
   체크표형(양식4)은 해당 등급 셀 체크 표기
3. `performance_summary` 실적총괄: rows[] = no / year / category(동등실적 세분류 ← serviceSubtype) /
   serviceName / overview(시설유형+취득종류, 수기 보정) / amount(단위 옵션: 백만원|억원, +지분%) /
   period(+개월) / staffCount(등급별 "고급:N 일반:N") / clientName(+**민간/공공 구분[신규]**) /
   clientPhone / score(빈칸) / 합계
4. `staff_summary` 투입인력 집계: rows[] = role(직위 — 패키지에서 지정) / name / grade(기준 옵션) /
   degree(최고학위) / licenses / careerMonthsTotal(careers+자사) / careerMonthsCompany(입사일) /
   perfCount(옵션: 화력/비화력 분리) / participateMonths / score(빈칸)
5. `staff_career` 개별 이력(인당 1장, 상세|간이 변형): name·company·engGrade·position·birthDate·
   age·tenure / education(학부·대학원) / licenses(명+취득일) / assignedRole(본사업 참여임무) /
   careerRows[] = client·projectName·task·amount(억원)·period·participatePeriod·thenCompany·thenPosition
   (service_participants ⋈ contracts, 타사는 careers)
6. `privacy_consent` 개인정보 동의서: serviceName(본문 치환)·signerName(서명 수기)
7. `security_pledge` 보안 서약서: pledgeDate·serviceName·companyName·position·name·birthDate·
   issuerOrg(발주처)
8. `org_chart` 사업수행 조직도: 자유양식 — 1차는 수동 작성/첨부 슬롯만 제공

→ eng_grade/env_grade/학력/자격증/경력 스키마(032 유틸 흡수분)가 양식들과 정확히 대응.
LLM 분석은 업로드 양식의 표·셀을 이 수퍼셋에 매핑하고, 미매핑 셀은 수기 항목으로 노출
(항목 추가/삭제 미세조정). 카탈로그는 `bid_package_forms.form_profile` jsonb에 문서 타입별
[셀 좌표 ↔ 표준 필드] 매핑으로 저장.

## 4-3. 회사 프로필 관리 메뉴 (2026-07-18 사용자 확정 — 패키지 신규 데이터의 관리 UI)

좌측 메뉴 **시스템 섹션에 '회사 프로필 관리' 신설**. 패키지 §4-2의 [신규] 데이터 공급원.
1. **업체 일반현황 카드**: 업체명·주소·대표자·사업자번호·업종 등 입력. (+신용평가등급도 여기서)
2. **인적구성**: **통합허가 대행업 기준(환경부 등급 env_grade)** 자동 집계 — 사용자 등록·삭제
   메뉴의 인원 상세 '환경부 등급(대행업)' 데이터로 구분. **해당 목록박스에 '미구분' 항목 추가**
   (기존 고급인력/일반인력 + 미구분).
3. **연혁 관리 카드**: 영업 스케쥴 관리 화면의 **타임라인 UI와 같은 형태**(세로선+노드+연월+내용).
4. **주요 사업내용 입력 카드**.
5. **면허/허가/등록증·인증 보유현황 카드**: 면허 종류(환경컨설팅회사·엔지니어링 컨설팅업·통합허가
   대행업 등 — **추가/삭제 가능**) + 인증(이노비즈·벤처기업·ISO 등) 선택 목록박스.
   **사업자등록증 LLM 추출 기능을 끌어와** 면허/인증 문서 업로드 → LLM 파싱으로 명칭·번호·
   취득일·유효기간 자동 입력.

## 4-4. 미결 논점

- **HWPX 원본 필요**: 제공 샘플이 `.hwp`(바이너리) — `fillHwpx`(zip/xml)는 HWPX만 다룸.
  한글에서 HWPX로 저장한 버전 필요(양식 업로드도 HWPX 권장 안내).
- 추가 샘플(다른 발주처 2~3벌)로 카탈로그 변형 범위 확인.
- 자사 프로필(연혁·신용등급) 관리 위치: 설정 화면 vs 마이그레이션 시드.
- 패키지 산출물 보관: 계약 증빙처럼 S3 저장(공고별) 여부, 재생성 정책.

## 5. 구현 단계

1. **P0 양식 분석**: ✅ 완료(샘플 5벌, §4 프리셋 확정)
2. **P1 진입·골격**: ✅ 구현 완료(078 미적용·미배포) — 상세 모달 버튼 + 전용 페이지 +
   발주처 양식 라이브러리 업로드
3. **CP 회사 프로필 관리**(§4-3): 메뉴 신설 + 079(company_profile/history/credentials) +
   일반현황·인적구성(env_grade 집계, '미구분' 옵션 보강)·연혁 타임라인·주요 사업내용·
   면허/인증(LLM 파싱 자동입력) — **패키지 데이터 선행이라 P2보다 먼저**
4. **P2 양식 업로드·LLM 매핑**: HWPX 표·셀 파서(TS) → LLM 셀 매핑(form_profile 저장) →
