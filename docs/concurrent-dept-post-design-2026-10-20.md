# 겸직(복수 부서 보직) 권한 설계 — 2026-10-20

> 요청: 한도경 부장이 통합환경2본부장과 화학안전본부장을 겸직한다. 겸직자에게 복수 부서 권한을 줄 수 있어야 한다.
> 상태: **설계만 작성. 구현 전에 §8의 결정이 필요하다.** 기준 코드는 origin/main `ce02ef7`.

## 1. 현황 — 겸직을 표현할 곳이 없다

- 직원 1명 = 부서 1개·직급 1개(`employee_profiles.dept_id`, `position_id`). `departments`에는 부서장 열이 없다.
- 인사 이벤트(`employee_hr_events`, 045)는 `promotion`·`transfer`·`resignation`만 있고 겸직 발령은 없다.
- 권한의 `self_dept`는 `loadUserAccess`의 `deptId` 하나(소속 부서)를 뜻한다(`frontend/lib/auth/rbac.ts:56-64`).
- "누가 부서장인가"를 판정하는 규칙이 화면마다 네 가지로 다르다.

| 위치 | 현재 규칙 | 화학안전본부 결과 |
|---|---|---|
| 업무보고 푸시 `lib/work-plan/push-notify.ts:13` | 부서 소속 중 직급 최상위 1인 | 이원종 차장(한도경은 받지 못함) |
| 성과급 본부장 몫 `lib/bonus/statements.ts:170-218` | 계약 `관리자` 다수결 → 없으면 직급 최상위 | 관리자 지정에 따라 다름, 기본은 이원종 |
| To-do 부서 보드 `lib/todo/visibility.ts:40` | tpl-dept-lead 보유 여부(어느 부서인지 무관) | 부서 구분 없음 |
| 업무추진계획 `getReporterContext` 등 | 권한 + 소속 부서 1개 | 화학안전본부 목록 접근 불가 |

### 1.1 한도경 부장이 지금 겪는 일
| 영역 | 현재 동작 |
|---|---|
| 업무추진계획(부서 보고 검토·취합·확정·지시·부서 과업) | 12개 API가 소속 부서로 강제 → 화학안전본부 보고는 목록에 안 뜸. 부서 선택은 관리자에게만 보임 |
| 부서 수주·수금 현황(299) | 통합환경2만 보임(부서 선택 UI는 이미 있음 — 범위만 넓히면 됨) |
| 결재 부서 문서함·완료 문서 열람 `getUserDeptId` | 통합환경2 문서만 |
| 업무보고 제출 알림 | 화학안전본부 보고 알림이 이원종 차장에게 감 |
| 게시판 부서 게시판·캘린더 "부서" 태그·To-do 주간 요약 | 통합환경2 하나만 |
| 기안 부서 | 문서가 항상 통합환경2로 등록됨(선택 불가) |
| 인력·성과급 평가·대상 목록 | 권한 범위(`specific_dept`)를 이미 따르므로 범위만 주면 동작 |

### 1.2 "템플릿을 한 번 더 주는" 방법을 쓰지 않는 이유
tpl-dept-lead를 `specific_dept=chemical-safety` override로 한 번 더 배정하는 방법도 있다(백엔드는 허용, 관리 화면은 같은 템플릿 중복을 막음). 하지만 쓰지 않는다.
- override는 템플릿의 **모든** grant에 적용된다(`rbac.ts:89-90`). `self`로 준 키가 화학안전본부 **전원**으로 넓어지는 권한 상승이 생긴다(예: 본인 근태·급여 조회 → 부서원 전원).
- 업무추진계획·결재·푸시·성과급처럼 권한 grant 밖에서 부서를 판정하는 곳은 이 배정을 모른다.
- 겸직 종료·조직도 표시·인사 이력과 연결되지 않는다.

### 1.3 조사 중 발견한 기존 결함(겸직과 함께 고칠 것)
- **L-1 부서 계약 집합 합산:** `deptContractIds`·`deptProjectIds`는 모든 부서 grant를 합친 집합 하나다(`rbac.ts:112-150`). 부서가 둘 이상이면, A부서 범위로 받은 키가 B부서 계약 단건에도 통과한다. 지금은 부서 범위가 둘 이상인 사람이 없어 드러나지 않았지만, 겸직을 넣으면 바로 생긴다.
- **L-2 To-do 부서 보드:** `createBoard`가 레거시 `users.dept_id`(전원 NULL)를 써서, 부서 보드가 부서 없이 만들어지고 부서원 자동 참여가 되지 않는다(`lib/todo/store.ts:581-598`).
- **L-3 성과급 수행부서 자동 채움:** `setBonusParticipant`가 수행부서가 빈 계약을 관리자의 소속 부서로 채운다(`lib/bonus/evaluations.ts:209-226`). 한도경이 관리자인 화학안전 계약이 통합환경2로 기록된다.

## 2. 설계 원칙
1. **소속은 하나, 보직은 여럿.** `employee_profiles.dept_id`는 그대로 "주 소속"(급여·인사·주소록 기본)이다. 겸직은 별도 "보직" 행으로 더한다.
2. **"부서장"의 진실원을 보직 표 하나로 모은다.** 네 가지 판정 규칙을 공통 함수 하나로 바꾼다. 주 소속 부서의 부서장도 같은 표에 기록한다.
3. **`self_dept` = 본인의 활성 보직 부서 전체**(주 소속 + 겸직). 템플릿·grant 정의는 바꾸지 않는다. 그러면 범위 기반 화면(계약·영업·인력·성과급·부서 수주·수금)은 저절로 두 부서를 보게 된다.
4. **판정은 부서별로 따로.** L-1을 고쳐 A부서 grant는 A부서 대상에만 통과시킨다.
5. 메뉴 구성은 바뀌지 않는다(같은 키, 범위만 확장). 재로그인이 필요한 경우는 §3.3의 자동 배정이 일어날 때뿐이다.

## 3. 데이터 모델 — 마이그레이션 300(번호는 구현 시 원격 전 브랜치 재확인)

### 3.1 `employee_dept_posts`(신규)
| 열 | 의미 |
|---|---|
| `post_id` text PK | |
| `employee_id` text NOT NULL → employee_profiles | |
| `dept_id` text NOT NULL → departments | |
| `post_kind` text CHECK IN (`head`, `member`) | `head` = 부서장, `member` = 겸직 부서원 |
| `title` text | 표시용 직책(예: "본부장") — 직급(position)은 그대로 |
| `is_primary` smallint | 주 소속 부서의 부서장 행이면 1(겸직 행은 0) |
| `effective_from` / `effective_to` text(YYYY-MM-DD) | 발령·해제일, 293과 같은 10자리 규칙 |
| `revoked_at`, `created_by`, `created_at`, `note` | |

- 부분 UNIQUE: 활성 행 기준 (`employee_id`, `dept_id`) 1개.
- 겸직 `member` 행의 부서는 주 소속과 달라야 한다(CHECK는 트리거 없이 저장 API에서 검사).

### 3.2 백필·이력
- 각 부서에서 tpl-dept-lead를 보유한 재직자 → `head`, `is_primary=1` 행. (예: 한도경 → 통합환경2 head.)
- 한도경의 화학안전본부 겸직은 **마이그레이션에 이름으로 넣지 않고** 배포 후 관리 화면에서 등록한다(등록 화면 실증을 겸함).
- `employee_hr_events.event_type` CHECK에 `concurrent_start`·`concurrent_end`를 더하고, 보직 저장 시 이력 행을 함께 남긴다.
- 새 권한 키는 없다(보직 관리는 기존 조직·인사 관리 권한을 그대로 씀) → tpl-system-admin 배포 행 추가 불필요.

### 3.3 부서장 보직과 템플릿
- `head` 보직을 등록할 때 그 사람에게 tpl-dept-lead가 없으면 자동 배정한다(id `post-<userId>-tpl-dept-lead`). 마지막 `head` 보직이 끝나면 이 자동 배정만 회수한다(`auto-…`·수동 배정은 건드리지 않음).
- 한도경은 이미 tpl-dept-lead가 있어 배정 변화가 없고, 재로그인도 필요 없다.
