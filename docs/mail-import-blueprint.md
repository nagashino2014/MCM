# 메일 가져오기 설계안 — 파일 업로드 + IMAP

> 작성 2026-10-16 · 개정 2026-10-16(아마란스 메일함 백업 ZIP 실측 반영) · 상위 설계: [company-email-blueprint.md](company-email-blueprint.md) §4-P5(임포트), [company-email-com-domain-phase1.md](company-email-com-domain-phase1.md)
> 상태: **I-1 배포·사용자 확인 완료(24664e6), I-2·I-3 구현(커밋 전, 2026-10-16)**. 결정 D-1~D-4 확정. 아마란스 이관의 주 경로는 **메일함 백업 ZIP 가져오기**이고, 아마란스 IMAP은 더존 회신 후 붙이는 선택 경로다.

## 0. 목표와 원칙

- **목표**: 직원이 지금까지 쓰던 메일함(아마란스 `@koensain.com`, 네이버·다음·지메일 등 개인 메일)의 **과거 송수신 메일을 MCM 메일함으로 옮긴다.**
- **원칙**
  1. **본인만, 본인 메일함으로.** 직원이 자기 계정의 메일을 자기 MCM 메일함에만 가져온다. 관리자가 남의 메일을 대신 가져오는 기능은 만들지 않는다.
  2. **고르게 한다.** 개인 메일에는 사적인 메일이 섞여 있으므로 메일함·기간을 직원이 고른다.
  3. **원본을 보존한다.** 원문 MIME을 그대로 보관하고, 같은 메일은 몇 번을 가져와도 한 번만 저장한다(폴더 소속은 모두 유지, §2.2).
  4. **받은편지함을 어지럽히지 않는다.** 가져온 받은 메일은 기본적으로 별도 폴더에 넣는다.
  5. **비밀번호는 최소한으로만 다룬다**(§5.3). 파일 경로는 비밀번호를 쓰지 않는다.
  6. **결과를 숫자로 맞춘다.** 원본 항목 수 = 새로 가져옴 + 중복 + 실패. 실패는 이유와 함께 보여 준다.

결론:
- **아마란스 백업 ZIP은 앱의 기존 파서로 그대로 처리할 수 있다.** EUC-KR·ks_c_5601-1987 등 옛 한글 인코딩도 문제없다.
- 원본 메일함은 **ZIP 이름과 EML 파일 이름 둘째 토큰**으로 자동 판별할 수 있다(직원은 확인만).
- ZIP은 data descriptor를 쓰므로 **중앙 디렉터리 기반 임의 접근**으로 읽는다. 사람당 ZIP이 수백 MB 안팎이라 범위 읽기 방식이 적합하다.
- 남은 확인: 사용자 정의 메일함 백업 표본, 대용량 첨부 링크가 든 메일 표본, 파일럿 2~3명의 메일함 크기.

## 2. 공통 설계 — 가져오기 작업

### 2.1 작업(job) 단위
- 직원이 "가져오기"를 시작하면 작업 1건이 생기고, 서버가 **틱마다 조금씩** 처리한다(§2.7).
- 작업 상태: `pending`(대기) → `running`(처리 중) → `done` / `failed` / `cancelled`. `paused`는 Next 정지·오류 재시도 대기.
- 직원은 진행률과 결과(원본 항목 수·새로 가져옴·중복·실패, 실패 사유)를 화면에서 보고, 언제든 취소할 수 있다.

### 2.2 적재 규칙

| 항목 | 규칙 |
|---|---|
| **보낸/받은 판별** | **원본 메일함 정보가 우선**이다. 파일: 업로드할 때 지정한 원본 메일함 종류(받은메일함·보낸메일함·사용자 메일함), IMAP: `\Sent` 특수 폴더. 원본 정보가 없을 때만(예: 여러 메일함이 섞인 `.mbox`) 보낸 사람이 내 주소인지로 보조 판별. 발신자 주소만으로 판별하면 나에게 보낸 메일·별칭·전달 메일이 잘못 분류된다 |
| 폴더 배치 | 보낸 메일 → **보낸편지함**. 받은 메일 → **"가져온 메일(원본 이름)"** 사용자 폴더(예: `가져온 메일(아마란스)`). 옵션으로 받은편지함 배치. 사용자 메일함 → `가져온 메일(아마란스)/메일함 이름` 라벨 |
| 원 폴더 | 원래 메일함 이름을 `labels`에 `import:<원본>/<메일함>`으로 남긴다 |
| **중복** | `Message-ID`(없으면 원문 SHA-256으로 `<import-{hash}@mcm.local>` 합성)가 같은 메일이 이미 있으면 **메시지는 새로 만들지 않고, 이번 폴더 배치·라벨만 추가**한다. 같은 메일이 받은메일함과 사용자 메일함에 함께 있어도 두 소속이 모두 남는다 |
| 읽음 | IMAP은 `\Seen` 그대로. **파일은 읽음 상태를 알 수 없어(EML에 없음) 모두 읽음으로 넣고, 화면에 그렇게 알린다** |
| 날짜 | 원문 `Date` 헤더(없으면 IMAP INTERNALDATE, 그것도 없으면 가져온 시각) |
| Bcc | 원문에 `Bcc` 헤더가 남아 있으면(보낸 메일 사본 등) 그대로 보존 |
| 스팸 판정 | 적용하지 않는다(과거 메일을 스팸함으로 옮기지 않음) |
| 수신 확인·추적 | 적용하지 않는다 |
| 알림 | 가져온 메일로는 새 메일 알림·푸시를 보내지 않는다 |
| 원문 | 앱 데이터 버킷 `mail-import/{mailboxId}/{hash}.eml` (`raw_s3_key`) |
| 한 통 크기 | **상한 100MB**(아마란스 수신 최대 크기와 같게). 넘으면 건너뛰고 실패 목록에 "크기 초과"로 남긴다 |
| 대용량 첨부 링크 | 본문의 아마란스 대용량 첨부 링크를 찾아 결과에 **"링크형 첨부 — 원본 파일 복구 안 됨(30일 만료)"**으로 표시. 링크는 본문에 그대로 둔다 |
| 손상 파일 | 파싱 실패 EML은 실패 목록에 "손상"으로 남기고 다음 항목으로 넘어간다 |

### 2.3 용량
- 가져온 메일도 메일함 용량(`quota_bytes`, 103)에 포함한다. **압축 크기가 아니라 압축 해제 크기**로 계산한다. ZIP은 중앙 디렉터리의 항목별 해제 크기 합계로 시작 전에 예상치를 보여 주고, 남은 용량을 넘으면 시작을 막고 관리자 용량 배분을 안내한다.
- 용량 집계 방식은 기존 메일함 사용량 계산 경로에 맞춘다(구현 시 확인).

### 2.4 권한·감사
- 시작·취소·완료는 접속기록(`recordAccessLog`, `targetKind: "mail_import"`)에 남긴다. 본문·비밀번호는 기록하지 않는다.
- 관리자는 **작업 현황만**(누가·언제·몇 통·상태) 볼 수 있고 메일 내용은 볼 수 없다.

### 2.5 결과 집계
- 항목마다 `imported`(새로 가져옴)·`duplicate`(중복 — 폴더 배치만 추가)·`failed`(이유: 크기 초과·손상·저장 실패 등) 중 하나로 셈한다.
- 작업 완료 시 **원본 항목 수 = imported + duplicate + failed**가 맞는지 검사하고, 어긋나면 작업을 `failed`로 두고 원인을 남긴다.

### 2.6 저장 순서(재시도 안전)
현재 수신 코드처럼 메시지 행을 먼저 만들고 첨부를 나중에 저장하면, 첨부 저장이 실패한 메일이 재실행 때 "중복"으로 건너뛰어져 **불완전한 상태로 남는다.** 가져오기는 다음 순서를 지킨다.
1. 원문과 첨부를 S3에 먼저 올린다(키는 원문 해시 기반이라 재시도해도 같은 키에 덮어씀).
2. **한 트랜잭션에서** 메시지·첨부 행·폴더 배치를 함께 기록한다. 하나라도 실패하면 모두 롤백한다.
3. 중복 판정은 2단계의 트랜잭션 안에서 한다. 완성된 메시지만 존재하므로 "중복"이면 첨부까지 온전한 상태다.

공용 저장 함수로 분리할 때 기존 수신 경로도 같은 순서로 바꿀지는 I-1에서 따로 판단한다(수신 경로 변경은 별도 검증 필요).

### 2.7 처리 엔진
- 새 틱 `/api/internal/mail-import-tick`을 `instrumentation.ts`에 1분 주기로 추가한다(기존 수신 틱과 같은 방식).
- 틱 1회는 **시간 예산 40초** 안에서 처리한다. 동시에 처리하는 작업은 **전체 1건**(advisory lock)으로 둬서 DB와 Next 서버 부하를 묶는다.
- 진행 위치(ZIP 항목 순번, `.mbox` byte offset, IMAP 폴더·UID)를 틱마다 저장해 **정지 후 이어서** 처리한다.
- 처리량은 메일 크기에 따라 다르다. 파일럿에서 실측해 안내 문구에 반영한다(목표: 1만 통을 하루 안에).

## 3. 데이터 모델 — 마이그레이션 `281_mail_import.sql`(가번호)

> 번호는 착수 직전 `git fetch` 후 원격 전 브랜치의 `infra/aws/`를 다시 확인한다(2026-10-16 기준 최대 280).

```sql
CREATE TABLE IF NOT EXISTS mail_import_jobs (
  job_id           text PRIMARY KEY,
  mailbox_id       text NOT NULL REFERENCES mailboxes(mailbox_id) ON DELETE CASCADE,
  user_id          text NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
  kind             text NOT NULL CHECK (kind IN ('file', 'imap')),
  source_label     text NOT NULL,                 -- '아마란스', '네이버' … (폴더 이름에 사용)
  source_address   text,                          -- 원 계정 주소(보조 판별)
  status           text NOT NULL DEFAULT 'pending'
                   CHECK (status IN ('pending', 'running', 'paused', 'done', 'failed', 'cancelled')),
  options          jsonb NOT NULL DEFAULT '{}'::jsonb,   -- 기간·받은편지함 배치 여부
  -- 파일 방식: 파일마다 원본 메일함 종류를 함께 둔다
  uploads          jsonb NOT NULL DEFAULT '[]'::jsonb,   -- [{key, name, folderKind: inbox|sent|custom, folderName}]
  -- IMAP 방식(비밀번호는 작업이 끝나면 NULL 로 지운다, §5.3)
  imap_host        text,
  imap_port        integer,
  imap_user        text,
  imap_secret_enc  text,
  secret_expires_at text,
  -- 진행·결과
  cursor           jsonb NOT NULL DEFAULT '{}'::jsonb,   -- 파일 순번·항목 순번·offset / 폴더·UID
  total_count      integer,                               -- 원본 항목 수
  imported_count   integer NOT NULL DEFAULT 0,
  duplicate_count  integer NOT NULL DEFAULT 0,
  failed_count     integer NOT NULL DEFAULT 0,
  link_attachment_count integer NOT NULL DEFAULT 0,       -- 복구 안 되는 링크형 첨부가 든 메일 수
  bytes_imported   bigint NOT NULL DEFAULT 0,             -- 압축 해제 기준
  last_error       text,
  failures         jsonb NOT NULL DEFAULT '[]'::jsonb,     -- 최근 실패 100건(파일·제목·사유)
  created_at       text NOT NULL,
  updated_at       text NOT NULL,
  finished_at      text
);
CREATE INDEX IF NOT EXISTS idx_mail_import_jobs_user ON mail_import_jobs(user_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_mail_import_jobs_active ON mail_import_jobs(status) WHERE status IN ('pending', 'running', 'paused');
```

- IMAP 증분 재실행을 위해 폴더별 `UIDVALIDITY`·마지막 UID를 `cursor`에 남긴다. 같은 원본을 다시 가져오면 직전 작업의 cursor 이후만 읽는다.
- 파일 방식의 증분(전환 직전 추가 백업)은 같은 메일함 ZIP을 다시 올리면 된다. 이미 있는 메일은 중복으로 셈하고 폴더 배치만 확인한다.

## 4. 방식 A — 파일 업로드 (주 경로)

### 4.1 지원 형식

| 형식 | 처리 |
|---|---|
| **아마란스 메일함 백업 `.zip`** | 안의 `.eml`을 모두 처리. 원본 메일함은 ZIP 이름·EML 파일 이름 둘째 토큰(`{날짜}_{메일함}_{계정}_{제목}.eml`)으로 자동 판별하고 업로드 화면에서 직원이 확인한다. 이름 없는 첨부는 `attachment-{순번}`으로 저장 |
| 일반 `.zip` | 안의 `.eml`을 모두 처리(하위 폴더 이름 = 원 메일함 라벨) |
| `.eml` (여러 개 동시 선택) | 파일 1개 = 메일 1통 |
| `.mbox` | `From ` 구분 줄로 메일을 나눔. 지메일 Takeout의 `X-Gmail-Labels` 헤더로 원 폴더·보낸 메일(`Sent`) 판별 |

- `.pst`(아웃룩)는 지원하지 않는다. 화면에서 대체 방법(아웃룩에서 `.eml`로 끌어 저장, 또는 IMAP)을 안내한다.

### 4.2 업로드·해제
- 브라우저 → **S3 presigned 업로드**(메일 대용량 첨부 업로드와 같은 방식). 파일당 상한 2GB.
- 업로드가 끝나면 작업을 만들고, 서버가 S3에서 읽어 처리한다. 원본 업로드 파일은 작업 완료 7일 뒤 지운다.
- **ZIP을 통째로 메모리에 올리지 않는다.** S3 범위 읽기(Range)로 중앙 디렉터리를 먼저 읽어 항목 목록·해제 크기를 얻고, 틱마다 항목 몇 개씩만 범위로 읽어 해제한다. 진행 위치는 항목 순번.
- `.mbox`도 범위 읽기로 조금씩 읽고 byte offset을 cursor에 저장한다.
- 압축 폭탄 방지: 항목 해제 크기가 100MB를 넘거나 압축률이 비정상적으로 높으면(예: 100배 초과) 그 항목을 실패 처리한다.

### 4.3 화면 흐름
1. 메일 설정 → **메일 가져오기** → "파일로 가져오기"
2. 원본 선택(아마란스·지메일·기타) → 파일 선택. **파일마다 원본 메일함을 고른다**(받은메일함·보낸메일함·사용자 메일함 + 이름). 아마란스 백업 파일 이름에 메일함 이름이 들어 있으면 자동으로 채우고 직원이 확인
3. 예상 통수·해제 용량 확인 → 시작. 안내: "파일로 가져온 메일은 모두 읽음으로 표시됩니다", "대용량 첨부 링크(30일 만료)의 파일은 함께 옮겨지지 않습니다"
4. 진행률 → 완료 후 결과(새로 가져옴·중복·실패와 사유, 링크형 첨부 수), "가져온 메일(아마란스)" 폴더로 이동 버튼

### 4.4 아마란스 직원 안내(화면 도움말 초안)
1. 아마란스 → 메일 → 환경설정 → **메일함 관리**
2. 받은메일함·보낸메일함·내가 만든 메일함에서 각각 **백업** → ZIP 저장
3. MCM 메일 설정 → 메일 가져오기 → 파일로 가져오기 → ZIP마다 원본 메일함 지정 → 시작
4. 아마란스 2단계 전환(MX 이전) 직전에 같은 순서로 한 번 더 백업해 올리면 그 사이 새 메일만 추가된다

## 5. 방식 B — IMAP (보조 경로)

### 5.1 연결
- 라이브러리: **`imapflow`**(신규 의존성 — D-2 확정 2026-10-16). Node 스트리밍·UID 처리 지원.
- 서버 프리셋: 네이버(`imap.naver.com:993`), 다음(`imap.daum.net:993`), 지메일(`imap.gmail.com:993`). **아마란스는 접속 정보가 확인되기 전까지 프리셋에 넣지 않는다**(§5.6). "직접 입력"도 허용하되 아래 보안 검사를 통과해야 한다.
- **암호화된 연결만 허용**한다: 즉시 TLS(993), 또는 143에서 STARTTLS가 성공한 경우([RFC 8314](https://www.rfc-editor.org/rfc/rfc8314)). 암호화 없는 로그인과 인증서 검증 끄기는 허용하지 않는다.

### 5.2 화면 흐름
1. 메일 설정 → **메일 가져오기** → "메일 계정에서 가져오기"
2. 원본 선택(프리셋) → 계정 주소·비밀번호(또는 **앱 비밀번호**) 입력 → [연결 확인]
3. 연결되면 **폴더 목록과 폴더별 통수·크기**를 보여 준다. 직원이 폴더와 기간(예: 최근 3년)을 고른다. 기본 선택은 받은편지함·보낸편지함만
4. 예상 용량 확인 → 시작 → 진행률

원본별 사전 준비 안내(네이버 IMAP 사용 설정·앱 비밀번호 발급 등)는 `CdHelp`로 단다.

### 5.3 비밀번호 취급 (D-1 확정 2026-10-16: 처리 기간 동안만 암호화 보관)
상위 설계는 "직원별 메일 비밀번호를 앱에 저장하지 않는다"로 정했다. 가져오기는 여러 틱에 걸쳐 처리하므로 **처리 기간 동안만** 예외를 둔다.
- `encryptSecret`(AES-256-GCM)으로 암호화해 `imap_secret_enc`에 둔다. 화면·API 응답·로그에 다시 내보내지 않는다.
- **작업이 끝나거나(done·failed·cancelled) 7일이 지나면 즉시 NULL로 지운다.** 만료 정리는 import 틱이 매번 수행한다.
- 직원에게 **앱 비밀번호 사용을 권장**한다(원 계정 비밀번호가 아니라 언제든 폐기할 수 있음). 가져오기가 끝나면 앱 비밀번호를 삭제하라고 안내한다.
- 채택하지 않은 대안(D-1 B안): 비밀번호를 보관하지 않고 "브라우저를 열어 둔 동안만" 처리. 큰 메일함은 수 시간 화면을 켜 둬야 해 비현실적.

### 5.4 보안 검사·잠금 방지
- 직접 입력 호스트는 DNS 해석 뒤 **사설·루프백·링크로컬(169.254 포함, IPv4-mapped IPv6 포함)·VPC 대역이면 거절**한다(서버가 내부망으로 접속하는 것 방지). 포트는 993 또는 143(STARTTLS 필수)만.
- 연결 시간 제한 15초.
- **인증 실패는 재시도하지 않고 즉시 작업 실패**로 둔다. 아마란스처럼 24시간 10회 실패로 외부 메일 사용이 잠기는 서비스가 있으므로, [연결 확인]도 직원이 누를 때 1회만 시도하고 자동 반복하지 않는다.
- 원 서버의 속도 제한·연결 끊김은 `paused`로 두고 다음 틱에 이어서 재시도(최대 5회 연속 실패 시 `failed`). 이 재시도는 이미 인증에 성공한 연결에만 해당한다.

### 5.5 처리
- 폴더마다 `UIDVALIDITY` 확인 → UID 오름차순으로 기간 내 메일을 50통씩 `BODY.PEEK[]`로 받는다(**원 서버의 읽음 표시를 바꾸지 않는다**).
- 원 메일함에서 **아무것도 지우거나 옮기지 않는다**(읽기 전용).
- 재실행 시 cursor 이후 UID만 받는다 → **증분 동기화**.
- POP3만 제공하는 서비스는 받은메일 일부만 가져올 수 있어, 보낸메일함·사용자 메일함 이관의 대체 수단으로 보지 않는다. 1단계에서는 POP3를 구현하지 않는다.

### 5.6 아마란스 IMAP — 더존 확인 사항
koensain.com 클라우드 이용 환경 기준으로 다음을 받은 뒤에만 아마란스 프리셋을 추가한다. 확인 전에는 비밀번호를 여러 서버에 반복 시도하지 않는다(§1.1 인증 실패 제한).
- IMAP 제공 여부(POP3만인지)
- 정확한 접속 서버 주소와 포트, 즉시 TLS인지 STARTTLS인지
- 로그인 아이디 형식(전체 이메일 주소인지 다른 형식인지)
- 웹 로그인 비밀번호를 쓰는지, 별도 메일·앱 비밀번호가 필요한지
- 접속 IP 제한이나 외부 서버 접속 제한이 있는지, MCM 실행 서버의 외부 IP를 허용해야 하는지
- kaikan00의 연결 실패 시각(10-16)에 대응하는 서버 로그와 실패 단계
